# 원래 승인 발행 프로필 해시의 비밀정보 검사 판정

[English](approval-publication-digest-scan.md) | [한국어](approval-publication-digest-scan.ko.md)

공식 Gitleaks 8.24.3 전체 보존 이력 검사에서 원본 구현 커밋
`d09b92acd4e90bbaf48f3b08e716307b5a2c6c33`의 승인 발행 벡터 42·87행
`credentialSha256` 두 항목이 `generic-api-key`로 탐지됐습니다. 독립 Python의 정렬된
간결한 UTF-8 JSON·SHA-256 계산과 소유 검증기 테스트로 두 값이 동일한 합성 공개 세션
메타데이터의 전체 해시임을 확인했습니다. 원본 파일 SHA-256은 영문 문서에 보존합니다.

원상 자료는 식별자·생성/만료/사용·철회 메타데이터이며 쿠키·CSRF·세션 비밀 검증값·
비밀번호 검증값·개인키를 포함하지 않습니다. 이 해시로 브라우저 로그인을 인증할 수
없습니다. 정확한 원본 커밋·경로·규칙·행 두 항목만 판정하며, 기존 판정과 원본 값·
바이트·이력은 보존합니다. 경로·규칙·값·향후 커밋 전체를 제외하지 않습니다.

초기 실패와 정확한 판정 후 전체 이력 검사를 별도로 보존합니다. 동일 파일과 ignore
파일을 별도의 폐기 가능한 로컬 검사 저장소에서 새 커밋으로 만들면 두 항목이 다시
탐지되어 실패해야 합니다. 이 대조군은 향후 항목까지 제외하지 않음을 확인합니다.
출력·보고서는 완전 가림을 사용하며 일치한 값이나 실제 브라우저 자격을 출력하지
않습니다. 검사 버전·규칙·범위·실패 동작은 그대로 유지합니다.

이 검사는 전체 코드 검사·GitHub CI·CodeQL·실제 서비스와 복구 검사·체크포인트 종료
감사를 대신하지 않습니다. 승인 철회는 아직 열린 체크포인트 4의 합성 참조 구성입니다.
