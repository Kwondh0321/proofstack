# 회귀·아티팩트 SDK 리다이렉트 경계

[English](regression-sdk-redirect-boundary.md) | [한국어](regression-sdk-redirect-boundary.ko.md)

`ProofStackRegressionClient`의 JSON 요청과 바이너리 내용 경로는 `redirect: "manual"`을
지정하고, 모든 3xx·이미 추적된 응답·불투명 리다이렉트를 본문 읽기 전에 거부합니다.
거부한 스트림은 취소하며 기존 마감 시간과 자격 증명 모드를 유지합니다. 변경 자동 재시도는 없습니다.

커밋 `2786d674d2fa39c0f8d198cfa749d83600700bda`의 실제 루프백 서버 두 개를 이용한 검사에서
307 아티팩트 업로드가 두 번째 서버에 합성 내용 64바이트와 합성 CSRF 헤더를 전달했습니다.
실제 사용자 자격 증명이나 비공개 아티팩트는 사용하지 않았습니다. 기존 텔레메트리 전송 보호와
별개인 회귀 클라이언트의 두 fetch 경로가 기본 리다이렉트 추적 동작을 사용하고 있었습니다.

실제 HTTP 검사 40개는 301/302/303/307/308, 같은 출처·다른 출처, JSON fixture 발행·조회,
바이너리 업로드·내용 조회에서 기존 문제를 재현했습니다. 수정 전 목적지 요청 0회 조건이 모두
실패했습니다. 수정 후 원래 요청 1회와 목적지 요청·내용 바이트·인증 헤더 0개를 요구합니다.
추가 검사는 스트림을 읽지 않는 거부·취소, 본문 부재와 취소 실패도 확인합니다.
기존 상한·마감 시간·정상 경로·커버리지 기준은 유지합니다.

실제 HTTP 검사는 Node 기본 fetch와 일회용 합성 루프백 서버를 사용합니다. 모든 브라우저나
운영 프록시 검증을 주장하지 않습니다. 사용자 제공 fetch는 수동 리다이렉트 옵션을 지켜야 하며,
응답 검사로 이미 실행한 네트워크 작업을 되돌릴 수는 없습니다. 반환된 리다이렉트 응답도
SDK의 신뢰된 fixture·아티팩트 내용으로 받아들이지 않습니다.

후속 개발에는 정확한 커밋의 전체 로컬·호스팅 검증이 필요합니다. 이 수정은 열린 Workflow 2
체크포인트 4를 승인하거나 배포·릴리스 권한을 부여하지 않습니다.
