# 네이티브 릴리스 결정 요청 예약

[English](workflow-2-decision-request-reservations.md) | [한국어](workflow-2-decision-request-reservations.ko.md)

마이그레이션 0070은 결정 입력 계획과 모든 네이티브 C3 요청 INSERT를 같은 정확한 범위의
트랜잭션 잠금으로 연결합니다. 정의가 같아도 이미 존재한 요청은 계획에 채택할 수 없습니다.
나중에 별도로 권한을 받은 워크로드가 작업을 만들 때 전체 계획 정의와 해시가 일치해야 합니다.
결정 발행자는 작업 생성·실행 또는 사람 승인 권한을 얻지 않습니다.

입력 루트, 모든 원본 소스, 전체 예약과 정규 outbox는 함께 커밋됩니다. 요청 잠금 경합은 내부
재시도 없이 계획 트랜잭션 전체를 실패시킵니다. 같은 의도의 재시도는 작업 생성 후에도 최초
그래프·예약 시각을 유지합니다. 기존 C3의 원본 재시도 영수증, 독립 작업 및 다른 정확한 범위의
동일 요청 ID는 유지됩니다.

새 계획의 비공개 `reservation_profile=1`, `reserved_at_lexical`, `reserved_at_key`는 잠금 안의
DB 시계가 기록합니다. 원본 입력 해시나 C3 밀리초 영수증은 바꾸지 않습니다. 네이티브 순서 키는
문자열로 읽어야 하며 Date·Number로 반올림하지 않습니다. 잠금을 기다린 뒤 오래된 스냅샷을 읽는
격리 수준은 필수 트리거가 거부합니다.

기존 계획은 예약 메타데이터가 null인 채 원본 바이트·해시·영수증을 유지합니다. 업그레이드나
동일 재시도는 과거 기록에 사전 예약 증거를 만들어 주지 않습니다. 권위 있는 발행자는 예약되지
않은 기존 입력을 거부하고 새 명시적 요청을 사용해야 합니다. 과거 타임스탬프 비교만으로는 부족합니다.

## 동일 클라이언트에서의 관측

`readPostgresReleaseDecisionReservationsOnClient(client, scope, reference, budget)`는 소유 읽기
경로로 원본 입력 그래프 전체와 정확한 입력 해시를 검증한 다음, 같은 클라이언트에서 순서가 고정된
모든 예약을 대조합니다. 네이티브 시각 키는 문자열로 유지하며 Date·Number로 반올림하지 않습니다.
알 수 없는 프로필, 일부만 비어 있거나 혼합된 기존 메타데이터, 누락·중복·재정렬, 변경된 범위·입력·
요청 참조는 전체 실패입니다.

필수 원본 합산 예산은 해석 전에 원시 행과 반복·빈 조회를 차감합니다. 읽기·무결성·예산 오류를
호출자가 잡더라도 그 예산은 영구적으로 실패 상태가 됩니다. 이후 읽기나 성공한 사용량 보고에
재사용할 수 없습니다. 새 트랜잭션·클라이언트·예산이나 성공 관측 캐시를 만들지 않습니다.

호출자의 정확한 범위의 READ COMMITTED 트랜잭션·백엔드·savepoint·입력 잠금은 반환 후에도 유지됩니다.
존재하지 않는 루트는 null, 기존 미예약 목록은 `legacy_unreserved`, 전체 새 예약은
`reservations_observed`로 구분합니다. 빈 관측 선택은 빈 목록을 그대로 보존하며 발행자 권한을
만들지 않습니다. 이 결과는 발행 seal이 아니며 모든 실패는 호출자 트랜잭션 전체 롤백이 필요합니다.

존재하지 않는 루트를 포함해 전체 읽기 전후의 네이티브 백엔드·트랜잭션 ID를 같은 합산 예산으로
확인합니다. 자동 커밋, 중간 트랜잭션 변경, 유지된 클라이언트 대신 넘긴 풀이 잠금 종료 뒤 성공
관측을 반환할 수 없습니다. 이 확인은 트랜잭션을 열거나 커밋하지 않으며 소유권은 호출자에게 있습니다.

소유 DB 시각 함수는 소수부 끝의 0을 생략하고 소수부가 0이면 `.000Z`로 기록합니다. 여섯 자리로
채우지 않고 이 원본을 보존합니다. 실제 SQL에서 얻은 0 및 1~6자리 벡터와 저장 컬럼의
`numeric(50,0)` 키 문자열로 모든 정상 형식을 확인합니다.

격리된 PostgreSQL 16.15 검사는 정의 바꿔치기·직접 SQL 작성자·양쪽 잠금 순서·롤백·세 범위 차원·
네이티브 영수증·이전 버전 업그레이드·마이그레이션 원장·기존 공통 저장소 동작을 확인합니다.
실제 합성 PostgreSQL 응답을 보존한 단위 검사는 채워진 목록과 빈 목록, 정확한/하나 부족한 합산
행·UTF-8 바이트 경계와 잡힌 오류 이후 재사용 거부를 확인합니다. 네이티브 검사는 존재·부재 잠금,
호출자 트랜잭션, 범위·격리 수준 거부와 기존 버전 업그레이드를 확인합니다. 복구 검사는 소유 읽기로
복원된 그래프를 재검증하고 예약 영수증을 정확하게 비교합니다. 기존 커버리지 기준과 보호는 유지합니다.

신뢰된 입력 저장소는 여전히 합성 원본 소스 픽스처를 받을 수 있습니다. 실제 인증, 현재 설치·발행자·
선택·소스 권한, 전용 역할, 최종 결정과 outbox의 원자적
발행은 남아 있습니다. 이 변경은 결정·사람 승인·서명을 발행하거나 체크포인트 4를 승인하지 않습니다.
Workflow 2는 7개 중 3개 승인 상태입니다.
