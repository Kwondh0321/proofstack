# 보존된 정책 기록의 의존성 목록 도출

[English](workflow-2-policy-record-closure.md) |
[한국어](workflow-2-policy-record-closure.ko.md)

상태: 보존된 메타데이터를 다시 도출하는 검사를 구현했습니다. Workflow 2 체크포인트 3은 열려 있습니다.

`capturePolicyRecordGraph`는 불변 요청의 후보·정책 루트에서 `entries`를 별도로 다시 계산합니다.
내부 [`deriveCapturedRecordClosure`](../../packages/policy-evaluation/src/derive-record-closure.ts)는
이미 만들어진 manifest 목록을 정답으로 받지 않습니다. 44개 기록 종류의 기존 검증기·열거기로
원본 레코드와 참조를 다시 확인하고 너비 우선 도달성과 모든 참조 발생 위치를 대조합니다.
별도 도출 과정이며 기존 스키마를 독립적으로 재구현하거나 제삼자가 감사했다는 뜻은 아닙니다.

## 보존하는 연결과 실패 경계

검증된 본문은 범위·정의 해시·수신 시각·전체 레코드 해시를 다시 통과해야 합니다. 본문에서
도출한 참조가 원래 부모 목록과 순서대로 기록된 간선에 일치해야 하며, 누락·추가·중복·순서 변경·
연결되지 않은 레코드·다른 대상으로의 대체를 거부합니다. 공유 레코드와 정상 역참조 순환은
허용하고 반복 참조의 위치를 모두 유지합니다.

순수 함수 `inspectPolicyEvaluationSelector`는 저장소 재조회 없이 보존된 자식의 기준 구성원,
모델 프로필 상호 참조, 실행 ID, 비교 계열 이전 버전을 기존 알고리즘으로 확인합니다.
동일 그래프의 검증된 자식과 모순되는 선택자 부재는 실패합니다. 실제 기준 구성원 불일치는
해당 기준 집합 본문을 읽을 수 있더라도 unavailable로 남깁니다. 없는 해시를 만들지 않습니다.

읽을 수 없는 부모는 `record: null`, `references: null`로 유지합니다. 하위 기록 부재는 명시적
관측이며 검증된 빈 목록이 아닙니다. 폐기된 본문만으로 저장소의 부재·이용 불가 관측을 독립적으로
증명할 수 없으므로, 발행 시 쓰기와 연동된 보호 아래 재확인해야 합니다.

`recordClosure.sources`는 이 경로에서 도출한 정렬된 정확한 기록 목록입니다. 기존 manifest
검증기의 예상 보존 기록 목록으로 사용할 수 있으며, 해시가 올바른 부분집합도 누락을 거부합니다.
이 결과만으로 완전한 의미·권한 snapshot이 되지는 않습니다.

## 남겨 두는 참조와 예산

`recordClosure.frontier`는 원본 간선 인덱스와 다음 구분을 보존합니다.

- `artifact`: 내용·수명주기를 별도 관측해야 하는 정확한 콘텐츠 설명자.
- `trace`: 전체 trace 완전성을 주장하지 않는 원본 이벤트 선택자.
- `unresolved_selector`: 원래 missing/unavailable 기록 선택자.
- `retained_declaration`: 프로토콜·구현·프로필·자격 정책·프롬프트·도구·출처·모델·안전 이벤트·요구 선언.

새 참조 종류는 타입 검사에서 명시적인 분류를 요구합니다. 선언은 설치·실행·제공자 신원·자격 증명
접근·승인·보존된 바이트가 아닙니다. 의도적으로 생략된 비교 아티팩트의 ID를 현재 카탈로그 조회로
바꾸어 생략을 복구하지 않습니다. 콘텐츠·trace·의미 검사 결과는 별도로 남습니다.

재열거한 모든 반복 참조와 정규 UTF-8 바이트를 trace·콘텐츠 I/O 전에 같은 요청 예산에 합산합니다.
정확한 한도는 허용하고 하나 부족하면 전체 실패합니다. 모든 CPU 연산이나 실측 메모리 상한을
계량한다는 뜻은 아니며, 선택자가 많은 부모의 추가 검사 비용에 대한 처리량 주장은 없습니다.

실제 메모리 그래프, 44종 도메인 연결, 순환, 읽을 수 없는 루트, 선택자 모순·불일치, manifest
부분집합, 변조, 정확한 예산 경계를 테스트합니다. 전체 권한 이력·부재 보호, 콘텐츠·trace 연결,
규칙별 입력, sealed 계약, snapshot/job/fence 원자 발행, 워커·API·SDK·복구·최종 감사는 남아 있습니다.
읽기 전용 source recheck는 여전히 잠금 해제 후 반환하며 나중의 발행 권한이 아닙니다.
새 route·role·grant·migration·워커·seal이나 추가 수락 체크포인트를 도입하지 않습니다.
