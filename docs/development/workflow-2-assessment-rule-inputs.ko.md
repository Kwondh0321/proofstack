# 후보 소유 평가 규칙 입력

[English](workflow-2-assessment-rule-inputs.md) |
[한국어](workflow-2-assessment-rule-inputs.ko.md)

상태: 보존된 평가 입력을 구현했습니다. Workflow 2는 승인된 체크포인트 2/7이며
체크포인트 3은 미완료입니다. 이 입력은 평가 결과가 아닙니다.

`capturePolicyArtifactEvidence`는 고정된 내부
[`inspectCapturedAssessmentRules`](../../packages/policy-evaluation/src/capture-assessment-rules.ts)의
`assessmentRules`를 반환합니다. 수집한 기록의 독립 복사본에서 정확한 요청·범위·시각·
루트 순서를 확인하고, 모든 원래 기록·수신 해시·전체 부모 참조·간선을 소유 도메인의
검사기로 재검증합니다. 부재 본문·참조는 null이며 엄격한 manifest 관측을 만족해야
합니다. 부재 기록에는 임의의 간선을 만들 수 없습니다.

기존 정책 평가 목록·평가 스냅샷·모델 보증 검사·후보 평가 계보를 I/O 없이 재현하고
전체 보고가 원래 수집과 일치하는지 확인합니다. 사용하지 않거나 읽을 수 없는 후보
선언과 모든 원래 규칙·위치·간선·소유권을 보존합니다. 정책에서만 참조하는 읽을 수
있는 평가는 `not_declared`이며 후보 소유 피연산자로 사용할 수 없습니다.

## 세 가지 기술적 입력

- Coverage의 `observed`는 원래 집계의 `attemptedCount`에, `decided`는 pass+fail인
  `decidedCount`에만 연결합니다. 계수 9개와 원래 전체 구성원을 정확한 집계 해시에
  보존합니다. abstain·error·not-applicable을 제거하거나 결정으로 바꾸지 않습니다.
  부재 집계의 값은 null이며 실제 보고된 0과 구별합니다.
- Uncertainty는 소유 집계·집계 정책·표본 가정과 원래 `passInterval`을 유지합니다.
  요청한 원래 하한·상한을 선택하고 방법·버전·신뢰수준·가정의 일치를 기술합니다.
  미보고 이유와 불일치하는 보고 구간도 보존하며 다른 구간을 계산해 임계값을
  통과시키지 않습니다.
- Eligibility는 평가의 구조화된 적격성과 모든 원래 차원, 또는 별도 형식인 모델
  보증의 적격성 enum·원래 사유·정확한 base 평가를 유지합니다. 부재 증거는
  명시적으로 남습니다.

각 입력은 전체 평가 해시와 이번 호출의 재현된 후보·스냅샷·모델 검사 인덱스에
연결됩니다. 다른 수집 결과에 이 인덱스를 적용할 수 없습니다. 보고된 계수·구간·
적격성과 불일치하거나 사용 불가한 전제조건이 함께 존재할 수 있습니다.
`inputs_retained`는 보존된 증거를 뜻하며 현재 사용 가능하거나 자격 있는 입력을
인증하지 않습니다.

## 누적 예산과 남은 경계

전체 원래 참조 재검사, 네 소유 보고의 재현, 전체 목록·문맥과 반복 규칙 프레임을
기존 수집·기록 바이트와 동일한 유한 canonical UTF-8 개수·바이트 예산에 계산합니다.
정확한 한도는 통과하며 하나 모자라면 실패합니다. 반환된 중첩 기록은 독립 복사본입니다.
저장소·객체·키 I/O, 의존성·역할·권한·마이그레이션·경로·worker·발행 포트를
추가하지 않으며 공개 표면에는 보고서 타입만 추가합니다.

`authorityBoundary`는 `retained_inputs_only`입니다. 전체 의미·현재 권한 의존 관계,
엄격한 봉인 스냅샷·결과 계약, 같은 열린 트랜잭션의 스냅샷·작업·fence 발행,
일곱 결정적 조건, 내구성 실행, API·SDK·복구·기여자 수락과 독립 완료 감사가
필요합니다. 끝난 원본 재검사 트랜잭션은 이 보고를 이용한 나중 발행을 승인하지 않습니다.
