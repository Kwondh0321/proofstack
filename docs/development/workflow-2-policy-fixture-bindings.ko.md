# 기록형 픽스처의 아티팩트 귀속 검증

[English](workflow-2-policy-fixture-bindings.md) | [한국어](workflow-2-policy-fixture-bindings.ko.md)

상태: 요청 기반 아티팩트 수집에서 기록형 픽스처의 게시·귀속 관계를 검증합니다.
전체 의미 관계, 변경 가능한 권한, 경쟁 방어가 있는 봉인과 Workflow 2의 세 번째 체크포인트는 미완료입니다.

## 내용 무결성과 소유 관계의 분리

복호화·해시 검사가 통과해도 파일이 다른 픽스처에 속하거나 게시자·마스킹·보존 조건이 다를 수
있습니다. 반대로 소유 기록이 맞아도 원문이 남아 있다는 보장은 없습니다. 두 관측을 별도로
보존하며 어느 하나를 정책 판정으로 바꾸지 않습니다.

검증 기준은 [ADR-0017](../architecture/0017-own-interaction-content-per-fixture.md)과 기존
메모리·PostgreSQL 픽스처 게시 경로입니다. 일반 빌드 파일·일반 트레이스 참조·증거 전용
픽스처에 새 소유권 의무를 부과하지 않습니다.

## 도메인 검사와 실제 수집 연결

`@proofstack/datasets`의 `inspectPolicyEvaluationFixtureArtifactBindings`는 이미 관측한
정확한 schema 0.2 픽스처와 선언된 바인딩마다 순서대로 제공된 카탈로그 투영을 검사합니다.
픽스처의 범위·참조·평가 시각·원래 전체 기록 해시를 다시 검증하므로 정의 해시가 같더라도
게시 접수 정보가 바뀌면 거절합니다. 목록이 짧거나 길거나 중간 원소가 빠지면 생략하지 않고 실패합니다.

이 검사는 순수 함수이며 DB·오브젝트·네트워크·원문을 읽지 않습니다. 임의 검증기 등록도
받지 않습니다. 투영의 메타데이터·소유권을 검증하지만 비공개 필드까지 포함하는 카탈로그
해시는 투영만으로 재계산할 수 없습니다. 해당 해시는 고정된
[아티팩트 관측기](workflow-2-policy-artifact-observation.ko.md)가 제공하는 출처 정보이지
HTTP 호출자가 제출해도 신뢰할 수 있는 증명이 아닙니다.

공개 `capturePolicyArtifactEvidence`가 자신의 그래프·아티팩트 관측에서 직접 검사 입력을
만듭니다. 내부 조립 함수는 패키지 루트에 공개하지 않습니다. 선언·요청·프롬프트·각 시도에서
반복된 참조를 모두 유지하고 기존 읽기·바이트 예산을 초기화하지 않습니다. 서로 다른 반복
관측은 귀속 검사 전에 기존 충돌 방어로 실패합니다.

`fixtureBindings`는 검증한 기록형 픽스처의 정확한 참조·전체 기록 해시를 보존합니다. 각
파일은 선언 인덱스 `bindingIndex`, 아티팩트 ID, 카탈로그 해시와 동일 결과의 원래 관측을
가리키는 `artifactCaptureIndexes`를 갖습니다. 그래프의 부모 해시·JSON 포인터도 남습니다.
일반 빌드·트레이스 출현을 자동으로 픽스처 소유 파일로 해석하지 않습니다.

부모를 읽을 수 없으면 그래프의 미해결 관측을 남기며 알 수 없는 파일 목록을 만들지 않습니다.
따라서 빈 `fixtureBindings`는 누락된 픽스처가 없다는 증거가 아닙니다. `roots_unavailable`도
성공적인 빈 귀속 목록을 반환하지 않습니다.

## 결과 해석

| 상태·이유 | 의미 |
| --- | --- |
| `matched` | 검사한 불변 게시·귀속 필드가 일치 |
| `unavailable / catalog_unavailable` | 쓸 수 있는 카탈로그 투영이 없음. 상세 원인은 원래 아티팩트 관측에 보존 |
| `mismatch / scope_mismatch` | 테넌트·프로젝트·환경 불일치 |
| `mismatch / descriptor_mismatch` | 파일 ID·해시·크기·미디어 형식·분류·마스킹 단계 불일치 |
| `mismatch / retention_mismatch` | 픽스처의 만료 없는 보존 조건과 불일치 |
| `mismatch / redaction_mismatch` | 마스킹 상태 또는 순서가 있는 전체 처리 기록 불일치 |
| `mismatch / publication_time_mismatch` | 활성화 접수 정보가 없거나 생성·활성화 시각이 픽스처 게시보다 늦음 |
| `mismatch / ownership_missing` | 알려진 카탈로그에 소유 기록이 없음 |
| `mismatch / ownership_mismatch` | 소유 픽스처·버전·범위·파일 ID·귀속 시각·귀속 주체 불일치 |

검사 순서에서 첫 불일치를 보고하며 한 카탈로그의 모든 결함을 열거하지는 않습니다. 파일
바인딩은 모두 검사합니다. 소유 ID뿐 아니라 `boundAt === fixture.createdAt`,
`boundByPrincipalId === fixture.createdByPrincipalId`를 포함한 정식 게시 기록과 같아야
합니다. 생성·활성화 시각은 밀리초로 반올림하지 않고 지원하는 전체 정밀도로 비교합니다.

게시 이후 삭제 표시·퍼지가 생겨도 불변 소유 관계를 지우지 않습니다. 귀속은 `matched`인데
내용은 이용 불가일 수 있고, 오브젝트가 없을 때도 같습니다. `matched`, 복호화 성공 또는
`artifacts_captured` 하나만으로 정책 충족·출시 허가·봉인을 선언하면 안 됩니다.

## 검증과 남은 경계

도메인 검사에는 부모 전체 해시·접수 정보, 소유권의 각 필드, 범위·파일 설명·마스킹 기록·보존
조건 변경, 시각 경계, 잘못된 목록과 반환값 격리를 포함합니다. 통합 검사는 합성 상호작용 데이터와 실제 픽스처 게시,
메모리 그래프·증거 저장소와 인증 암호화를 사용합니다. 별도 메모리 카탈로그는 기존 테스트용
소유권 연결 함수를 사용하며 새 교차 어댑터 트랜잭션이나 PostgreSQL 정책 워커 검증을 주장하지 않습니다.

내용은 맞지만 소유자·게시자·귀속 시각이 틀린 경우, 보존·마스킹 조건을 바꿔 다시 암호화한
경우, 카탈로그·부모·오브젝트 부재, 삭제 표시, 반복 출처와 내부 조립 오류를 검사합니다.
일반 파일의 읽기에는 픽스처 소유권을 강제하지 않으며 기존 예산과 운영 오류 전파를 유지합니다.

모든 선행 버전·데이터셋·재현·평가 관계, 원문의 의미, 소유자의 권한, 권한 있는 철회·정책 이력,
관측 이후 변경 방어는 이번 범위가 아닙니다. 해당 경계·트랜잭션 revision 검사·봉인·정책 조건·
영속 작업·API/SDK·복구·격리·종단 간 승인을 이어서 완료해야 합니다. Workflow 2 완료 수는 **2/7**입니다.
