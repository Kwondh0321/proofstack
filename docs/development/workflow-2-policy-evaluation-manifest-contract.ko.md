# 정책 평가 의존 증거 목록 계약

[English](workflow-2-policy-evaluation-manifest-contract.md) |
[한국어](workflow-2-policy-evaluation-manifest-contract.ko.md)

상태: 증거 목록 기반 기능 구현. 정책 평가 체크포인트는 아직 미완료입니다.

이 변경은 [ADR-0022](../architecture/0022-snapshot-bound-policy-evaluation.ko.md)와
[평가 진입 감사](workflow-2-policy-evaluation-entry-audit.ko.md)에 필요한 불변 증거 목록입니다.
봉인된 스냅샷, 출처 수집, 정책 판정, 워커, 영속 저장, 공개 API는 아직 구현하지 않았습니다.
목록의 무결성은 출처 진실성, 정책 충족, 사람의 승인 또는 릴리스 권한을 뜻하지 않습니다.

## 정확한 참조와 관측

[참조 계약](../../packages/contracts/src/policy-evaluation-source-reference.ts)은 후보·정책·설치
바인딩, 데이터셋·픽스처, 비교 정의·결과·스냅샷, 평가·집계·실행·관측, 출처·검토자 자격,
모델·사람 평가 보증, 재현 결과·런타임 등 44종의 정확한 참조를 보존합니다. 기존 참조 스키마를
재사용하며, 검색 발견·실행 거절 기록은 기존 식별자·해시 필드를 사용합니다. 임의 JSON, URL,
최신 별칭, 호출자가 선택한 피연산자로 대체하지 않습니다.

식별 키는 `종류:기록ID`이며 ASCII 코드 단위로 정렬합니다. 논리적 부모가 아니라 저장소의
불변 버전·결과·시도 ID를 사용합니다. 런타임·격리 프로필은 `종류:ID:버전`입니다. 같은 기록에
다른 해시·부모·비교 역할·재현 작업을 붙이면 새 항목이 아니라 충돌입니다. 서로 다른 종류는
ID나 JSON 모양이 같아도 구분합니다.

각 항목은 정확한 참조와 수집기가 만든 다음 관측 중 하나를 포함합니다.

- `verified`: 검증된 원본 전체에 `encodeEvaluationCanonicalJson(record)`를 적용한 SHA-256인
  `recordSha256`을 보존합니다. 원래 접수 정보가 있으면 포함하며 기존 의미적 정의 해시와
  구분합니다. 수집기는 원본별 스키마·범위·참조·정의 해시·저장 투영을 먼저 검증해야 합니다.
- `missing`: 권위 있는 정확한 조회가 수집 시점의 부재를 확인했습니다.
- `unavailable`: `record_invalid`, `reference_mismatch`, `not_yet_available`를 구분합니다.
  손상이나 미래 증거를 0, 정상적인 빈 집합, 항목 삭제 허가로 바꾸지 않습니다.

예상 밖의 저장소 오류, 네트워크 실패, 워커 중단과 재시도는 관측이 아니라 운영 실패입니다.
후보·정책 루트의 부재나 손상은 여전히 사용 가능한 스냅샷의 봉인을 막아야 합니다. 목록 스키마
자체가 루트를 판별하거나 이 의무를 대신하지 않습니다. 아티팩트 소유권·바이트 가용성·변경
가능한 생명주기는 별도 관측과 리비전 보호가 필요합니다. 중첩 참조만으로 보존 바이트를
검증하지 않습니다. 개별 기준 등은 소유 기록과 이후 규칙 증거 투영에 정확히 묶여야 합니다.

## 전체 페이지와 해시 연결

[목록 계약](../../packages/contracts/src/policy-evaluation-manifest.ts)의 범위는 다음과 같습니다.

| 경계 | 한도와 조건 |
| --- | --- |
| 전체 항목 | 2–100,000개. 향후 작업은 요청자가 지정한 더 작은 누적 수집 한도도 집행해야 함 |
| 페이지 | 마지막을 제외하고 128개. 마지막도 비어 있으면 안 되며 인덱스·총개수·목록 ID·정확한 요청에 묶임 |
| 루트 설명자 | 최대 782개. 페이지 해시·개수·첫 키·마지막 키를 빠짐없이 순서대로 보존하고 중첩을 금지 |
| 조회 표현 | 루트와 페이지 각각 UTF-8 512 KiB. 서버 정보와 이스케이프된 HTTP 상관 ID 포함 |

페이지 해시는 항목·관측·인덱스·총개수·목록 ID·요청·범위·스키마·인코딩 도메인을 묶고,
루트 해시는 모든 페이지 설명자를 순서대로 묶습니다. 페이지는 목록 ID를, 루트는 페이지 해시를,
향후 스냅샷은 루트 해시를 참조하므로 순환이 없습니다. 불변 루트와 정확한 페이지 인덱스를
사용해야 하며 `latest` 커서를 쓰면 안 됩니다.

`assemblePolicyEvaluationManifest`는 수집기가 준비한 순서를 그대로 사용합니다. 자동 정렬,
중복 제거, 부재 채우기, 가용하지 않은 항목 삭제, 초과 목록 잘라내기를 하지 않습니다.
`validatePolicyEvaluationManifest`는 기대 루트·요청·범위를 확인하고 모든 해시를 재계산한
후 별도로 도출한 전체 참조 목록과 비교합니다. 개수만 같아서는 부족하며 종류·식별자·해시·
역할·대상·결과·원래 시각 문자열까지 일치해야 합니다. 스키마 통과는 암호학적 검증이 아닙니다.

기대 목록은 향후 권위 있는 루트와 의존 그래프에서 도출해야 하며, 검증 대상 목록을 그대로
복사하거나 공개 호출자가 제공하도록 해서는 안 됩니다. 부모가 없으면 가용하지 않은 경계로
남기고 알 수 없는 하위 기록을 규칙 충족에 사용하지 않습니다. 현재 검증기는 주어진 기대
목록과의 차이를 감지할 뿐 그 기대 목록 자체의 권위·완전성을 증명하지 않습니다. 실제 수집과
저장소 승인 검증이 그 별도 의무를 충족해야 합니다.

[공개 벡터](../../packages/contracts/vectors/policy-evaluation-manifest-v1.json)는 독립적인
정렬 키 JSON 직렬화기로 계산했습니다. 페이지는 982바이트, 루트는 676바이트이며 정확한
SHA-256은 벡터와 영문 문서에 수록했습니다. 출처 해시는 합성 표본입니다.

## 검증과 남은 경계

테스트는 모든 종류, 같은 ID의 해시·부모·역할 충돌, 부재, 페이지 경계, 누락·중복·순서 변경,
범위·요청 삽입, 해시 위조, 재계산과 기대 목록 불일치를 다룹니다. 코어는 100,000개 항목을
실제 782개 페이지로 조립하고 전부 검증하는 테스트도 포함합니다.

크기 테스트는 최대 프로필 키를 가진 전체 루트와 최대 ID·프로토콜·버전·미디어 타입·소수점
이하 30자리 시각의 재현 결과 페이지를 사용합니다. 상관 ID의 한글·이모지·제어문자·단독
서로게이트·따옴표·역슬래시 및 지수 표기의 정수 확장도 확인합니다. 표현 크기 여유에 대한
테스트이며 HTTP 스트림 집행, 메모리 성능이나 운영 SLO를 증명하지는 않습니다. 향후 워커는
수집 바이트·동시성도 제한해야 하고 전체 목록을 하나의 무제한 응답으로 전달하면 안 됩니다.

별도의 [comparison 선택 기반 기능](workflow-2-policy-evaluation-comparison-selection.ko.md)이 이제
candidate의 모든 comparison 결과를 조사하고 읽지 못한 집합과 모호한 집합을 보존합니다. 여전히
실제 출처 그래프의 권위 있는 전체 목록 도출, 선택한 결과의 전체 계보 검증, 규칙별 증거,
아티팩트·생명주기 관측, 보호된 수집·봉인, 스냅샷·결과, 지속 작업·별도 워커 권한이 남았습니다.
HTTP·SDK에서는 한도 직전·정확한 한도·초과 스트림, 불변 식별자와 전체 페이지를 검증해야 합니다.
응답 스키마만으로 공개 엔드포인트가 생기지 않으며 로드맵 완료 항목 수도 늘리지 않습니다.
