# 정책 평가용 재현 의존 관계 추출

[English](workflow-2-policy-evaluation-replay-references.md) |
[한국어](workflow-2-policy-evaluation-replay-references.ko.md)

상태: 계획·실행 대상 릴리스·성공 재현 결과의 직접 의존 관계 추출 기반입니다.
재귀 수집, 실제 바이트·권한 검증, 스냅샷 봉인, 규칙 평가, 영속 정책 워커와
체크포인트 종료 승인은 아직 완료되지 않았습니다.

[재현 추출기](../../packages/replay/src/policy-evaluation-replay-references.ts)는
[데이터셋 목록](workflow-2-policy-evaluation-dataset-references.ko.md)을 확장합니다.
이미 인가된 문맥, 수집한 기록 관찰, 명시적인 참조 개수·바이트 예산을 받습니다.
재현 도메인의 고정 검사기와 공통 기록 결속 경계로 다시 검증한 사본을 순회합니다.
출처 대체, 발행 기록·이력 변경, 미검증 증거와 지역적 충돌을 정상적인 빈 목록이나 부분
목록으로 바꾸지 않습니다. 저장소·네트워크·파일·자격 증명·프로세스 작업은 수행하지 않습니다.

## 직접 참조와 미해결 선언

`enumeratePolicyEvaluationReplayDefinitionReferences`는 계획과 대상 릴리스를,
`enumeratePolicyEvaluationReplayResultReferences`는 성공 재현 결과를 받습니다.
결과 재검증에는 기존 전체 이력 개수·canonical 기록 크기 제한도 계속 적용됩니다.

| 부모 기록 위치 | 추출 내용 | 별도로 필요한 검증 |
| --- | --- | --- |
| 계획의 데이터셋·기록 재현 호출의 fixture | 정확한 버전·해시를 포함한 기록 참조 | 실제 소속 관계와 분류된 콘텐츠 계보 |
| 계획·모든 시도의 실행/격리 프로파일 | 버전·해시·종류를 포함한 기록 참조 | 인가된 정의와 설치된 실행 권한 |
| 계획·시뮬레이션·모든 시도의 대상 릴리스 | 정확한 릴리스 기록 참조 | 실행 파일·빌드 출처 의존 관계 |
| 작업 루트·모든 시도의 계획 | 정확한 계획 기록 참조 | 실패한 시도와 반복 참조도 각각 보존 |
| 빌드 출처·실행 파일·시뮬레이션 자격·위험 수용·시도 결과 | 전체 파일 설명자 | 보관 수명·소유권·실제 바이트·수정 가드 |
| 워커 프로토콜·기록/대상 어댑터 | 형식화된 `replay_declaration` | 이름·버전은 설치 증명이나 manifest 어댑터 기록이 아님 |
| 사전 설치 대상·허용된 하위 프로세스 | ID와 각 해시 의미를 보존하는 선언 | 코드 로딩·실행 권한을 부여하지 않음 |
| 실제 제공자 endpoint 프로파일 | 해시가 포함된 정확한 선언 | 데이터셋의 해시 없는 선택자로 축소하지 않음 |
| 자격 증명 선택자 | ID·버전만 있는 선언 | 비밀 값이나 조회·사용 권한이 아님 |
| 예산 원장의 파일 생성 ID | ID만 있는 선언 | 예약이 실제 생성·보관을 증명하지 않으므로 설명자를 만들지 않음 |
| 빌드·호출·시뮬레이션 설정·실패 상세/재시도·실행/사용량 해시 | 해시만 있는 선언 | 콘텐츠 위치·canonical 원문·실제 바이트 검증을 추정하지 않음 |

선언은 소유 도메인의 계약과 서로 다른 프로토콜·버전 제한을 재사용합니다.
같은 endpoint ID·버전에 다른 정의 해시가 붙거나, 같은 자격 증명 버전이 서로 다른 부모 ID를
주장하면 충돌입니다. 서로 다른 자격 증명 버전은 허용합니다. 기존 불변 기록·전체 파일
설명자 충돌 검사도 적용합니다. 동일한 반복 참조도 예산 계산 전에 합치지 않습니다.

출력 위치는 부모 기록의 JSON pointer이며 가져올 URL이 아닙니다. 고정 필드 순서와 숫자
배열 순서를 사용해 모든 시도·관찰·선언을 보존합니다. 내장 호출 정의 해시는 선언으로
보존하지만 이 추출기가 내장 호출과의 해시 관계나 실제 실행을 독립적으로 증명하지는 않습니다.
실행 관찰 해시도 단독으로 실제 보관 바이트의 위치를 알려주지 않습니다. 내부 작업·시도·fence·
예약·boundary ID는 검증된 부모 기록에 남으며 외부 기록으로 만들지 않습니다.
시드·실행 제어·저장소 URL/리비전·목적지 호스트·자유 텍스트·빌더 이름·정책 설정도 부모 전체
해시에 결속되지만 검색·통신·자격 증명 접근·실행을 허용하는 정보로 해석하지 않습니다.

## 한도와 무결성

모든 기록·파일·미해결 선언을 각각 한 번의 참조와 전체 canonical UTF-8 크기로 계산합니다.
정확한 한도는 허용하고 초과하면 부분 결과 없이 예외를 발생시킵니다. 이는 부모별 한도이며
전체 그래프의 누적 예산이나 I/O·실행·시간 제한은 아닙니다. Manifest 출처 종류 44개는 그대로이며
`replay_declaration`은 참조 목록의 변형이지 새 manifest 출처나 봉인된 관찰이 아닙니다.
출처 세 종류의 직접 추출이 추가됐지만 자식 수집과 권위 있는 의존 관계 완전성 검증은 별도입니다.

재검증은 기록 일관성을 확인하며 출처 권한이나 완전한 권위 이력을 증명하지 않습니다.
합성한 스키마 유효 이력은 해당 상태 전이가 실제 발생했다는 증거가 아닙니다. 전체 기록 해시와
정확한 출처 비교는 원래 관찰에 순회를 결속하지만 저장소 어댑터의 이력 누락을 증명하지 못합니다.

## 검증과 남은 작업

테스트는 기존 정의 벡터, 모든 경계/실행 형식, 인덱스 9를 넘는 배열, 실제 메모리 저장소의
발행·작업·예산 흐름과 이전 실패 이력을 사용합니다. 별도의 구조 기반 오라클이 기록 형식,
파일 설명자와 선언 말단을 찾아 순서 있는 전체 목록 및 바이트 계산을 비교합니다.
예상 목록 생성에 운영 추출기나 수집기를 사용하지 않습니다. 부모·범위·시각 대체, 관찰 변경,
지역적 충돌, 정확한 예산 경계, 본문 일회 접근, 사본 격리, 엄격한 선언 검사와 예외도 점검합니다.

남은 출처 읽기, 재귀 그래프 수집, 정확한 trace 이벤트, 실제 파일·소유권, 설치·수명 권한,
전체 충돌·의존 관계 검사, 보호된 봉인, 결정론적 규칙, 영속 작업·별도 DB 역할,
API·SDK·워커, 실제 서비스 수용 검사와
[체크포인트 종료 조건](workflow-2-policy-evaluation-entry-audit.ko.md)은 계속 남아 있습니다.
사용자용 사이트·서버·DB 쓰기·실행 권한은 추가하지 않습니다.
