## 원래 기록과 평가를 연결

이번 변경의 캐시 없는 계약·핵심 패키지 검사에서 6,345+4,460개, 총 10,805개 테스트가
통과했습니다. 새 자격증명·레코드·전체 목록·신원·원래 작업 그래프·예산 검사 126개를
포함합니다. 커버리지 기준은 유지했고 타입·린트·경계·문서·서식·스테이징 비밀정보 검사도
통과했습니다. 이 결과는 최종 커밋의 저장소 전체 검사·원격 수용 검사와 구분합니다.

선택·검토자 권한·승인 기록의 엄격한 형식, 정의 해시와 기대한 모든 범위·참조 성분을
검증합니다. 원래 승인 인증 영수증을 바꾼 자료는 옛 해시로 통과할 수 없습니다.
원래 정책 평가는 소유 요청·전체 작업 그래프·실제 봉인/결정 실행 시도·전체 페이지·결과를
연결하고 결정론적 근거를 다시 계산합니다. 해시와 소유 결과 참조를 함께 바꾼 위조도
거부합니다. 결과를 요청자가 고르거나 latest 결과를 가져오지 않습니다.

기존 엔진의 정책 상태·후보 권한·적용성 검사를 공유합니다. 평가되지 않은 적용성은
미확정이며 C3의 승인 결과는 계속 indeterminate입니다. 현재 승인이 있다고 원래 근거
부족·적용 불일치·미검증 권한을 만족으로 바꾸지 않습니다. 옛 worker lease도 재활성화하지
않습니다. 원래 source witness는 이후 평가자·작성자 제외 조건을 소유 데이터로 유도할 때
사용해야 하며 아직 완전한 현재 권한 정족수를 구현한 것은 아닙니다.

## 원래 소스의 참여자 이력

[고정된 원본 참여자 수집기](../../packages/policy-evaluation/src/capture-original-evaluation-actors.ts)는
원래 작업·결과 검증과 설치된 48종 소유 레코드 reader를 재사용합니다. 각 원래 전체 저장
해시·영수증·정확한 소스·의미 관측을 비교한 뒤 고정된 principal 필드를 추출합니다. 정의
해시만으로 영수증의 행위자를 검증하지 않습니다. 원래 본문이 없으면 unavailable을
보존하며 새로 생성된 본문이나 최신 자료로 대체하지 않습니다. 정확한 후보·정책 원본은
검증된 원래 봉인 입력의 불변 본문을 사용합니다.

[버전 계약](../../packages/contracts/src/release-evaluation-actor-provenance.ts)은 소스 작성자,
평가 요청자, 리플레이 작업 요청자, 실제 평가·보증 행위자와 선언된 프로필 주체를 구별합니다.
리플레이 worker ID를 인증된 principal로 만들지 않습니다. 중첩된 전체 리플레이 이력 행과
두 종류 fixture 조회도 같은 원래 결정 예산에 포함합니다. 소유 조회 오류를 잡아도 전체
예산은 실패 상태를 유지하며 최초 원인을 보존합니다.

이는 과거 참여자 증거이며 완전한 현재 권한 cut·비공개 인증·예외 정족수·게시 권한이
아닙니다. 소스와 평가자 완전성은 서로 다르며 평가자 목록만으로 전체 소스 권한을
입증하지 않습니다. [요청 소유 reader](workflow-2-policy-request-job-readers.ko.md)가 메모리·
PostgreSQL의 정확한 요청→작업 조회를 제공합니다. 이를 완전한 현재 버전 계약에 연결하고
네이티브 guard와 원자적 결정 게시를 닫는 일은 계속 남아 있습니다. 호출자가 보낸 이 계약을 권한으로
받으면 안 됩니다. 테스트는 실제 메모리 소유 저장소와 upstream 누락을 검사하며 완전한
실서비스 결정 흐름을 검증했다고 주장하지 않습니다.

참여자 변경의 계약 6,367개·핵심 4,558개·정책 수집 1,604개, 총 12,529개 테스트와
세 패키지 타입 검사가 통과했습니다. 커버리지 기준은 유지했으며 새 검사 167개와 기존
실제 소유 라우팅의 추가 검증을 포함합니다. 순차 패키지 실행 중 소스·인덱스는 같았고
로그 SHA-256은 `778a39306813eee41b6587ad0df8532e34ffc805f2d8174b10f2b066448891a2`입니다.
이 결과를 최종 커밋의 저장소 전체·원격 검사로 대체하지 않습니다.

## 완전한 선택과 하나의 검증 예산

원래 선택, 관련 버전과 생명주기를 모두 보존합니다. 정확한 만료는 만료이며 미래 효력은
아직 유효하지 않습니다. 누락된 predecessor·event·successor는 미완성으로 남고 중복·충돌
버전이나 terminal event는 충돌로 남습니다. 철회·교체된 옛 선택을 유리한 최신 선택으로
대체하지 않습니다. 역순 256개 버전 체인도 재귀 없이 검사합니다.

실제 reader가 설치·gate target의 불변 logical root와 전체 열거·누락 guard를 확인해야
합니다. `complete` 표시는 그 증명이 아닙니다. 선택 안의 게시자 목록도 실제 현재 인증과
설치 범위 권한을 대신하지 않습니다.

동결된 하나의 예산이 반복·누락 관측, 모든 실제 승인 행과 정규 UTF-8 바이트를 셉니다.
정확한 한도는 허용하고 한 행·바이트·승인이라도 넘으면 전체 cut을 실패 상태로 만듭니다.
잘못된 정규 자료와 실제 할당량 초과는 서로 다른 오류입니다. 오류를 잡아 계속 실행해도
성공 사용량이나 부분 게시 권한을 얻을 수 없습니다.

## 자격증명과 새 행위

공개 상태 투영에는 원래 DB 시각·만료·사용·철회만 포함하며 쿠키·세션/CSRF/토큰 값,
prefix·salt·비밀 검증 해시·비공개 증명은 포함하지 않습니다. 비밀이 없더라도 적절한 열람
권한은 필요합니다. 기존 DB의 세션 시간·최대 사용 횟수 규칙을 보존합니다. 서비스 상태
계약을 추가했지만 서비스 자격증명 저장소나 새 인증기를 추가한 것은 아닙니다.

원래 바인딩·자격증명과 현재 grant·capability·tenant/project/environment를 따로 검사합니다.
owner 역할만으로 누락된 권한을 얻을 수 없고 서비스·workload가 사람의 승인이 될 수 없습니다.
서비스 데이터는 별도로 허가된 비공개 결정 게시 경로에서만 사용할 수 있습니다.

명시적 logout·바인딩 비활성화·관리자 철회는 옛 검토를 사용할 수 없게 합니다. 자연스러운
옛 로그인 만료만으로 이미 기록된 검토를 지우지는 않으며 승인 자체의 만료, 현재 검토자
권한·grant·충돌·정확한 subject는 계속 확인해야 합니다. 모든 새 승인·관리·게시에는 살아
있는 실제 인증이 필요합니다. 이 구분은 승인 시각이나 유효기간을 갱신하지 않습니다.
기존 밀리초 인증 영수증은 정확한 정수 floor로 원래 생성 시각 표현과 비교하고, DB 원문은
보존합니다. 이 규칙을 아티팩트 AAD나 의미 평가 시각에 적용하면 안 됩니다.

저장 전에 자격증명·행위자 관측을 포함한 완전한 버전 계약과 실제 현재 권한 port·정족수를
닫아야 합니다. 자료 0.1만으로 충분하지 않습니다. 이어서 메모리·네이티브 원자적
그래프/결정/outbox, 예약·복구·API/SDK·실서비스 기여자 검증과 별도 종료 감사를 수행합니다.

[캡처된 현재 검토·일반 정족수](workflow-2-current-release-reviews.ko.md)가 이 원본 검사를
사용합니다. 실제 소유 소스와 완전한 게시 계약·네이티브 권한은 계속 별도로 검증해야 합니다.
