# 정책 평가용 데이터셋 의존 관계 열거

[English](workflow-2-policy-evaluation-dataset-references.md) |
[한국어](workflow-2-policy-evaluation-dataset-references.ko.md)

상태: 데이터셋·fixture의 직접 의존 관계 기반 기능. 재귀 수집, 보호된 스냅샷, 규칙 평가 및
체크포인트 승인은 아직 완료되지 않았습니다.

`packages/datasets`의 `enumeratePolicyEvaluationDatasetReferences`는 인가된 문맥,
[데이터셋 읽기](workflow-2-policy-evaluation-definition-readers.ko.md)의 정확한 관찰·기록,
참조 수와 바이트 한도를 받습니다. 저장소·네트워크·아티팩트 바이트에 접근하거나 에이전트를
실행하지 않습니다. core가 datasets를 역으로 가져오지도 않습니다.

## 관찰한 부모 기록과 연결

공통 `revalidatePolicyEvaluationCapturedRecord`가 래퍼 접근자 실행 전에 문맥을 복사하고,
미등록 필드와 검증되지 않은 관찰을 거부한 뒤 본문을 한 번 읽습니다. 고정 도메인 검사기가
스키마·정의 해시·정확한 범위와 참조·발행 시각을 재검증합니다. 새 전체 기록 해시와 출처가
원래 관찰과 같아야 합니다. 발행 메타데이터만 바꿔도 이전 관찰을 그대로 사용할 수 없습니다.
기존 평가·모델·사람 기록 30종의 열거 함수도 이 공통 경계를 사용합니다.

이는 내부 무결성 검사이지 인증이 아닙니다. 외부 호출자가 권위 있는 검증기를 선택하거나,
직접 만든 기록·해시만으로 실제 보관 사실을 입증하거나, 두 fixture 저장소의 충돌 검사를
우회할 수 없습니다. 예상 밖 오류도 기존 참조 오류의 원인으로 보존하며 빈 성공 목록으로
바꾸지 않습니다.

## 보존하는 의존 관계와 선언

| 부모 필드 | 참조 종류 | 의미와 남은 확인 |
| --- | --- | --- |
| 데이터셋 구성원 | `record` | 정확한 fixture ID·버전·해시, 실제 구성원 관계와 콘텐츠는 별도 확인 |
| 데이터셋·fixture 이전 버전 | `record` | 부모의 논리 ID로 완성한 참조, 실제 자식 계보는 별도 확인 |
| fixture 출처 | `trace_snapshot_selector` | 정확한 trace ID·이벤트 순서·개수·캡처 시각·관찰 한계, 이벤트 해시나 완전한 트레이스를 추정하지 않음 |
| 상호작용 아티팩트 바인딩 | `artifact` | 전체 서술자, 소유권·수명주기·바이트·리비전은 별도 확인 |
| 각 모델·도구 아티팩트 ID | `artifact` | 검증된 부모 바인딩과 연결한 서술자, 실패 시도와 반복 참조도 보존 |
| 프롬프트·도구 계약 | `interaction_prompt`, `interaction_tool_contract` 및 아티팩트 | 의미상 ID·버전·해시와 콘텐츠 위치, 실행 구현을 등록하는 것이 아님 |
| 정규화 요청 어댑터·캡처 어댑터·출처 형식 | `protocol_declaration` | 이름·버전 선언이며 실제 설치나 코드 로드 권한은 입증하지 않음 |
| 모델 공급자 엔드포인트 프로파일 | `endpoint_profile_selector` | 해시 없는 ID·버전, 별도 해소가 필요하며 URL 검색·인증정보 조회·공급자 호출은 하지 않음 |

포인터는 부모 기록 안의 위치이며 가져오기 URL이 아닙니다. 아티팩트 ID를 부모 내부 서술자로
연결하며 외부 조회는 하지 않습니다. 정규화 요청의 `adapterName`·`adapterVersion`은
`name`·`version`으로 표시합니다. 같은 프롬프트·도구 ID와 버전이 다른 정의 해시를 가리키면
로컬 충돌로 거부합니다. 같은 정의가 서로 다른 아티팩트 위치를 사용하는 것은 허용하되 각각
별도 출현으로 남깁니다. 기존 불변 기록·아티팩트 서술자 충돌 검사도 유지합니다.

고정된 스키마 필드 순서와 숫자 배열 순서로 실패한 호출, 선택적인 시스템·프롬프트·스트리밍
아티팩트, 반복 참조를 보존합니다. 아티팩트 필드 목록은 계약의 키와 컴파일 시 대조합니다.
자유 텍스트·공급자 요청 ID·모델 이름·편집 규칙 라벨 등은 부모 해시에 묶인 메타데이터이며
존재하지 않는 보관 기록 참조로 바꾸지 않습니다.

## 한도와 검증 경계

[공통 출현 한도](workflow-2-policy-evaluation-evidence-references.ko.md)는 중복과 미해결
선언을 포함해 각 항목의 개수와 정규 UTF-8 바이트를 계산합니다. 트레이스 선택자는 전체 이벤트
목록을 담은 **선언 하나**이며 해당 이벤트가 읽혔다는 뜻이 아닙니다. 실제 수집 시 각 이벤트의
개수·바이트·시간은 별도 누적 한도에 반영해야 합니다. 정확한 한도는 허용하며 초과 시 잘린
목록을 반환하지 않고 오류를 냅니다.

매니페스트의 불변 출처 종류는 바뀌지 않습니다. 이 출현 목록은 추가 매니페스트 기록, 봉인된
스냅샷, 자식 존재 증명이 아닙니다. 재현 계획·대상 릴리스·결과의 열거, 전체 수집·충돌 검사,
보관 바이트 내부 참조 확장, 설치·수명주기 권한, 리비전 검사, 실제 규칙 평가, 워커·영속성·
API·SDK와 [체크포인트 종료 조건](workflow-2-policy-evaluation-entry-audit.ko.md)이 남습니다.

## 검증

기존 정의 벡터 전체와 모델·도구 통합 fixture를 독립적으로 만든 구조 기반 참조 목록과
대조합니다. 정확한 바이트 계산, 선택 아티팩트, 실패 시도, 반복 참조, 9를 넘는 배열 인덱스,
이전 버전 ID, 실제 메모리 발행, 범위·시각 바꿔치기, 발행 메타데이터 변경, 위조 관찰,
방어적 복사, 잘못된 래퍼와 접근자 변조를 검사합니다. 기존 30종 열거 테스트도 공통 무결성
경계를 검증합니다. 이는 운영 환경 준비 완료를 입증하지 않습니다.
