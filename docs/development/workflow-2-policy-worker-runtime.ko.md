# 네이티브 정책 워커 런타임

[English](workflow-2-policy-worker-runtime.md) | [한국어](workflow-2-policy-worker-runtime.ko.md)

상태: 구현 선행조건이며 Workflow 2 체크포인트 3은 열려 있습니다(승인 2/7).

[인증된 단일 시도 라이브러리](workflow-2-policy-worker-attempt.ko.md)는 이제
`createPostgresPolicyWorkerRuntime`을 사용할 수 있습니다. 서버 소유 팩터리가 자원을 열기 전에
서비스 주체의 정확한 실행 범위를 다시 확인합니다. 전용 DB 역할과 TLS를 검증하고, 명시적으로
허용한 루프백에만 평문을 허용합니다. 네이티브 wire 풀은 연결 4개와 checkout 상한 500ms를
사용합니다. 마이그레이션을 확인하고 설치 카탈로그를 복사한 뒤 아티팩트 자원을 엽니다.

수집 시도마다 내부 allowance·manifest·snapshot·물리 읽기 예약 ID를 새로 만듭니다. 초기 고정
리더와 필수 수집 크레딧 예약은 같은 nonce를 사용합니다. 객체 읽기는 영속 바이트 예약과
`createS3PolicyWorkerArtifacts`의 제한된 리더를 반드시 거칩니다. SDK 물리 시도 1회, 정확한
암호문 크기와 유한한 abort를 유지하며, 예약 없는 기존 읽기 경로는 거부합니다. 객체·키 I/O 전에
초기 메타데이터 트랜잭션이 끝나고, 최종 전체 소스 검증·크레딧 정산·snapshot/job 저장은 기존
하나의 열린 트랜잭션에서 처리합니다.

반환 포트는 소유 워커 저장소, 정확한 원본 snapshot/result 리더, 신뢰된 봉인 조합과 종료뿐입니다.
전달 데이터에 control 풀이나 객체 쓰기 포트가 없으며 봉인 호출의 인증 주체·범위·워커 fence
대체를 거부합니다. 재시도는 원본 봉인을 유지하고 실제 결과 계산 전에 완전한 새 규칙 비용을
예약합니다. 완료 결과의 재관찰은 비용이나 객체 읽기를 추가하지 않습니다.

종료는 새 봉인 호출을 거부하고 이미 시작한 작업을 기다린 뒤 객체와 풀 정리를 모두 시도합니다.
동기 정리 실패도 다른 정리를 막지 않으며 반복 종료는 같은 결과를 돌려줍니다. 초기화 실패의
원인과 정리 오류를 보존합니다. 기다리는 것은 스케줄러 취소나 비용 환불이 아닙니다. 자원
팩터리가 반환 전에 실패하면 자신이 부분적으로 연 자원은 직접 정리해야 합니다.

단위 검사는 권한·설정 선검사, 필수 예산 연결, 내부 ID, 카탈로그 복사, 대체 거부, 제한된 S3
호출 전달과 정리 경합을 검증합니다. 실제 PostgreSQL 역할·마이그레이션과 인증 암호화된 S3
객체를 사용하는 통합 검사는 활성 워커 SQL 밖의 객체 읽기, 불변 snapshot/result 재읽기,
정확한 비용, 중복 완료 전달의 원본 보존과 control 역할의 실행 거부를 검증합니다. 합성 그래프의
일부 upstream 참조는 의도적으로 unavailable이므로 권위를 만들어 내지 않고 indeterminate로
남습니다. 전체 predicate/outcome, 기여자 그래프나 별도 프로세스 crash/취소 검증은 아닙니다.

실행 명령과 환경 변수는 [영문 가이드](workflow-2-policy-worker-runtime.md)에 있습니다.
반드시 새 격리 서비스의 `proofstack_test` DB와 테스트 S3를 사용해야 합니다. 테스트는 전용
역할과 고유 버킷을 만들고 진단용 DB·객체를 남기며 서비스 소유자가 정리를 관리합니다.
**Policy worker integration** CI가 기존 독립 작업 9개를 보존하면서 별도로 실행합니다.

실제 credential provider·독립 실행 파일·프로세스 재시작/crash/취소·전체 상태 복구·공개 API/SDK·
완전한 기여자 흐름·독립 종료 감사가 남습니다. 테스트의 로컬 키와 합성 credential 카탈로그는
운영 신원·키 관리·TLS 배포·OS 격리를 입증하지 않습니다. 지속 목표·큐·연속 스케줄러를 만들지
않으며 출시 결정이나 배포 권한도 제공하지 않습니다.
