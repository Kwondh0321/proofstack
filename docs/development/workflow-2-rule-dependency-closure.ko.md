# 후보 소유 규칙의 의존 경로

[English](workflow-2-rule-dependency-closure.md) |
[한국어](workflow-2-rule-dependency-closure.ko.md)

고정된 artifact capture 구성이 [원래 순서의 규칙 입력](workflow-2-complete-rule-inputs.ko.md)을
캡처한 기록·원본 참조·남은 의존 경로에 연결합니다. 체크포인트 3의 준비 작업이며
Workflow 2의 승인된 체크포인트는 **2/7**입니다.

## 원본 목록과 위치

내부 함수는 소유 도메인의 검증기로 전체 원본 기록을 다시 열거하고, 요청의 루트에서
도달 가능한 기록을 독립적으로 구성합니다. 전체 manifest 항목과 기록 closure 및 사용량을
비교합니다. 요청·범위·의미 시각·부모 해시·원본 수신 시각·선택자 결과·프로토콜 후보가
연결되며, 항목이나 frontier의 누락·추가·순서 변경·교체는 반환 전에 실패합니다.

`ruleDependencies.sources`에는 사용하지 않거나 읽을 수 없는 기록도 남습니다.
`frontier`에는 artifact·trace·선언·미해결 선택자의 모든 원본 발생 위치가 남습니다.
source 위치는 이 보고서의 정렬된 목록, edge 위치는 이번 호출의 원본 그래프,
frontier 위치는 이 보고서의 전체 frontier를 가리킵니다. 호출자가 다른 증거로
교체하거나 새로 조회할 권한을 뜻하지 않습니다.

별도 `rootContext`는 규칙 밖의 정책 의존성과 후보의 문맥을 펼칩니다. 각 규칙은
원본 predicate와 source 참조를 유지합니다. artifact 규칙은 선택된 후보 구성요소를,
비교 규칙은 읽을 수 없거나 사용하지 않는 결과를 포함한 **후보의 전체 비교 목록**을,
assessment 규칙은 존재하는 경우 정확한 후보 선언을 연결합니다. 없는 assessment 대신
다른 결과를 고르지 않습니다. 승인은 원래 입력에서 `not_evaluated`와
`approval_not_evaluated`로 남습니다.

단일 대상이 null이어도 보존된 프로토콜 후보를 모두 순회합니다. 미래 시각·사용 불가·
descriptor 불일치 후보를 삭제해 승자를 고르지 않습니다. 연결된 선언의 권한 frontier도
유지합니다. 프레임 안의 기록은 고유하지만 반복된 참조와 frontier는 모두 남으며,
서로 다른 규칙은 별도로 계량합니다. 루트를 다시 만나도 다른 모든 규칙을 함께 펼치지 않습니다.

## 한계와 남은 작업

원본 재열거와 canonical 문맥·항목·전체 프레임이 같은 수량·UTF-8 바이트 예산을 사용합니다.
프레임 수량에는 반복된 seed/source/edge/frontier 위치도 포함합니다. 중첩 반환값은
독립된 복사본이며 추가 저장소·객체·키 조회를 수행하지 않습니다.

이 위치 정보는 기록된 값의 평가 자격·현재 권한·적용성·판정·실행 코드·승인·봉인을
확정하지 않습니다. 무관한 미사용 기록의 누락을 0이나 규칙 판정으로 바꾸면 안 됩니다.
소유 도메인의 의미 검증, 권한, 누락 상태의 해석 뒤에 제한된 snapshot/result 계약이
필요합니다. 읽기 전용 재검사 트랜잭션은 반환 전에 끝나며, 게시에는 계속 열린 하나의
트랜잭션 안에서 전체 guard와 실행 fence를 유지해야 합니다.

실제 암호화 메모리 capture 및 PostgreSQL의 유지된 metadata 트랜잭션 구성에서
전이 경로·반복·누락·미래 프로토콜 후보·변조·정확한 수량/바이트 경계를 검사합니다.
캐시 없는 전체 검사와 정확한 커밋의 CI/security 뒤에 종속 구현을 진행합니다.
봉인·원자적 게시·7개 판정·지속 작업/작업자 권한·API/SDK·복구·기여자 통합 및
독립 exit audit와 이후 체크포인트는 남아 있습니다.
