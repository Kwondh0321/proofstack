# 인증된 승인 철회 참조 구현

Workflow 2 체크포인트 4는 아직 완료되지 않았습니다. 기본 설명은
[영문 가이드](workflow-2-authenticated-approval-revocation-reference.md), 설계 결정은
[ADR-0063](../architecture/0063-preserve-original-approval-mutation-provenance.md)에 있습니다.

`ReleaseApprovalRevoker.revokeApproval`은 실제 OIDC 브라우저 자격과
`eventId`, 정확한 승인 참조, `reason`만 받습니다. 쿠키·CSRF·현재 `approval:decide`
검증이 요청 본문과 원본 조회보다 먼저 실행됩니다. 범위·검토자·시각은 서버가 정하며,
다른 사람이나 권한 선언 관리자가 원래 검토자를 대신해 철회할 수 없습니다.

명시적인 `synthetic_reference`는 선택·검토자 관리와 같은 비공개 테넌트 상태 안에서
실제 승인 저장소, 원래 인증 프로필, 소스·프로필의 outbox 의도를 함께 보존합니다.
전체 대상 목록과 원본 해시·관계를 다시 확인하고, 철회·인증 프로필·의도를 한 번에
확정합니다. 중간의 권한·세션·소스 변경, 완료 전 로그인 만료, 발행 시각보다 과거인
최종 시각, 누락·변조된 원본은 부분 기록 없이 실패합니다.

본인 승인을 철회할 때 예전 승인의 유효기간이나 현재 전문성·선택이 유지될 필요는
없지만 현재 로그인과 승인 권한은 필요합니다. 동일 요청의 재시도와 새 로그인도 최초
행위자·세션·요청·시각·기록·프로필을 바꾸지 않습니다. 기존 승인·평가·결정은 그대로
보존됩니다. 원래 인증 근거가 없는 과거 행에 근거를 만들어 붙이지 않습니다.

별도 0.1 승인 발행 프로필은 원래 기록·OIDC 사용자·안전한 권한·세션 메타데이터의
정확한 해시와 시각을 보존합니다. 쿠키·CSRF·비밀 검증값·아티팩트 평문·키를 담지
않습니다. 독립 Python 벡터와 경계·변조·경쟁·롤백 검사가 이를 검증합니다. 프로필의
원래 시각에서 유효했던 신원은 현재 인증이나 현재 검토 권한의 증명이 아닙니다.

테스트용 원본 가져오기는 명시적인 합성 과거 자료이며 실제 새 승인 발행을 증명하지
않습니다. 새 승인 발행의 현재 대상·원본 행위자·검토자·근거/통제 내용 검증,
PostgreSQL 가드 유지·원자적 발행·복구, 결과 전 입력 계획, 결정 발행, API·SDK·기여자
통합과 독립 종료 감사가 남아 있습니다. 이후 체크포인트 5–7과 측정에 따른 5단계를
진행하며, 이 참조 구현만으로 단계 완료·운영 승인·프로덕션 준비를 주장하지 않습니다.
