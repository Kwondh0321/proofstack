# PostgreSQL 정책 평가 출처 쓰기 직렬화

[English](workflow-2-policy-source-locks.md) | [한국어](workflow-2-policy-source-locks.ko.md)

상태: 실제 DB 쓰기 경로의 잠금 참여와 비공개 트랜잭션 잠금 기능을 구현했습니다.
Workflow 2 체크포인트 3은 미완료이며 완료 수는 **2/7**입니다. 원자적 입력 발행의 전제조건이지,
스냅샷 봉인·변경 비교·평가기·출시 게이트가 완성된 것은 아닙니다.

## 보호되는 쓰기

마이그레이션 `0050_policy_evaluation_source_locks`는 직접 SQL과 기존 발행 함수까지 포함한
DB 쓰기에 트랜잭션 단위 배타적 advisory lock을 적용합니다.

| 출처 식별자 | 같은 잠금을 사용하는 변경 |
| --- | --- |
| 테넌트 + `artifact` + 파일 ID | 카탈로그 생성·상태 전이, 기록된 fixture의 파일 소유권 추가 |
| 테넌트 + `release_policy` + 정책 버전 ID | 정책 발행, 철회·대체 이력 추가 |

DB가 도메인 구분자가 있는 JSON 배열을 해시해 잠금 키를 만듭니다. 기존 테넌트 단위 고유 ID를
따르며 프로젝트·환경별 조회 조건과 RLS를 대체하지 않습니다. 잠금은 읽기나 발행 권한이 아닙니다.
해시 충돌은 무관한 기록을 보수적으로 직렬화할 수 있지만 필요한 잠금을 생략하지는 않습니다.

불변성·상태 전이·접수 기록·소유권·테넌트 격리·outbox 제약은 유지합니다. AFTER 행 트리거이므로
기존 도메인 검증기의 행 잠금 순서를 유지합니다. 잠금을 기다리는 쓰기는 커밋되지 않아 다른
트랜잭션에 보이지 않습니다. **아직 없는 파일·정책 버전·종결 이력**의 동시 생성도 보호합니다.
기존 행에만 거는 잠금으로는 이 경우를 보호할 수 없습니다. 외부 호출이나 새 보존 데이터는 없습니다.

## 비공개 읽기 프로토콜

`proofstack_try_lock_policy_evaluation_source(kind, id)`는 유효한 트랜잭션 로컬
테넌트·프로젝트·환경과 READ COMMITTED 격리 수준을 요구합니다. 공유 트랜잭션 잠금을
대기 없이 시도하고 Boolean을 반환합니다. 여러 관측자는 공존할 수 있고, 쓰기는 배타적 잠금을
사용합니다. 두 함수는 호출자 권한과 고정 `pg_catalog` 검색 경로를 사용하며 PUBLIC 실행 권한은
제거합니다. 기존 런타임 역할에는 새 읽기 함수 권한을 추가하지 않았습니다.

앞으로의 신뢰된 스냅샷 발행기는 **한 연결 안에서** 아래 절차를 모두 수행해야 합니다.

1. 인가된 정확한 scope와 유효한 작업 fence로 명시적 READ COMMITTED 트랜잭션을 시작합니다.
2. 신뢰된 수집 증거에서 부재까지 포함한 완전하고 제한된 잠금 대상을 도출합니다. 중복을 제거하고
   순서를 고정하며 호출자가 고른 일부 대상만 받아서는 안 됩니다.
3. 모든 공유 잠금을 시도합니다. **하나라도 false면 전체 트랜잭션을 롤백**해 앞서 얻은 잠금도
   해제하고, 실패한 트랜잭션 밖에서 제한된 수집 재시도나 실패를 기록합니다.
4. 모든 잠금을 얻은 뒤 후속 SQL 문에서 정규화된 권위 기록을 읽고 정확한 scope·전체 해시·
   종결 이력·소유권·가용성·만료·예상 관측을 독립적으로 다시 검사합니다. 잠금 성공은 검증 성공이 아닙니다.
5. 검증된 스냅샷과 필요한 작업·fence 상태를 원자적으로 발행하고 커밋합니다. 불일치나 오류면
   롤백하며 잠금 없는 발행으로 전환하지 않습니다.

관측자가 대기하지 않으므로 기존 쓰기의 행·자원 잠금 순서와 새로운 순환 대기를 만들지 않습니다.
잠금 전에 만들어진 repeatable-read 스냅샷은 이미 커밋된 변경을 숨길 수 있어 거절합니다.
Autocommit 호출은 즉시 잠금이 풀리므로 이 프로토콜이 아닙니다. 별도 연결에서 조회하거나,
외부 파일·네트워크 I/O 중 잠금을 유지하거나, savepoint로 일부 잠금을 남기거나, false 이후
계속 발행하는 것도 허용되지 않습니다. 기존 쓰기의 일반적인 DB 경합·교착 오류가 없어지는 것은 아닙니다.

이는 필요한 통합 계약이며 **아직 실제 스냅샷 발행기에 연결되지 않았습니다**. 기존 두 번 읽기
수집은 그대로이며 원자성을 주장하지 않습니다. 전체 관측 비교, 잠금 예산·재시도·기한,
현재 마이그레이션 검증, 전용 worker 역할과 실제 봉인 저장이 남았습니다. 새 API·호출자 권한·
평가 결과·승인을 제공하지 않습니다.

## 검증과 한계

실제 PostgreSQL 테스트는 타이머만으로 순서를 추정하지 않고 `pg_blocking_pids`와 advisory 대기를
확인합니다. 부재 생성·활성화·삭제 표식·최종 삭제·소유권 추가, 어댑터와 SQL을 통한 철회·대체,
쓰기 선행 시 즉시 false, 공유 관측, 별개 대상, 트랜잭션 종료, 격리 수준·scope 거절, 기존 역할의
함수 실행 거절, 기존 데이터와 원장을 보존하는 순방향 업그레이드를 검증합니다.

일반 쓰기 경로는 트리거를 생략할 수 없습니다. 관리자가 트리거를 끄거나 복구용 replication
설정·스키마 변경으로 우회하는 행위는 런타임 보호 범위 밖입니다. 복구·마이그레이션은 기존
조정된 유지보수 장벽을 유지해야 합니다. 객체 저장소까지 포함한 전역 동시 스냅샷, 역사적 진실,
측정된 처리량, 운영 준비 완료, 전체 정책 평가나 출시 권한을 증명하지 않습니다.

PostgreSQL 16 근거: [잠금](https://www.postgresql.org/docs/16/explicit-locking.html),
[트리거 실행](https://www.postgresql.org/docs/16/trigger-definition.html).
