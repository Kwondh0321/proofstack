# Workflow 2: 제어 기록 의존 증거 추출

[English](workflow-2-policy-evaluation-control-references.md)

상태: 직접 의존 관계 추출입니다. 재귀 수집이나 정책 평가 체크포인트 완료가 아닙니다.

`enumeratePolicyEvaluationControlReferences`는 [제어 기록 읽기](workflow-2-policy-evaluation-control-record-readers.ko.md)의
관찰 하나를 받아 고정 도메인 검사기로 본문·범위·출처·기록 시각을 재검증하고,
캡처된 전체 기록 SHA-256과 대조한 뒤 참조를 추출합니다. 저장소를 조회하거나 호출자가
선택한 검증기를 사용하지 않습니다.

## 처리하는 기록

| 기록 | 보존하는 직접 의존 증거 |
| --- | --- |
| 비교 정의 | 양쪽 데이터셋·fixture·평가·모델 보증·재현과 내부 계획/결과/대상 참조, 지표의 기준, 미해결 이전 버전 |
| 비교 스냅샷 | 정의·데이터셋, 각 fixture, 가용성과 무관한 아티팩트, 적격성과 무관한 보증 참조, 결과의 평가·기준, 수치 관찰, 재현, 안전 이벤트 선언, 누락된 평가·모델 보증·아티팩트 ID |
| 비교 결과 | 양쪽 스냅샷·정의, 양쪽 아티팩트와 ID, 쌍/단측/무효 사례에 남은 fixture, 주변 분포와 전이의 기준 |
| 릴리스 후보 | 평가·빌드 아티팩트·비교·데이터셋·모델 보증·이전 버전, 런타임 어댑터·프롬프트·도구 아티팩트, 모델 선언과 정확한 버전 해석 근거, 코드 출처 선언·대상 릴리스 |
| 릴리스 정책 | 지지 근거·반대 근거의 출처와 검토, 설치 바인딩·이전 버전, 각 규칙의 출처와 비교/평가 참조, 미해결 아티팩트·승인 요건 |
| 설치 바인딩 | 권한 근거 아티팩트 |

명시된 스키마 필드 순서와 배열의 숫자 순서를 따르며 각 출현과 JSON 포인터를 보존합니다.
중복 별칭, 실패·부적격 증거, 선택적 평가 누락, 폐기된 아티팩트, 무효 비교 사례를 제거하지
않습니다. 집계 수치, 집단·지표·역할 선택자, 설명·한계·누락 이유·정책 적용 조건은 부모 해시에
결속되며 외부 기록으로 꾸며내지 않습니다. 트레이스 히스토그램은 정확한 이벤트 목록이 아닙니다.

## 미해결 선언과 권한의 구분

새 `control_declaration` 출현은 소유 도메인의 엄격한 계약으로 다음 일곱 종류를 검사합니다.

- `comparison_predecessor`: 버전 ID·해시만 보존합니다. 빠진 논리 비교 ID를 부모에서 추정하지
  않으며 정확한 해석과 같은 비교 계보인지는 이후에 검증해야 합니다.
- `artifact_identity`: ID만 있는 출현을 보존합니다. 해시·바이트·가용성을 만들어내지 않습니다.
- `safety_event`: 이벤트·출처 ID, 출처 해시, 종류와 시각을 보존하되 권위 있는 저장소나 실제
  발생 사실을 확정하지 않습니다.
- `model_declaration`: 공급자와 정확한 버전/별칭 주장을 보존합니다. 정확한 버전 해석의
  아티팩트도 별도 출현으로 추출하지만 선언·참조만으로 실제 바이트를 검증하지 못합니다.
- `candidate_source`: Git 저장소·커밋·트리 주장을 보존하되 네트워크 접근이나 해당 출처의
  체크아웃·빌드 사실을 승인 또는 증명하지 않습니다.
- `artifact_requirement`, `approval_requirement`: 후보 아티팩트 해석과 검토자·정족수 요건을
  보존합니다. 충족된 요건이나 승인 기록이 아닙니다.

이는 출현 형태의 추가이며 매니페스트 출처는 기존 44종 그대로입니다. 선언으로 자격증명,
실행·발행·설치·릴리스 권한을 부여하지 않습니다.

## 충돌·한도·재검사

모든 출현은 개수와 전체 canonical UTF-8 바이트 한도를 소비합니다. 정확한 한도는 허용하지만
초과하면 부분 목록 없이 오류를 반환합니다. 부모별 한도이며 전체 그래프·조회·시간·워커
한도는 아닙니다. 반환 값은 방어적으로 복사합니다.

동일 식별자의 정확한 참조가 충돌하면 거부합니다. 기존 설명용 비교 벡터는 아티팩트 ID 하나에
서로 다른 해시 두 개를 담습니다. 설명용 기록으로는 유효하지만 정책 수집용으로 일관된 정확한
아티팩트 목록을 제공하지 못하므로 거부 사례로 유지합니다. 정규화·중복 제거로 충돌을 숨기지
않으며, 같은 ID·같은 콘텐츠의 별도 fixture로 성공 경로를 확인합니다. 같은 선언의 반복은
보존하지만 같은 이전 버전 ID나 안전 이벤트 ID의 서로 다른 주장은 거부합니다.
부분 참조와 완전한 참조의 대조 및 부모 간 충돌 검사는 전체 그래프 수집 단계에 남아 있습니다.

본문·범위·출처·시간 바꿔치기, 기록 시각만의 변경, 부재·미검증 관찰, 캡처 해시 불일치를
거부합니다. 기록 접근 전에 입력을 고정하고 본문은 한 번 읽습니다. 예상 밖 실패는 타입이
명시된 오류이지 성공한 빈 목록이 아닙니다. 인가된 수집 출처, 저장소 완전성, 비교 재계산,
정책 효력, 재귀 완전성, 실제 바이트나 봉인을 증명하지 않습니다.

## 검증과 다음 작업

도메인 fixture, 실제 메모리 저장소·운영자 바인딩 해석기, 별도 재귀 구조 검사 및 정렬된 JSON
해시·바이트 계산으로 대조합니다. 검사기는 필드 모양이 같은 결과 ID·정책 ID를 소유 필드로
구별합니다. 여섯 기록·일곱 선언, 모든 정책 술어 분기, 기준을 가진 두 지표, 모든 스냅샷
누락 종류, 단측·무효 사례, 아티팩트 가용성 형태, 별칭·이전 버전·반복 출처, 10개가 넘는 배열,
정확한 한도·초과·충돌·바꿔치기·변경·오류를 검사합니다.

이 경계로 기록 읽기와 직접 참조 열거는 각각 **44종 중 41종**이 됩니다. 후속
[런타임 정의 경계](workflow-2-policy-evaluation-runtime-definitions.ko.md)가 남은 세 종류를 추가해
두 목록 모두 **44종 중 44종**입니다. 이 수치는 단계 완료율이 아닙니다. 재귀 자식 수집, 선택자 해소,
보관 바이트 검증, 전역 완전성·충돌·한도, 권한·수명주기 리비전 검사, 스냅샷 봉인, 결정론적
규칙과 영속 워커·API·SDK 통합, 실제 서비스 인수 검증은
[체크포인트 진입 검토](workflow-2-policy-evaluation-entry-audit.ko.md)의 필수 미완료 작업입니다.
