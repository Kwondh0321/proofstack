# 아티팩트 시각 무결성 감사

[English](artifact-timestamp-integrity-audit.md) |
[한국어](artifact-timestamp-integrity-audit.ko.md)

상태: **수정 구현됨. 실제 DB 및 네이티브 복구 회귀 검사 통과**.
전체 저장소와 정확한 커밋의 원격 승인 검사는 별도 배포 관문입니다.
검사 기준 커밋: `d4b375fcc56413cad2cca1ca76d99a3bf0a576fc`.
이 발견 사항은 카탈로그 재검사를 정확한 DB 관측 시점으로 취급하기 전에 해결해야 합니다.
Workflow 2의 세 번째 체크포인트 완료나 새로운 완료 항목을 뜻하지 않습니다.

## 관찰한 실패

검사 기준 커밋의 공개 예약 유스케이스는 아래 만료 시각을 허용합니다. 암호화 계획은 원래 보존 시각 문자열을
인증 데이터에 포함하지만, PostgreSQL 카탈로그는 `timestamptz`로 저장한 뒤
`to_char(..., 'YYYY-MM-DD"T"HH24:MI:SS.MS"Z"')`로 조회합니다. 반환 문자열이 데이터 키를
감쌀 때 사용한 문자열과 달라질 수 있습니다.

| 허용된 예약 만료 시각 | 카탈로그 반환값 | 저장된 계획으로 암호화 |
| --- | --- | --- |
| `2026-09-28T03:00:00.000Z` | `2026-09-28T03:00:00.000Z` | 성공, 원본 바이트 복호화 성공 |
| `2026-09-28T03:00:00Z` | `2026-09-28T03:00:00.000Z` | `ArtifactProtectionError` |
| `2026-09-28T12:00:00.000+09:00` | `2026-09-28T03:00:00.000Z` | `ArtifactProtectionError` |
| `2026-09-28T03:00:00.000001Z` | `2026-09-28T03:00:00.000Z` | `ArtifactProtectionError`, 보존된 시각 자체도 달라짐 |

별도 실제 어댑터 사례에서는 유효한 콘텐츠를 예약·암호화하고
`2026-08-28T03:01:00.000001Z`에 활성화했습니다. 정책 평가 시각이
`2026-08-28T03:01:00.000Z`이면 `not_yet_available`이어야 하지만 실제로는 `verified`를
반환했습니다. DB 조회가 1마이크로초 차이를 제거한 뒤 도메인 검사로 전달하기 때문입니다.
도메인의 정확한 비교만으로 어댑터에서 이미 사라진 정밀도를 복구할 수는 없습니다.

격리된 UTF-8 PostgreSQL 16 클러스터와 고유 테스트 테넌트에서 기존 예약·카탈로그·키링·암호화·
정책 아티팩트 읽기 코드를 실행해 얻은 결과입니다. 진단 과정에서 운영 DB, 기존 암호문,
마이그레이션, 런타임 암호화 형식을 변경하지 않았고 테스트 서버는 종료했습니다.

## 재현과 검증 범위

[`postgres-artifact-catalog-repository.integration.test.ts`](../../packages/postgres/src/postgres-artifact-catalog-repository.integration.test.ts)의
`artifact timestamp integrity` 그룹으로 재현합니다.

```sh
# PROOFSTACK_TEST_DATABASE_URL은 격리된 일회용 통합 테스트 DB여야 합니다.
pnpm --filter @proofstack/postgres exec vitest run \
  --config vitest.integration.config.ts \
  src/postgres-artifact-catalog-repository.integration.test.ts \
  -t 'artifact timestamp integrity'
```

수정 전 **선택된 6개 테스트 중 1개 통과, 5개 실패**를 확인했습니다. 기존 8개 사례는 명시적인
이름 필터 때문에 이번 실행에서만 제외됐으며 삭제·비활성화하지 않았습니다. 암호화 실패 3개,
만료 시각 보존 실패 1개, 평가 시점 오판정 1개를 검출한 것이지 결함 해결의 증거가 아닙니다.
추가한 테스트 코드는 TypeScript 검사를 통과했습니다.

기준 커밋의 기존 저장소·원격 승인 검사는 이 사례를 추가하기 전에 통과했습니다. 그 결과가
새로 재현한 결함까지 검증하거나 무효화하지는 않습니다. 통과를 위해 단언을 약화하거나 통합
테스트에서 사례를 제외하지 말고, 문제가 남은 작업 트리를 전체 통과로 보고하지 않습니다.

## 수정 및 호환성 검토 완료 조건

다음은 수정의 승인 범위를 정의하는 완료 조건입니다.

1. 지원하는 시각 표현에서 예약·저장·새 연결 조회·암호화·복호화 사이의 인증된 보존 의미를
   유지합니다. 기존 인증 데이터 형식을 제자리에서 바꾸거나 키 검증 불일치를 무시하지 않습니다.
2. 정책 수집에 필요한 정확한 시각을 유지합니다. 평가 시점 이후의 활성화가 문자열 변환으로
   적격이 되어서는 안 됩니다. 영수증 순서·만료 경계의 동일 시각·생명주기 조회에도 같은 지원
   정밀도 계약을 적용합니다.
3. `artifactReservationIdentity`, 새 예약의 만료 검사, 메모리 어댑터의 비교, PostgreSQL
   투영과 유지보수 조회를 함께 검토합니다. 서로 다른 서브밀리초 만료를 같은 예약으로 간주하지
   않습니다.
4. 원래 인증된 문자열, 정확한 의미 시각, DB 스케줄링·인덱스용 투영을 구분합니다.
   PostgreSQL 16의 마이크로초 해상도와 입력 시간대 문자열 비보존 때문에 `timestamptz`만으로
   원래 표현·더 높은 정밀도를 모두 보존할 수 없습니다. 파생된 투영으로 정확한 만료보다 먼저
   콘텐츠를 폐기해서는 안 됩니다.
5. 저장 표현을 변경한다면 일관된 타입 투영·제한된 검증·불변성·테넌트 격리·출처 잠금·복구 ACL
   검증을 갖춘 전진 마이그레이션을 사용합니다. 이미 적용된 마이그레이션을 고치거나 런타임
   보호를 해제해서 통과시키지 않습니다.
6. 기존 유효한 암호문과 정규 UTC 밀리초 기록의 호환성을 입증합니다. 현재 열만으로 원래
   오프셋·생략된 소수부·사라진 소수 자릿수를 유일하게 복원할 수는 없습니다. 기존 손상 기록을
   복구했다고 꾸미지 말고, 필요한 운영자 복구·재수집을 별도로 식별하고 문서화합니다.
7. 집중 회귀 검사, 실제 어댑터·유지보수, 마이그레이션·복구·격리, 전체 저장소 검사 및 정확한
   커밋의 원격 CI/Security를 재검증한 뒤 보호된 정책 발행을 연결합니다. 순수 검사 함수나 DB
   잠금 자체는 이 문제의 수정이 아닙니다.

## 전진 수정과 지원 정밀도

`0051_artifact_timestamp_integrity`는 기존 `expires_at` 타입 투영과 별도로 원래 문자열
`expires_at_lexical` 및 정확한 `numeric(50, 0)` 시각 키를 저장합니다. 키는 초당 10^30 단위로
정수 초와 허용된 소수 자릿수를 모두 반영합니다. 고정 검색 경로의 비공개 트리거가 투영의
일치성을 검사하고 키를 계산하며 두 불변 필드의 후속 변경을 거절합니다. **새 만료 기록에는
원래 문자열이 필수**입니다. 이를 보내지 않는 구버전 작성자는 다른 암호화 문맥을 만들지 않고
거절됩니다.

예약 동일성·만료 검사, 메모리 어댑터와 PostgreSQL 만료 조회가 정확한 시각 비교를 사용합니다.
표현만 다른 같은 시각은 최초 기록과 암호화 계획을 재사용하고, 소수부가 다른 시각은 충돌입니다.
유지보수는 반올림된 DB 시각이 아닌 정확한 키를 사용하며, 생성보다 10^-30초 늦은 만료도
조기 폐기하지 않습니다. 공통 아티팩트 스키마에서 시각 범위와 정확한 생명주기 순서를 검사하고,
정책 읽기는 중복 검사 대신 이 검증을 공유합니다.

보존 시각은 양의 4자리 ISO 연도, `Z` 또는 `+/-15:59` 이내 오프셋, 최대 30자리 소수부를
허용합니다. 네이티브 생성·활성화·tombstone 시각은 조회 시 마이크로초를 보존하며, 그보다
정밀한 값을 요구하는 어댑터 쓰기는 DB 접근 전에 거절합니다. 손실 없는 기존 밀리초 표기는
그대로 유지합니다. 폐기 영수증은 기존의 정규 UTC 밀리초 계약을 유지합니다. 서버 시계 출력은
계속 UTC 밀리초이며 이번 수정이 시계의 실제 측정 정밀도를 높이지는 않습니다.

마이그레이션은 커밋까지 카탈로그의 배타적 DDL 잠금을 유지합니다. 기존 데이터 보완 중에는
기존 전진 생명주기 보호 트리거만 잠시 중지하고, 출처 잠금은 유지하며, 같은 트랜잭션에서
보호 트리거를 재활성화합니다. 실패하면 스키마·데이터·트리거 상태를 함께 롤백합니다.
새 트리거는 `SECURITY DEFINER`가 아닌 비공개 함수이며 `--no-acl` 복구 후를 포함한 런타임
역할 재설정의 권한 회수 목록에 등록합니다.

## 업그레이드와 복구 한계

구버전 작성자를 중지하고 기존 절차에 따라 DB·오브젝트·키를 함께 백업한 뒤, 마이그레이션
계정으로 전진 마이그레이션을 적용하고 대응하는 새 앱 버전과 준비 상태 검사를 실행합니다.
구버전은 원래 문자열을 보내지 않고 정밀 영수증을 읽지 않으므로 혼합 버전 쓰기를 지원한다고
주장하지 않습니다. DDL·데이터 보완은 카탈로그 작업을 막을 수 있어 실제 데이터 규모에 맞는
배포 시간을 확보해야 합니다.

기존 데이터 보완은 DB에 남아 있는 네이티브 시각만으로 정규 문자열을 만듭니다. 기존의 정상
UTC 밀리초 암호문과 무기한 보존 암호문은 암호화 봉투·오브젝트 재작성 없이 호환됩니다.
이미 사라진 표기·소수 자릿수는 유일하게 복원할 수 없습니다. 따라서 과거 오프셋·소수부 생략
기록의 인증 실패가 업그레이드 후에도 남을 수 있으며, 회귀 검사는 검증 우회 대신 이 실패를
보존합니다. 복구에는 신뢰할 수 있는 원래 메타데이터와 키·오브젝트 또는 새 ID를 이용한
승인된 재수집이 필요합니다. 불변 기록을 덮어쓰거나 시각을 추측하거나 인증을 우회하지 않습니다.
자동으로 과거 손상 기록을 살리는 기능은 포함하지 않습니다.

영구 회귀 검사는 실제 카탈로그 통합 그룹,
[전진 마이그레이션 검사](../../packages/postgres/src/artifact-timestamp-migration.integration.test.ts),
공통 스키마·예약·유지보수 검사와
[조정된 복구 리허설](../../services/recovery/src/postgres-recovery.integration.test.ts)에 있습니다.
복구 리허설은 30자리 소수부와 오프셋이 있는 암호문에 대해 복구된 메타데이터·복호화·트리거의
비공개 권한을 확인합니다. 실제 배포 커밋에서 통과해야 하며, 테스트 코드의 존재만으로 승인하지
않습니다.

로컬 수정 증거: 새 UTF-8 PostgreSQL 16.15 클러스터에서 PostgreSQL 패키지 통합 검사
34개 파일의 **263/263** 사례가 통과했습니다. 별도의 네이티브 사용자 지정 형식
`--no-owner --no-acl` 백업·복구에서 카탈로그 **43개** 행이 정확하게 보존됐고, 역할 재설정 후
플랫폼 함수의 PUBLIC 실행 권한과 관리 대상 역할 10개의 새 트리거 실행 권한은 모두 0입니다.
복구된 아티팩트 역할로 조회한 기록은 30자리 만료 시각을 그대로 유지했고, 복구된 암호화
계획으로 원래 평문을 복호화했습니다. 이 로컬 검사는 제공한 키와 메모리의 바이트를 사용했으며,
전체 S3·키 백업 복구 리허설이나 배포된 DB의 검증은 아닙니다. 각 실행 후 테스트 서버를 종료했습니다.

PostgreSQL 참고: [시각 타입과 정밀도](https://www.postgresql.org/docs/16/datatype-datetime.html),
[출력 형식](https://www.postgresql.org/docs/16/functions-formatting.html).
