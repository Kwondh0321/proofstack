# 수집한 평가 스냅샷의 연결 검사

[English](workflow-2-policy-evaluation-snapshot-bindings.md) | [한국어](workflow-2-policy-evaluation-snapshot-bindings.ko.md)

상태: 기록 그래프 수집에서 실행 결과·집계·평가 기록의 보존된 관계를 검사합니다. 전체 의미 관계,
출처 권한, 동시 변경 방어를 거친 봉인과 Workflow 2 세 번째 체크포인트는 미완료입니다.
검사 과정에서 평가기·오라클·재현 대상을 실행하지 않습니다.

## 개별 기록과 관계의 무결성

정확한 참조와 전체 기록 해시가 유효해도 기록끼리 모순될 수 있습니다. 관측이 선언되지 않은
시도를 가리키거나, 결과가 관측을 누락하거나, 집계가 같은 사례를 중복 계산하거나, 평가 기록이
실제 정책보다 유리한 커버리지를 표시할 수 있습니다.

그래프의 `evaluationSnapshots`는 같은 호출에서 이미 수집한 기록과 부모에 결속된 간선을
사용합니다. 임의의 그래프를 받아 승인하는 공개 API로 노출하지 않습니다. 저장소 추가 조회,
최신 별칭, 관측 교체, 통계 방법 교체나 분모 축소를 하지 않습니다.

## 기존 도메인 규칙의 재사용

| 검사 | 범위 |
| --- | --- |
| `run_history` | `EvaluationRunSnapshotSchema`: 정확한 실행·관측 이력, 연속된 사전 선언 시도, 예산·시간 순서·재시도 오류·종료 사유·최종 판정 |
| `aggregate_snapshot` | `EvaluationAggregateSnapshotSchema`: 정책·실행·결과·기준·데이터셋 참조, 구성원 판정, 중복 사례, 시간 순서, 방법·보존 구간의 메타데이터 |
| `assessment_snapshot` | `AssessmentSnapshotSchema`: 정확한 집계와 모든 실행·관측 목록, 자격·검토 참조, 위험 등급·독립 그룹 선언·커버리지·통계 가정 차원 |
| `aggregate_history` | 집계 자체와 각 구성원 실행 이력의 전제 검사; 다른 구성원이 누락되어도 확인된 모순은 유지 |

각 실행 결과에는 이력 검사가, 집계에는 자체 검사와 구성원별 이력 검사가 있습니다. 평가 기록은
자체 검사와 집계 이력의 전제 검사를 보존합니다. 일부 관계가 일치한다고 이전 모순이 사라지지
않습니다. 모순 요약이 이미 결정되어도 개별 누락·모순 보고서는 그대로 남습니다.

전체 입력이 필요한 도메인 검사에서 기록이 빠지면 `unavailable`입니다. 빠진 구성원을 제외해
성공한 작은 스냅샷을 만들지 않습니다. 잘못된 기록·미래 기록의 원래 사유는 그래프에 남으며
단순 누락으로 바꾸지 않습니다. 읽지 못한 부모는 `unavailableParents`에 따로 기록합니다.
저장소 오류가 나면 부분 성공을 반환하지 않습니다.

## 출처·순서·작업량 제한

각 보고서는 정확한 출처, 원래 전체 `recordSha256`, 순서가 있는 검사와 그래프의
`dependencyEdgeIndexes`를 보존합니다. 간선에는 부모 해시·JSON 포인터·자식 참조·선택자 실패가
남습니다. 평가 기록의 중첩 검사에 사용한 집계 간선도 원래 부모를 유지합니다. ID만 있는 실행
선택자가 해결되지 않으면 그 간선을 그대로 남기고 해시나 누락 노드를 만들지 않습니다.
내부 간선 불일치는 수집 오류로 처리합니다.

실행 결과 → 집계 → 평가 기록 순으로 검사하며 각 그룹은 출처 키 순서로 정렬합니다. 입력과
출력은 분리되어 있고 같은 수집 그래프의 노드 삽입 순서를 바꿔도 보고서는 동일합니다.

`inspectionUsage`는 전체 검사에 사용한 의존 참조 횟수와 canonical 바이트를 셉니다. 이 별도의
메모리 내 검사 계수에도 요청의 수집 참조·바이트 상한을 적용합니다. 같은 집계를 여러 평가가
재검사하면 중첩 입력도 매번 **스키마 파싱 전에** 다시 계수합니다. 경계값은 허용하고 초과 시
부분 보고서 없이 실패합니다. 공유 수집 계수를 초기화하거나 외부 전송·영속 재시도 비용까지
측정한다고 주장하지 않습니다.

## 검증과 남은 한계

실제 메모리 저장소에 시간 순서·서로 다른 사례가 맞는 기록을 게시한 뒤, 개별 해시는 유효하지만
관계가 틀린 반례를 검사합니다. 시도 바꿔치기, 예산·시각·판정 불일치, 관측 누락, 잘못된 종료,
사례 중복, 데이터셋·구간 메타데이터, 평가 구성원·커버리지 불일치를 다룹니다. 누락·오염·미래
기록, 누락과 모순의 공존, 조회 횟수·해시·입력 분리·순서·반복 작업 한도·내부 출처 오류·저장소
장애도 확인합니다.

관계 일치는 평가기·오라클의 실행 정확성, 값의 사실성, 통계 가정의 타당성, 구간 경계값의 독립
재계산이나 검토자·독립성·출처 선언의 권한 증명이 아닙니다. 실행과 기준·평가기·자격의 연결,
모델·사람 평가 관계, 아티팩트 귀속·내용, 변경 가능한 권한·동시 변경 방어가 별도로 필요합니다.
기존 데이터셋·재현·비교·트레이스·아티팩트 보고서를 단일 스냅샷 일치로 대체하지 않습니다.
봉인·결정론적 정책 결과·영속 작업·API/SDK·종단간 검증은 남아 있습니다. Workflow 2 완료
체크포인트는 **2/7**입니다.
