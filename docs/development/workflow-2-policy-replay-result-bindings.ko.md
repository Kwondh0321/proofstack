# 수집한 재현 결과의 계획 연결 검사

[English](workflow-2-policy-replay-result-bindings.md) | [한국어](workflow-2-policy-replay-result-bindings.ko.md)

상태: 기록 그래프 수집에서 보존된 실행 이력의 일관성을 제한된 범위로 검사합니다. 전체 의미 관계,
설치·실행 권한, 봉인된 스냅샷과 Workflow 2 세 번째 체크포인트는 미완료입니다. 재현 작업을 실행하거나
수정하지 않습니다.

## 기록 무결성과 실행 의미의 분리

[정확한 재현 결과 읽기](workflow-2-policy-evaluation-replay-result-reader.ko.md)는 전체 보존 이력,
성공한 최종 출처, 범위, 접수 시각, 행·바이트 한도와 스키마 수준의 식별자·fence·회계 관계를
검사합니다. 시도가 가리키는 계획의 실제 정의와 런타임·격리·실행 대상이 같은지는 별도 문제입니다.
프로필이 바뀌어도 전체 기록 해시는 유효할 수 있습니다.

`@proofstack/replay`의 `inspectPolicyEvaluationReplayResultBindings`는 검증된 결과 관측과 정확한
계획 관측을 받아 고정된 도메인 검사기로 원래 전체 해시에 재결속합니다. 읽기 객체는 세 개의
열거 가능한 값 속성만 허용하며 getter·숨은 필드·추가 필드·누락을 거절합니다. 계획 출처는 작업의
계획과 정확히 같아야 하며, 사용 불가 계획은 null 본문과 원래 사유를 보존합니다. 잘못되거나 바뀐
증거는 부분 성공 없이 실패합니다.
제공된 누락 관측은 신뢰된 수집 경로의 출처 정보이지, 공개 호출자가 저장소 조회나 기록 부재를
증명하는 수단이 아닙니다.

결과 읽기의 행·바이트 한도를 먼저 적용하며 출력은 허용된 이력 행당 고정 개수의 검사로 제한됩니다.
결과마다 계획과 한 쌍으로 재검사하므로 공유 계획을 전체 호출에서 한 번만 검사한다고 주장하지
않습니다. 별도의 I/O·영속 재시도 계측이 아니며 전체 요청의 수집 한도를 초기화하지 않습니다.

## 검사와 출처

출력에는 원래 결과의 `source`·`recordSha256`, 정확한 `plan.source`·`recordObservation`, 순서가
고정된 `checks`가 있습니다. 각 검사는 종류·보존 이력의 JSON 포인터와 일치·불일치·확인 불가를
보존합니다.

| 검사 | 의미 |
| --- | --- |
| 접수 시각·시도 수 | 계획 보존 뒤 작업 생성, 첫 시도와 작업 시작 시각 일치, 선언한 시도 상한 |
| 모든 시도 | 이전 실패까지 실행 대상·런타임·격리 프로필·워커 프로토콜이 계획과 정확히 일치 |
| 재시도 선언 | 재시도 예약된 실패·만료 기록, 자동 재시도와 오류 종류 선언; 효과 안전성 형식은 기존 스키마가 검사 |
| 재시도 시각 | 일반 실패는 기존 대기·기한 계산, 과거 lease 만료 시각이 없으면 확인 불가 |
| 예산 정책 | 10개 차원 각각의 한도·측정 선언이 계획과 일치 |
| 경계 식별 | 예약 작업·실행 종류와 모드·선택적 사용량 경계가 계획에 존재; 전역 사용량은 허용 |
| 이력 접수 시각 | 같은 fence의 시도 시작·종료 범위, 예약보다 이르지 않은 정산 |
| 성공 결과의 회계 | 미정산 예약·초과 사용을 숨기지 않으며 알 수 없는 사용량을 확인 불가로 유지 |

마지막 성공 시도가 이전 실패를 대체하지 않습니다. 불일치 하나로 다른 실패·누락을 생략하지
않습니다. 계획을 읽을 수 없어도 독립적인 접수·회계 검사는 유지합니다. 반환값은 입력과 분리됩니다.
빈 장부는 보존된 미정산·분쟁이 없다는 뜻이지, 사용량 0의 측정이나 모든 작업의 예산 예약 증명이
아닙니다.

## 만료된 lease의 재시도 시각

참조 메모리 저장소·상태 전이는 이전 만료 시도의 `endedAt`을 새 워커 인수 시점에 기록합니다.
스케줄러가 사용한 과거 lease 만료 시각은 최종 스냅샷에 없습니다. 인수 시각을 실패 시각으로
오인해 대기 시간을 다시 적용하면 정상 재시도를 거절하게 됩니다. 따라서
`lease_expiry_unretained` 사유로 확인 불가를 남기고 만료 시각을 만들지 않습니다. 재시도 선언의
불일치는 독립적으로 남습니다. 일반적인 종료 실패 이력은 기존 `decideReplayRetry` 계산과 다음
시작 시각으로 대기 시간·기한을 확인합니다.

## 수집 경로·검증·남은 한계

`capturePolicyRecordGraph`가 이미 수집한 결과와 계획을 연결합니다. `replayResults.results`에
검사를, `replayResults.unavailableResults`에 읽을 수 없는 결과 출처를 보존합니다. 저장소 추가
조회·워커 변경·자격 증명 조회는 없으며 비교·트레이스·아티팩트 수집에서도 보고서를 유지합니다.
기록 해시와 `/job/plan` 간선이 연결되며 저장소 장애 시 부분 수집을 반환하지 않습니다.

실제 메모리 저장소의 게시·작업·lease 인수·예약·정산·관측·성공 흐름으로 테스트합니다. 개별 기록은
다시 검증되지만 관계가 틀린 경우, 이전 시도 바꿔치기, 누락 사유, 접수 경계, 재시도 시각, 예산과
경계 선언, 미정산·분쟁·초과 사용, 해시 변조와 잘못된 입력·한도를 다룹니다. 그래프 테스트는 실제
완료 작업을 상위 평가 기록에 연결하고 읽기 횟수와 출처를 확인합니다.

선언된 이력 일치는 실행 바이트, 결과 파일의 귀속·내용 의미, 완전한 계측, OS 격리, 런타임 설치,
철회·출처 신뢰·정책 충족을 증명하지 않습니다. 기존 데이터셋·계획·아티팩트 보고서도 유지해야 합니다.
나머지 관계와 변경 가능한 권한·동시 변경 방어 이후 봉인·정책 결과·영속 작업·API/SDK·종단간 검증이
남아 있습니다. Workflow 2 완료 체크포인트는 **2/7**입니다.
