# 제공된 클라이언트에서 원래 정책 증거 읽기

[English](workflow-2-policy-original-client-readers.md) | [한국어](workflow-2-policy-original-client-readers.ko.md)

이 선행 구현은 새 트랜잭션 없이 원래 스냅샷·페이지·결과의 소유 검증을 재사용합니다.
체크포인트 4와 현재 릴리스 권한·결정 게시는 미완료입니다.
[ADR-0048](../architecture/0048-reuse-owning-policy-reads-on-supplied-clients.md)과
[진입 감사](workflow-2-decision-entry-audit.ko.md)의 경계를 유지합니다.

## 원래 증거와 검증

스냅샷 조회는 정확한 원래 요청·작업·스냅샷 바인딩, 정규 헤더, 작업 그래프의 마지막 정규
이력과 outbox 의도를 검사합니다. 페이지 조회도 같은 검증을 수행하고 정확한 원래 페이지를
검사합니다. 잘못된 인덱스는 전송 전에, 루트 밖의 페이지는 콘텐츠 조회 전에 거부합니다.
정확한 루트의 실제 부재만 null이며 누락·변조된 페이지나 잘못된 행 수를 성공으로 바꾸지 않습니다.

평가 결과 조회는 원래 작업 그래프·이력·outbox·봉인·페이지 집합으로 원래 증거를 재계산합니다.
결정한 완료 시도·fence·네이티브 완료 영수증을 보존합니다. 게시 경로와 같은 결과 검증기를
공유하고 호출자 verdict나 최신 평가를 대신 사용하지 않습니다. 없는 작업·결과는 null이며
잘못된 보존 결과·봉인·시도·페이지는 오류입니다.

기존 저장소 조회도 이 함수를 사용합니다. 제공된 클라이언트의 고정 SELECT만 실행하며 연결,
BEGIN·COMMIT·ROLLBACK·release, 파일 읽기 또는 임의 검증 콜백을 추가하지 않습니다.
마이그레이션·역할·권한·경로·외부 의존성도 추가하지 않습니다.

## 현재 권한과 예산

검증된 과거 결과는 현재 릴리스 권한이나 승인이 아닙니다. 철회된 정책을 재활성화하거나
원본의 완전성을 보증하지 않습니다. 향후 고정 서버 합성기가 원래 요청 소유권에서 정확한
참조·페이지를 유도하고 실제 사용자를 인증한 뒤 현재 권한·모든 원본과 부재 가드·마이그레이션·
복구 epoch·실행 한계를 같은 클라이언트에서 원자 커밋까지 유지해야 합니다.

반복 조회를 포함한 원래 전체 행·바이트 예산, 수명, 실패 오염, 롤백, 시작한 작업의 완료 대기는
호출자가 관리합니다. 종료된 읽기 트랜잭션은 게시 권한이 아닙니다. 콘텐츠·키·네트워크
입출력이나 사람의 응답 대기를 이 함수나 향후 가드 안에 숨기지 않습니다.

## 검증 범위

스냅샷 단위 전송 모델은 이력 검증을 건너뛰지 않고 실제 메모리 원본의 정규 이력 헤더·페이지를
반환합니다. 결과 전송 모델은 실제 전이 이력과 롤백 복원을 검사합니다. 변조된 완료 시도는
이력 바인딩에서 먼저 거부되고 원래 완료 시도 검증기의 별도 직접 회귀 검사도 유지합니다.

실제 PostgreSQL 사례는 충돌하는 논리 ID의 세 테넌트 자료를 먼저 모두 게시한 후 각자의
헤더·모든 페이지·재계산 결과를 같은 제어 역할 연결에서 읽습니다. 연결·트랜잭션 ID와
호출자의 저장점을 보존하는지 검사합니다. 로컬 집중 사례와 전체 PostgreSQL 및 정확한 SHA의
CI·서비스·기여자 검증을 구분하며 현재 결정 권한이나 체크포인트 완료를 주장하지 않습니다.
