# 요청에 연결된 정책 증거 기록 그래프

[English](workflow-2-policy-evaluation-record-graph.md) |
[한국어](workflow-2-policy-evaluation-record-graph.ko.md)

상태: 메타데이터 순회 기반 기능. Workflow 2의 세 번째 체크포인트는 아직 미완료입니다.

`@proofstack/policy-evaluation`은 기존 도메인의 고정 조회기, 직접 참조 열거기, 부모에 연결된
선택자 조회기를 조합합니다. core가 datasets/replay를 역으로 참조하지 않도록 별도 비공개
워크스페이스 패키지에 배치했습니다. 근거는
[ADR-0024](../architecture/0024-compose-policy-record-acquisition-above-domain-packages.md)입니다.

## 입력과 책임

`capturePolicyRecordGraph(request, repositories)`는 완전한 불변 `PolicyEvaluationRequest`와
애플리케이션이 제공한 읽기 전용 저장소를 받습니다. I/O 전에 요청 스키마와 범위별 정의 해시를
검증하고 입력을 복사합니다. 호출자는 이미 수집 권한을 확인하고 올바른 범위의 저장소를
제공해야 합니다. 올바른 해시는 인증이나 다른 테넌트를 읽을 권한이 아닙니다.

루트는 요청에 명시된 정확한 릴리스 후보와 정책 두 개뿐입니다. 호출자가 별도 루트, 유리한
검증기, 그래프 또는 성공 판정을 주입할 수 없습니다. 44개 기록 종류를 기존 도메인별 조회기로
연결하며, 새 HTTP API·CLI·공개 SDK·실행 가능한 정책 워커를 제공하는 변경은 아닙니다.

## 순회와 결과

1. 후보와 정책 순서로 시작해 너비 우선으로 순회합니다.
2. 자식을 열거하기 전에 부모의 스키마, 범위, 정확한 참조, 정의 해시, 기준 시각 및 전체 기록
   관측 해시를 기존 조회기로 확인합니다.
3. 모든 참조 발생 위치에 부모 참조·부모 기록 해시·JSON 포인터를 보존합니다. 이미 방문한
   자식을 다시 가리키더라도 그 참조 발생 자체를 삭제하지 않습니다.
4. 기준 선택자, 모델 평가기 선택자, 실행 ID, 부분 비교 선행 참조는 검증된 부모의 정확한
   위치에서 해석합니다. 미리 읽어 검증한 자식은 확장할 때 다시 조회하지 않습니다.
5. 같은 기록 ID는 한 번만 확장합니다. 정상적인 기준/오라클/픽스처 및 모델 프로필/평가기
   역참조를 보존합니다. 같은 기록 ID에 다른 참조가 붙거나 반복 관측의 전체 해시가 달라지면
   실패합니다. 같은 아티팩트 ID의 상충하는 설명도 서로 다른 부모 사이에서 거부합니다.
6. 기록과 manifest 항목은 기존 식별자 키로 정렬하고, 간선은 부모 순회 및 발생 순서를 유지합니다.

`nodes`는 조회 결과와 참조를 담습니다. 누락 또는 사용 불가 기록의 `references`는 `null`이며,
검증된 빈 목록으로 위장하지 않습니다. 반대로 정상 기록이 실제로 참조를 갖지 않을 수는 있습니다.
`entries`는 기록 관측 목록일 뿐, 그대로 봉인에 사용해도 되는 권위 있는 전체 의존관계가 아닙니다.

간선의 `target`은 정확한 자식 참조 또는 `null`입니다. 해석하지 못한 선택자는 누락/사용 불가
사유를 `selectorFailure`로 남기며 해시를 만들어 넣지 않습니다. 아티팩트, 정확한 트레이스 선택자,
프로토콜/프로필 선언, 후보 소스 주장, 승인 요구 등은 미해결 간선으로 보존합니다. 대상 참조가
있어도 실제 자식 기록은 누락될 수 있으므로 `unresolved.records`와 `unresolved.references`를
모두 확인해야 합니다.

두 미해결 수치가 0이더라도 의미적 정합성, 정책 유효성, 권한, 콘텐츠 바이트의 가용성 또는
스냅샷 봉인을 증명하지 않습니다. 모든 부모-자식 관계나 잘못된 의미적 순환을 검증하는 기능도
아닙니다. 전체 스냅샷 수집에는 추가 도메인 검증이 필요합니다.

## 한도와 오류

| 카운터 | 계산 대상 |
| --- | --- |
| `usage.reads` | 누락·반복을 포함한 실제 조회. 두 형식의 픽스처 조회는 2회 |
| `usage.records` | 조회 횟수와 보관된 재현 시도·예산·취소·실행·사용량 이력 행 |
| `usage.bytes` | 공백 없는 JSON 호환 응답의 UTF-8 바이트. 반복 응답과 null도 재계산 |
| `usage.references` | 중복·미해결 선언을 포함한 모든 참조 발생 |
| `usage.referenceBytes` | 참조 항목들의 정규 UTF-8 바이트 합 |

`maxAcquisitionRecords`는 기록 수와 별도의 참조 발생 수를 각각 제한합니다.
`bytes + referenceBytes`는 `maxAcquisitionRecordBytes` 이하여야 합니다. 부모별 및 재현 이력별
한도도 함께 적용합니다. 이 카운터는 한 번의 호출에만 적용되며, 재시도·재시작을 관통하는 작업
전체 예산이나 전송량·프로세스 메모리·아티팩트 바이트 검증을 대신하지 않습니다. 요청의 시도,
기한, 임대, 평가 규칙 및 콘텐츠 한도는 후속 실행 계층에서 구현해야 합니다.

조회 전에 횟수를 예약하고, 의미 검증 및 복사 전에 응답 바이트를 확인합니다. 순환 객체, 과도한
중첩, 비유한 숫자, JSON으로 측정할 수 없는 객체, 접근자, 숨김/심볼 속성, 잘못된 배열을 거부하며
getter를 실행하지 않습니다. 선택적 undefined 속성은 JSON 바이트에 포함하지 않지만, 알 수 없는
필드를 숨기기 위해 도메인 스키마 검증 전에 삭제하지도 않습니다.

그래프 충돌과 한도 오류는 `PolicyRecordGraphError`의 코드·사유·선택적 충돌 식별자로 구별합니다.
기존 검증 오류는 구분해서 유지하고 저장소 오류는 그대로 전달합니다. 실패 시 부분 그래프를
성공으로 반환하지 않습니다. 픽스처의 병렬 조회 중 한쪽이 실패해도 이미 시작한 다른 조회가
끝난 뒤 실패를 전달합니다. 이는 멈춘 저장소 요청을 강제로 취소하거나 기한을 보장하는 기능은
아닙니다.

## 검증과 다음 순서

실제 메모리 평가/모델/사람/비교 저장소, 44개 종류의 라우팅, 두 픽스처 형식, 런타임 카탈로그,
실제로 완료한 메모리 재현 작업을 검증합니다. 순회 순서, 정상 역참조, 입력 복사, 중복 보존,
누락/사용 불가 구별, 부모 사이 충돌, 반복 관측 변경, 정확한 예산 경계, 잘못된 응답, 저장소
실패와 진행 중 조회 정리를 테스트합니다. 운영 배포나 전체 정책 평가 완료를 증명하지는 않습니다.

[수집된 비교 증거 연결](workflow-2-policy-comparison-capture.ko.md)이 전체 비교 선택과 직접
재계산을 추가 조회 없이 연결합니다. 다음은 전체 기록 간 의미 검증, 정확한 트레이스 이벤트와 아티팩트 바이트,
선언·설치·소스 권한과 변경 이력 확인, 수집 경쟁 방어, 전체 의존관계 산출과 스냅샷 봉인,
모든 정책 조건 평가, 권한을 분리한 영속 작업/워커, API/SDK·복구·격리·기여자 종단 간 검증입니다.
릴리스 결정, 예외 승인, 증명 서명, CI 강제 적용은 그 이후 체크포인트입니다.
