# 릴리스 정책의 논리 루트와 원본 게시 의도 무결성

[English](workflow-2-policy-storage-integrity.md) | [한국어](workflow-2-policy-storage-integrity.ko.md)

상태: PostgreSQL 정책 소유 읽기의 무결성 보완입니다. Workflow 2는 여전히
**7개 체크포인트 중 2개 승인** 상태입니다. 결정적 정책 평가, 봉인된 스냅샷,
결과·작업 게시 또는 승인 권한을 완성한 변경은 아닙니다.

## 정확한 저장 루트

선행 버전이 없는 독립 정책 버전도 앞서 게시된 정책과 논리 ID를 공유할 수
있습니다. 논리 리소스가 지정한 원본 루트의 ID와 계보 개수만 검사하면
루트 본문·정규화 투영·원본 게시 의도의 손상을 놓칠 수 있었습니다.

이제 요청 버전과 같은 연결·범위의 소유 검증기로 정확한 저장 루트의
전체 본문과 투영을 검사합니다. 범위, 논리 ID, 스키마, 정확한 버전과
다이제스트가 리소스 결합과 일치해야 합니다. 루트에는 선행 버전이 없으며
루트 자신의 리소스도 같은 버전·다이제스트를 지정해야 합니다. 요청 버전이
루트면 이미 읽은 행을 재사용하고, 별도 루트면 한 번 검사합니다.

저장된 관계를 검증하며 게시 시각으로 최초 게시 순서를 추정하거나 최신
버전을 선택하지 않습니다. 정책 게시 재시도와 새 게시의 읽기 확인도 같은
검사를 사용합니다. 새 생명주기 게시의 대상과 대체 후속 정책도 검사합니다.

## 원본 의도와 권한

요청 정책, 별도 루트, 단건 생명주기 이벤트와 전체 이력의 각 이벤트는
전체 원본 페이로드·스키마·DB 수신 시각이 일치하는 게시 의도를 보존해야
합니다. 기존 고정 상태 함수를 사용하며 누락·충돌·수신 시각 변조는 전체
읽기를 실패시킵니다. 손상된 이벤트를 이력에서 제거하지 않습니다.

기존 정책 작성자 역할과 범위 권한을 사용합니다. 직접 outbox 읽기 권한이나
새 역할·API 권한을 추가하지 않습니다. 전달 시도·게시 상태 같은 가변 메타데이터는
원본 의도와 별개입니다. 같은 의미의 재시도는 원본 행위자·시각·기록을 반환합니다.
이미 저장된 생명주기 이벤트의 재시도에는 대상·후속 정책 재검사를 추가하지 않습니다.

## 범위와 남은 경계

정규화된 테넌트·프로젝트·환경을 먼저 제한하므로 다른 범위의 손상은 부재로
보입니다. supplied-client 읽기는 그 연결의 고정 읽기만 실행합니다. 범위·권한·
guard·트랜잭션·실패 taint·연결 정리는 호출자가 소유합니다.

추가 루트 본문과 내부 의도 쿼리는 현재 외부 획득 계량기에 개별 노출·계량되지
않습니다. 내부 SQL·행·본문·마감 시간의 완전한 제한, 요청 소유 루트 관측,
고아 저장 관계의 부재, 선행 의미와 현재 권한 closure는 남아 있습니다.
초기 registry/resource 조인이 본문을 반환하지 않았다는 사실만으로 모든
자식 소유 저장 관계의 부재를 증명하지 않습니다.

봉인기는 전체 closure를 보존·계량하고 모든 guard를 유지한 같은 열린
트랜잭션에서 스냅샷·작업·fence를 원자적으로 게시해야 합니다. 읽기 또는
guard 해제 후 반환된 재검사 보고서는 나중의 게시 권한이 아닙니다.

실제 격리 PostgreSQL 검사는 루트 본문·투영·registry와 정책/이벤트 원본
의도의 삭제·변조를 다룹니다. 관리자 손상은 테스트 자료에만 적용하며 CHECK를
유지합니다. 기존 정책 작성자 역할의 읽기, 범위 불투명성, 롤백 후 복원,
게시 재시도·새 생명주기 게시 거부와 정상 전달 후 원본 기록 보존을 검증합니다.
