## 분리된 네이티브 자격 증명

[마이그레이션 0068](../../packages/postgres/migrations/0068_release_service_credentials.sql)은 변경 불가
서비스 principal, 전역 고유 정규 prefix, 기존 scrypt 검증자, 명시적인 프로젝트·환경 범위와 원래 DB
생성·만료를 저장합니다. 자격 증명·principal ID는 테넌트 간 충돌할 수 있습니다. 이 프로필의 권한은
`release:decision:publish` 하나이며 사람 승인·설치자·검토자 관리·정책 worker 권한을 주지 않습니다.
워크로드 API 키나 위임 권한을 재사용하지 않고 서비스 토큰 형식·암호 매개변수도 바꾸지 않습니다.

비공개 관리자 함수는 실제 DB 생성·철회 시각을 기록합니다. 동일 생성 의도는 나중 철회까지 포함한
최초 기록을 유지하며 변경 의도는 충돌합니다. 동일 철회는 최초 시각·이유를 유지하고 재활성화하지
않습니다. 신원·검증자·범위·만료 변경과 삭제를 금지합니다. 소유자에게도 테넌트·명시적 프로젝트·환경
강제 RLS가 적용됩니다. 이 신뢰된 관리자 함수 자체가 공개 토큰 발급이나 실제 발급자 인증은 아닙니다.

네이티브 제공자는 기존 서비스 인증기의 고정 조회·최종 확인 포트를 구현합니다. 실제 `pss_v1_` 비밀은
DB 게시 보호 밖에서 기존 scrypt로 검증합니다. 그 후 동일 불변 신원·검증자·전체 권한이 현재 활성인지
다시 확인합니다. 원시 토큰은 저장하지 않습니다. prefix·salt·검증자는 비공개 인증에서만 사용하고
현재 권한 관찰·계량기·공개 출력으로 보내지 않습니다. 오류는 원래 자격 증명 행이나 SQL 원인을 노출하지 않습니다.

기존 런타임 역할과 PUBLIC에는 새 테이블·함수 권한이 없고 재프로비저닝은 복구된 과거 접근 권한도
제거합니다. 비공개 테이블의 PUBLIC 권한도 명시적으로 철회해 상속된 열 접근이 남지 않게 합니다.
테스트 관리자 권한은 실제 런타임 게시 권한이 아닙니다. 전용 인증·게시자 역할과 운영 비밀
프로비저닝은 별도 구현·운영 작업이며 실제 비밀을 예제·소스·채팅에 넣지 않습니다.

## 현재 신원과 유지 중인 보호

제공 클라이언트 재검사는 실제 `authenticateServiceDecisionPublisher`의 비공개 인증 객체를 소비합니다.
호출자 영수증·다른 요청·범위·브라우저 증명은 대체할 수 없습니다. 정확한 READ COMMITTED 문맥을 확인하고
테넌트/자격 증명의 공유 보호를 대기 없이 획득한 뒤, 비밀 없는 원래·현재 상태와 DB 시각을 같은 연결에서
읽습니다. 기존 고정 신원 검사는 소유·현재 범위·권한·생성/인증 순서·철회·만료를 검사합니다.

필수 쓰기 보호는 부재 생성과 철회를 호출자 트랜잭션 종료까지 막습니다. 경합은 전체 실패이며 부분 권한을
반환하지 않습니다. UTC 원문과 문자열 수치 순서 키의 정밀도를 유지하고 원래 인증 시각은 밀리초입니다.
원래 계량기로 행·부재·문맥·보호·시각과 신원 검사를 계산합니다. 정확한 한도는 통과하고 한 단위 부족은
전체 실패하며 잡힌 실패도 같은 계량기를 오염시킵니다.

연결·트랜잭션을 교체하거나 종료하지 않고 보호를 호출자에게 유지합니다. **반환값은 서비스 신원 요소일 뿐
전체 결정 권한이나 재사용 가능한 게시 봉인이 아닙니다.** 모든 보호를 원자적 결정/outbox 쓰기까지
유지해야 하며 보호 중 콘텐츠·키·네트워크·서명 I/O를 실행하지 않습니다.

## 검증과 남은 경계

실제 scrypt와 폐기 가능한 PostgreSQL 16.15 `proofstack_test`에서 비밀 검증·다른 namespace·검증 후
철회·불변 필드·범위 변경·세 테넌트 충돌·소유자 RLS·격리/경합·동일 backend/XID/savepoint·부재 생성/철회
경합을 검사합니다. 단위 검사는 잘못된 원본·확인·검증자 매개변수·현재 상태·만료·예산·잡힌 실패·오류
노출을 따로 검사합니다. 커버리지 기준은 유지합니다.

복구 자료는 활성·철회 자격 증명을 채우고 전체 원본·검증자·비밀 없는 상태를 비교한 뒤 원래 활성 비밀을
검증하고 철회된 비밀을 거부합니다. 복구 테스트에는 기존 identity 워크스페이스만 추가합니다. 원시 서비스 토큰은
백업·저장소 자료·권한 보고서로 옮기지 않습니다.
아키텍처 검사는 이 의존성을 복구 테스트에서만 허용하며 운영 복구 코드의 제한은 유지합니다.

전체 설치·검토자·소스·통제·부재·원래 평가 계보·게시자 독립성·복구 epoch·DB 유효 기간을 전용 역할과
유지 중인 동일 결정/outbox 트랜잭션에 결합해야 합니다. API/OpenAPI/SDK·비공개 CLI·실서비스 기여자
인수·독립 종료 감사 후에만 체크포인트 4를 인수하고, 이후 5–7 및 측정 조건에 따른 5단계를 진행합니다.
