# 정책 계산 완료와 과거 결과의 무결성

Workflow 2 체크포인트 3은 아직 미완료입니다. 이 코어 선행 구현은 논리적인 실행 완료와
원래 봉인 입력에 대한 저장 결과 검증을 다룹니다. 실제 결과 저장·게시, API, 워커 실행은 포함하지 않습니다.

`completePolicyEvaluationJob`은 현재 잠긴 작업의 worker·시도·lease·fence·복구 epoch와
정확한 완료 시점을 확인합니다. 열린 계산 시도가 원래 스냅샷을 유지해야 하며, 봉인
입력에서 도출한 전체 규칙 수만큼 현재 시도의 계산 비용을 먼저 지급해야 합니다.
API 호출자가 일부 규칙 수를 고르는 것은 유효한 실행 계약이 아닙니다.

원본 요청·스냅샷·시도 시작·누적 비용을 보존하면서 같은 시도를 닫고, lease를 제거하며,
불변 결과 참조와 완료 영수증을 연결합니다. 엄격한 `complete` 이력은 원래 fence·결과·
전체 규칙 수를 유지하고, 이력 재검증은 상태 전환을 다시 도출합니다. 정규 terminal
outbox에는 정확한 결과 식별자가 포함됩니다. 논리 전환은 실제 원자 저장을 뜻하지 않습니다.

`validatePolicyEvaluationResultRecord`의 기대 범위·작업·요청·스냅샷·결과·실행 fence·완료
영수증은 권한 있는 소유 작업과 닫힌 시도에서 가져와야 합니다. 호출자의 기대 해시나
결과 자체가 권한을 대신하지 않습니다. 정규 해시와 원래 실행 필드를 확인한 뒤, 완전한
봉인 페이지에서 모든 규칙 근거와 결과 수를 다시 계산합니다. 위조한 근거를 재해시해도 거부합니다.

과거 결과 검증은 오늘의 시간이나 epoch로 기존 영수증을 바꾸거나 lease를 되살리지 않습니다.
실제 게시에는 현재 실행 권한 검증과 결과·시도 종료·작업 완료·정규 intent의 원자 저장이
필요합니다. lease가 제거된 뒤 최종 만료를 확인하려면 DB가 보존한 위조 불가능한 원래
lease 관찰이 필요합니다. 동일 결과 재요청은 원래 영수증을 유지해야 합니다.

PostgreSQL 결과 저장·게시, 메모리 공유 적합성, 전체 작업 비용 계량, 워커·API·SDK,
모든 상태 복구와 독립 종료 감사는 남은 작업입니다. 자세한 경계는
[영문 문서](workflow-2-policy-result-integrity.md)에 있습니다.
