# 워크플로 1 종료 진입 감사

[한국어](workflow-1-exit-entry-audit.ko.md)

- 상태: 독립적인 워크플로 1 종료 검토 진입 승인, 체크포인트는 열려 있음
- 검토일: 2026-09-06
- 의존성: `b5e2dca`까지 승인된 워크플로 1 기능 체크포인트 7개

- 워크플로 2 진입: 차단

## 결정

독립적인 워크플로 1 종료 검토를 시작할 수 있다. 의존성 순서에 따른 모든 기능은 있지만,
승인된 개별 체크포인트 근거만으로 전체 단계를 승인할 수는 없다. 종료 검토는 독립적으로
구현한 부분들이 정직하고 사용 가능하며 테넌트가 격리된 하나의 사고→비교 워크플로를
구성하는지, 예제 전용 어댑터를 프로덕션 조립 경계로 오인하지 않는지 입증해야 한다.

검토는 다음의 정확한 권한 사슬에서 시작한다.

```text
인증된 실패 트레이스
  -> 불변 증거 전용 스냅샷
  -> 보존 안전한 상호작용 캡처
  -> 정확한 기록 경계 재생
  -> 영속적이고 제한된 재생 작업
  -> 자격이 검증된 비모델·모델 보조 평가
  -> 정확한 기준선·후보 비교
  -> 설명 목적 운영자 화면
```

각 화살표는 일반 저장소, API, SDK, 워커, 데이터베이스 역할, 복구, 브라우저 경계에서 정확히
영속화된 소스를 해석해야 한다. 스키마 픽스처, 메모리 전용 흐름, 주입된 합성 해석기, 서로
따로 통과하는 예제, 클라이언트가 작성한 투영은 이 증명을 대신할 수 없다.

종료 검토는 계속 정책과 독립적이다. 증거가 eligible, ineligible, unverifiable,
comparable, partially comparable, incomparable인지 결론 내릴 수 있다. 릴리스 임계값을
고르거나 예외를 승인하거나 에이전트 권한을 부여하거나 후보를 배포하거나 한 사업 목표가
옳다고 결정할 수는 없다. 그 권한은 워크플로 2와 책임 있는 운영자에게 남겨 둔다.

## 진입 교차 검증에서 발견한 항목

초기 교차 계층 검토에서 단계 승인 전에 닫거나 명시적으로 거부해야 할 경계를 발견했다.

1. API 비교 라우트는 서버 측 `ComparisonEvidenceResolver`를 받지만 기본 조립은 의도적으로
   `comparison_source_unavailable`을 반환한다. 승인된 비교 서비스 테스트는 적대적 합성
   해석기를 주입한다. 종료 검토는 저장소 기반 정확 소스 투영을 추가하고 실행해야 하며,
   그렇지 않으면 워크플로 1을 열린 상태로 유지해야 한다.
2. 기존 서비스 예제는 각 체크포인트를 증명하지만, 인증된 실패부터 비교까지 하나의 보존
   그래프를 아직 이루지 않는다. 종료 검토에는 관련 없는 데모의 연속이 아니라 안정적인 ID와
   완전한 재조회를 갖춘 하나의 제한된 참조 흐름이 필요하다.
3. 녹색 단위, PostgreSQL, 복구, 브라우저 스위트는 중요한 국소 불변 조건을 증명하지만,
   전체 그래프가 API·워커 재시작, 소스 사용 불가, 아티팩트 생명주기 변경, 조정된 빈 대상
   복구 후에도 일관된지는 증명하지 않는다.
4. 기준 레코드는 소스, 권위, 적용 가능성, 최신성, 충돌, 자격 검증, 사람 검토 증거를
   보존하지만, 요청자 주장, 검색 스니펫, 오래된 소스, 범위 불일치, 미해결 충돌, 보존하지
   않은 바이트, 자격 없는 검토자만 근거인 경우 보수적으로 실패하는지 단계 감사에서 입증해야
   한다.
5. 기존 가이드는 체크포인트별로 나뉘어 있다. 기여자에게 필요한 서비스, 명령, 예상 출력,
   실패 상태, 정리, 결과가 주장할 수 없는 것을 설명하는 하나의 정확하고 제한되며 재현 가능한
   경로가 필요하다.
6. 자율적인 진실 판별, 프로덕션 준비, 임의 공급자 호환성, 인과적 개선, 승인 또는 릴리스
   권한을 암시하는 오래된 표현이 없는지 공개 문서를 검색해야 한다.

이 항목들은 승인된 한계가 아니라 열린 감사 발견 사항이다. 각각 수정하거나 실행 가능한
근거로 반증하거나, 워크플로 1을 종료할 수 없는 이유로 남겨야 한다.

## 독립 감사 방법

종료 검토는 이전 체크박스 결정과 독립적인 근거를 사용한다.

1. 워크플로 1에서 추가한 모든 공개 계약, API 작업, SDK 메서드, 워커 명령,
   데이터베이스 테이블, 역할 권한, RLS 정책, 복구 투영, 가이드, 예제, 브라우저 라우트를
   목록화한다.
2. 첫 캡처 실패부터 최종 비교 결과까지 정확한 ID, 의미 다이제스트, 범위, 선행 레코드,
   행위자, 시간, 아웃박스 의도를 추적한다.
3. 실제 PostgreSQL 기반 인증 서비스 흐름을 실행하고 적용 가능한 각 프로세스를 중지·재시작한
   뒤 공개 SDK 작업으로 보존된 모든 레코드를 읽는다.
4. API, 재생 워커, 평가 워커, 모델 워커, 사람 검토자, 아티팩트 권한을 분리해 실행한다.
   역할 교차 쓰기, 추측 ID, 충돌하는 테넌트 ID, 누락 범위, 재사용 연결 컨텍스트를 공격한다.
5. 모든 워크플로 1 테이블의 대표 상태로 조정된 빈 대상 복구를 연습하고, 런타임 자격증명을
   복사하지 않은 채 최종 비교와 한계를 재현한다.
6. 적대적 콘텐츠, 보존, 취소, 임대, 재시도, 시간 초과, 공급자 실패, 다이제스트 치환, 생략된
   사례, 사용 불가 사용량, 충돌 기준, 검토자 상관관계, 브라우저 접근성 사례를 실행한다.
7. 지원 런타임과 고정 의존성으로 깨끗한 체크아웃에서 기여자 문서를 따르고, 관찰된 출력을
   모든 공개 주장과 비교한다.
8. 모든 발견 사항을 기록하고 가장 이른 책임 불변 조건에서 수정하며, 집중 근거를 다시
   실행한 뒤에만 전체 로컬·원격 게이트를 실행한다.

## 기준 신뢰 루트 게이트

ProofStack은 잘못된 지시를 그 작성자를 더 강하게 신뢰하는 방식으로 해결할 수 없다. 종료
검토는 다음 계층을 서로 독립적으로 검사 가능하게 유지해야 한다.

| 계층 | 필요한 근거 | 단독으로는 결코 충분하지 않은 것 |
| --- | --- | --- |
| 요청 | 정확한 요청자 ID, 작업, 의도한 모집단, 위험 등급, 선언된 목표 | 기준이 맞다는 요청자의 주장 |
| 탐색 | 질의, 공급자, 시간, 순위가 있는 후보, 정확한 검색 출처 | 검색 순위, 스니펫, 생성 요약, 인기, 모델 답변 하나 |
| 소스 무결성 | 보존 바이트, 정규 URI, 다이제스트, 발행자 주장, 버전, 검색 시각, 라이선스, 가용성 | 소스 ID나 권위 없는 유효 해시 |
| 소스 권위 | 검증된 발행자 ID, 관할권, 범위, 유효 기간, 대체 관계, 충돌, 책임 있는 검토 | 공식처럼 보이는 브랜드나 검토자 직함 |
| 적용 가능성 | 정확한 작업, 환경, 로케일, 모집단, 관할권, 제외 조건, 가정, 안전한 전체 표현식 | 일반적 관련성이나 의미 유사성 |
| 자격 검증 | 비공개 픽스처, 방법 버전, 범위, 실패, 기권, 보정 슬라이스, 실행자 ID | 규칙 작성에 사용한 동일 픽스처 통과 |
| 이의 제기 가능성 | 반대 증거, 소수 의견, 충돌, 비평, 검토자 독립성, 만료, 대체 관계 | 다수결이나 서로 상관된 모델 심사자 |
| 결정 권한 | 워크플로 2에서 별도 권한을 가진 정책과 책임 있는 사람의 승인 | 워크플로 1의 어떤 점수, 평가, 비교 결과 |

필요한 계층이 없거나 오래됐거나 충돌하거나 범위 밖이면 결과는 `unverifiable`,
`require_approval`, `ineligible` 또는 그 밖의 명시적인 사용 불가 상태로 남아야 한다. 검색은
더 나은 후보를 찾을 수 있지만 누락된 권위 계층을 조용히 채울 수 없다.

## 종료 승인 행렬

아래 모든 행이 실행 가능하고 승인될 때까지 마지막 워크플로 1 로드맵 체크박스는 열어 둔다.

| 경계 | 필요한 종료 근거 |
| --- | --- |
| 완전한 계보 | 인증된 실패 트레이스 하나가 정확한 ID와 다이제스트로 불변 카탈로그, 캡처 상호작용, 재생 정의·작업, 관찰, 평가, 비교, 운영자 투영에 도달함 |
| 프로덕션 조립 | 비교 스냅샷이 지원되는 저장소 기반 조립으로 정확히 영속화된 상위 증거를 해석하며 클라이언트 작성 또는 주입 합성 투영은 근거로 세지 않음 |
| 계약 일관성 | 패키지 간 모든 ID, 버전, 다이제스트, 범위, 상태, 생략, 단위, 행위자, 선행 레코드가 일치하고 미지 필드·미래 스키마를 보수적으로 거부함 |
| 권한 | HTTP capability와 최소 권한 DB 역할이 제어, 워커, 검토자, 비교, 읽기 권한의 상호 사칭과 릴리스 허가를 막음 |
| 기준 신뢰 | 요청자 전용, 검색 전용, 오래됨, 사용 불가, 충돌, 범위 불일치, 자격 미검증 기준이 보존된 출처와 함께 서로 다른 보수적 결과를 만듦 |
| 재생 안전 | 증거 전용 입력은 실행할 수 없고 정확한 캡처, 네트워크 대체, 런타임 제어, 예산, 임대, fencing, 재시도, 취소, 부작용, 공급자 모드가 선언한 한계를 유지함 |
| 보존 | 분류 평문이 일반 레코드·화면 밖에 있고 소유권, pin, 내보내기, tombstone, purge receipt, 사용 불가 내용, 복구 사본 의무가 명시적으로 남음 |
| 격리 | 최소 세 테넌트의 동일 ID, 추측 조회, 범위 교차 계보, 역할 치환, 연결 컨텍스트 재사용을 애플리케이션·PostgreSQL 경계에서 거부함 |
| 재시작과 복구 | 전체 그래프와 아웃박스 상태가 프로세스 재시작·조정된 빈 대상 복구를 견디고, 복원 런타임 역할은 새로 구성되며 원본 상태가 변하지 않음 |
| 실패 모드 | 소스 경쟁, 무효 다이제스트, 공급자 사용 불가, 시간 초과, 충돌, 늦은 응답, 부분 범위, 누락 사례, 호환 불가 방법, 적대적 표시 문자열이 안전하고 관찰 가능하게 실패함 |
| 사용성 | 깨끗한 체크아웃용 기여자 경로 하나가 제한되고 문서화되며 재현 가능하고 영어를 기본으로 연결된 한국어 안내가 있으며 예상 성공, 보수적 실패, 정리, 한계를 설명함 |
| 운영자 화면 | 실제 영속 상태가 반응형이고 키보드·화면 낭독기에서 사용 가능하며 제한된 적대적 텍스트에 안전하고 분류 평문·숨겨진 정책·릴리스 제어가 없음 |
| 오픈소스 | 아키텍처, 위협 모델, 운영, 예제, 확장 경계, 테스트 명령, 라이선스, 보안 정책, 기여 절차, 지원하지 않는 주장을 찾을 수 있고 서로 일관됨 |
| 저장소 | 고정 설치, 포맷, 경계, 문서, 린트, 엄격 타입, 커버리지, 빌드, 의존성 감사, 비밀정보 검사, CodeQL, PostgreSQL, S3, 아티팩트, 복구, 완전한 워크플로 1 서비스 게이트가 녹색임 |

## 진입 한계

- 이 문서는 감사를 시작하며 워크플로 1을 승인하지 않는다.
- 이전 체크포인트 승인은 각자 명시한 경계에서 유효하지만, 단순 합산으로 단계 승인을 만들 수
  없다.
- 선택적 3010 포트 비교 실험은 개발 편의 기능이며 종료 근거에서 제외한다. 지원되는 운영자
  표면은 이것 없이 작동해야 한다.
- 합성 픽스처는 결정론적 적대 사례를 구동할 수 있지만, 전체 서비스는 최종 투영을 조작하는
  대신 실제 공개·영속성 경계를 통해 이를 보존해야 한다.
- 성공적인 종료는 참조 사고→비교 워크플로를 승인할 뿐 프로덕션 준비, 보편적 공급자 호환성,
  모델의 진실, 법적 준수, RPO/RTO, 릴리스 집행을 승인하지 않는다.

## 즉시 감사 순서

1. 저장소 기반 비교 증거 투영과 보수적으로 실패하는 소스 해석 행렬을 구현한다.
2. 일반 API, SDK, 워커, 런타임 역할, 재시작, 정확한 재조회 경계를 사용하는 하나의 제한된
   PostgreSQL 기반 워크플로 1 승인 흐름을 만든다.
3. 기준 신뢰 루트 적대적 근거를 추가하고, 사용할 수 없는 권위를 검색, 모델, 요청자 주장이
   숨길 수 없게 한다.
4. 전체 그래프가 드러내는 틈에 맞춰 조정된 복구와 세 테넌트 행렬을 확장한다.
5. 기여자용 실행 가이드 하나를 추가하고 깨끗한 상태에서 독립적으로 따른다.
6. 공개 주장과 브라우저 동작을 감사하고 모든 발견을 닫은 뒤 전체 로컬·원격 게이트를
   실행한다.
7. 그 결과가 모두 녹색인 뒤에만 최종 워크플로 1 감사를 발행하고 워크플로 2 진입을
   검토한다.
