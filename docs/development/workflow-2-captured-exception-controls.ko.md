# 예외 보완 통제의 전체 보존 관측

[English](workflow-2-captured-exception-controls.md) | [한국어](workflow-2-captured-exception-controls.ko.md)

이 구현은 내부 보존 관측 검사이며 체크포인트 4는 미완료입니다.
[ADR-0049](../architecture/0049-inspect-every-captured-exception-control.md)와
[진입 감사](workflow-2-decision-entry-audit.ko.md)의 현재 권한·원자 게시 경계를 유지합니다.

## 모든 원래 참조 보존

원래 정규 예외 승인과 각 관측의 승인 다이제스트·범위·숫자 인덱스·콘텐츠 참조를 검사합니다.
최대 16개를 관측 도착 순서와 무관하게 원래 숫자 순서로 반환합니다. 마지막 관측이 없으면
전체 보고서가 불가용이며 유리한 앞부분만 성공으로 반환하지 않습니다. 추가·중복·외부 범위·
잘못된 관측과 일반 승인을 예외로 바꾸는 입력은 거부합니다.

미검사·검증 실패·불가용 카탈로그·이후 변경·만료를 구분해 보존합니다. 보존 상태가 되려면
앞서 확인한 콘텐츠와 가드 중의 전체 공개 카탈로그 및 원본 행 다이제스트가 일치해야 합니다.
다이제스트만 같다고 변경된 공개 메타데이터를 무시하지 않습니다. 생성·사용 가능·소유권 영수증이
성공했다고 주장한 콘텐츠 관측보다 나중이면 사용할 수 없습니다. 만료는 전체 정밀도 DB cut보다
엄격히 나중이어야 하며 Date로 반올림하지 않습니다. 모두 보존됐을 때 실제 가장 이른 카탈로그
만료만 반환하고 무기한 보존에 임의 만료를 만들지 않습니다.

공개 투영에는 암호화된 비공개 카탈로그 정보가 없으므로 원본 전체 행 해시를 여기서 재계산할
수 없습니다. 실제 아티팩트·네이티브 조회가 원본과 콘텐츠 결과를 검증해야 합니다. 공개된
verified 표시는 그 자체로 콘텐츠·인증·현재 게시 트랜잭션의 증명이 아닙니다.

## 예산과 권한

예산 객체 인스턴스와 엄격한 바깥 필드만 받습니다. 고정 서버 합성기가 원래 요청의 예산을
제공해야 하며 인스턴스 검사가 호출자 인증이나 작업·요청 바인딩을 증명하지는 않습니다.
승인과 각 전체 관측·콘텐츠·가드 중
카탈로그 투영을 같은 예산에 계상하며 반복 검사에 새 예산을 만들지 않습니다. 실제 조회 포트는
실패·폐기·반복·관계 조회를 포함한 모든 실제 시도도 같은 예산에 계상해야 합니다. 이 보존 비용
하한은 전체 입출력 원장이 아닙니다. 정확한 행·바이트·승인 한계는 통과하고 한 단위 부족하면
원래 예산이 실패 상태를 유지합니다. 일반 가짜 예산 콜백은 내부 입력 검사에서 거부하지만
임의의 신뢰된 JavaScript 실행을 막는 인증 경계라는 뜻은 아닙니다.

보존 증거는 통제 효과·정족수·예외 적용·사람의 전문성·릴리스 권한이 아닙니다. 조건과 리뷰
행동도 바꾸지 않으므로 반대 리뷰의 증거가 보존돼도 찬성으로 바꾸지 않습니다. 새 정책 요건,
기본 검토자 권한이나 예외 정족수를 만들지 않습니다. 향후 고정 합성기는 원래 주체·설치 요건·
현재 사용자와 권한·전체 행동과 이력·승인 간 같은 물리 원본의 일관성을 검사하고 필요한 모든
가드를 원자 게시까지 유지해야 합니다. 알 수 없는 증거나 예외 불가 위반을 면제하지 않습니다.

집중 검사는 16개 전체와 마지막 누락, 순서, 미검사·실패·변경·철회·만료, 시간 정밀도, 만료
최솟값, 변조·중복·초과 입력, 가짜 예산, 상충하는 물리 카탈로그, 정확한 한계와 한 단위 부족,
반환 복사를 검사합니다. 기존 일반 승인 정족수 검사도 함께 실행합니다. 실제 OIDC·CSRF와
현재 검토자 권한, 예외 적용, 네이티브 게시 및 체크포인트 종료 검증은 별도 후속 작업입니다.
