## 원래 기록 전체와 재시도

[마이그레이션 0067](../../packages/postgres/migrations/0067_release_approval_storage.sql)은 원래 승인,
정확한 주체의 여섯 참조, 순서 있는 조건·충돌 선언과 보완 통제 참조, 폐기를 다섯 비공개 테이블에
저장합니다. 정규 원본 바이트·해시, 정확한 범위, 지연 완전성·순번·계보 제약과 정규 outbox 의도가
전체 쓰기를 묶습니다. 선행 행동에는 후속 하나와 폐기 하나만 허용합니다. 소유자에게도 강제 RLS와
추가 전용 보호를 적용합니다. 상위 참조 보존은 소유 기록의 존재나 현재 권한을 증명하지 않습니다.

[어댑터](../../packages/postgres/src/postgres-release-approval-repository.ts)는 기존 신뢰된 공통 포트를
구현합니다. 정의 해시는 원래 인증·권한·DB 정밀도 시각을 포함하지만, 재시도는 의도와 검토자 principal을
비교해 최초 기록 전체를 반환합니다. 새 로그인·현재 권한 버전·나중 기록 시각이나 폐기는 원래 영수증을
바꾸거나 승인을 되살리지 않습니다. 변경 의도와 다른 검토자는 충돌합니다. 폐기는 원래 참조·동일 검토자·
인과 시각을 먼저 검증하고 동일 의도에 최초 이벤트·로그인을 반환합니다.

## 전체 보호 읽기

제공 클라이언트의 정확한 원본·폐기·종류/전체 주체 읽기는 호출자의 명시적 범위 트랜잭션을 사용합니다.
전체 읽기는 별도 테넌트 승인 공유 보호를 대기 없이 얻은 뒤 비공개 VOLATILE READ COMMITTED 관찰을 합니다.
모든 테이블의 필수 쓰기 보호는 생성·대체·폐기를 호출자 트랜잭션 종료까지 막습니다. 경합은 전체 실패입니다.
이 보호 단위는 처리량 측정 결과가 아닙니다. 기존 C3 보호 영역을 넓히지 않습니다.

16개 고정 키셋 페이지는 승인·반대·에스컬레이션·기권, 원본·후속·폐기를 전부 보존합니다. 일반 승인과
규칙 예외를 구분하며 최신·승인·미만료·충돌 없음 필터를 쓰지 않습니다. 정규 해시와 모든 정규화 필드·참조·
선언·통제·계보·outbox를 검사합니다. 손상은 부재나 유리한 일부 목록이 되지 않습니다.

원래 계량기는 실제 바이트·반복 원본·관계·묶음 메타데이터·페이지·부재를 해석 전에 계산합니다. 승인 관찰은
개별 기록이며 자식 묶음은 메타데이터입니다. 전체 주체 부재는 한 기록을 소비합니다. 정확한 한도는 통과하고
한 단위 부족은 전체 실패하며 잡힌 실패도 같은 계량기를 오염시킵니다. UTC 원문은 소수부 최대 30자리를
유지하고 DB 수치 순서 키는 문자열로 옮깁니다. 원래 OIDC 인증 시각의 밀리초 계약은 그대로입니다.

제공 클라이언트는 연결이나 트랜잭션을 교체·종료하지 않습니다. 편의 저장소는 반환 전에 자체 읽기를
끝냅니다. **반환된 목록은 나중 게시 권한이 아닙니다.** 합성 OIDC 영수증은 실제 사용자 인증이 아닙니다.

## 검증과 남은 일

변경하지 않은 공통 사례를 실제 PostgreSQL에서 실행합니다. 추가 사례는 여러 페이지의 모든 행동,
동일 backend/XID/savepoint, 부재 생성·폐기·대체 경합, 범위·격리·경합, 다섯 비어 있지 않은 테이블의
소유자 RLS, 손상과 지연 순번 제약·전체 롤백을 검사합니다. 실제 합성 PG 16.15 전송 관찰에 기반한
단위 검사는 원본·정규화·계보·의도·예산·최초 영수증·실패·연결 정리를 검사하며 독립 SQL 오라클은 아닙니다.

복구 자료는 선언·예외 통제·폐기를 포함해 다섯 테이블 모두를 채우고 복구 원본·전체 목록·정규 outbox·
최초 재시도를 비교합니다. 기존 역할 재프로비저닝은 과거 비공개 권한도 제거합니다. 폐기 가능한
`proofstack_test`만 사용합니다. 관리자 자료 권한은 실제 런타임 승인 권한이 아닙니다.

새 역할·기본 권한·공개 변경 API·worker·예약을 추가하지 않습니다. 실제 발급자·검토자·게시자 인증과 인가,
전용 역할, 현재 전체 소스·부재, 복구 epoch·DB 유효 기간을 유지 중인 동일 원자적 결정/outbox 트랜잭션에
결합해야 합니다. 제한된 API/SDK·실서비스 기여자 흐름과 독립 종료 감사 후에만 체크포인트 4를 인수합니다.
이후 체크포인트 5–7과 측정 조건에 따른 5단계를 진행합니다.
