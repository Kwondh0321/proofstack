# Original model endpoint resolution

Status: owning retained-data resolver and contextual checks. Workflow 2 remains
**2/7 accepted**; checkpoint 3 is open. [Korean guide](workflow-2-model-endpoint-resolution.ko.md).

A recorded model attempt retains an endpoint profile ID and exact version, but
no endpoint definition digest. The resolver revalidates the complete original
schema-0.2 fixture, its exact source and full observation before selecting the
original `/interactionCapture/interactions/{i}/attempts/{j}/provider` occurrence.
The owning fixture enumerator admits every direct reference and its canonical
bytes against finite limits before any repository I/O. A caller cannot replace
that occurrence with a selector, requested digest or partial parent.

`readPolicyEvaluationModelEndpointResolution` selects independent installation
data by all three scope coordinates, endpoint profile ID and case-sensitive
version. The reader receives no requested digest. The owning profile validator
checks the complete strict body and its semantic digest before the resolver
derives an exact `endpoint_profile` source from that independently valid record.
Original registration receipts remain in the complete observation hash and are
compared with full-precision UTC availability cuts. Parent and child availability
are independently required; a child cannot make a future parent available.

`inspectPolicyEvaluationModelEndpointResolution` performs the same retained-data
and context validation without repository I/O. Both functions retain the original
parent source, full parent hash, hashless selector occurrence and whole-parent
reference/byte admission. Repeated attempts remain separate origins even when
they select the same profile. Caller inputs and reader scope are detached before
awaiting I/O; unexpected storage and validator failures propagate unchanged.

Valid independent data produces `resolved` with its complete record and full
observation. This status does not assert matching model context. Four separate,
ordered checks compare the original provider name, operation membership, model
boundary-kind membership and complete provider-configuration artifact descriptor.
Every configuration field, including optional redaction stage, participates.
All three original model operations are supported without narrowing the profile's
broader live-operation declaration contract.

A valid profile with conflicting context remains resolved retained data and has
an explicit `mismatch` check. Missing independent data produces `missing`; invalid
data, wrong scope/identity/version and registration after the cut produce explicit
`unavailable` reasons. All four contextual checks remain unavailable when no
validated record exists. No expected digest, target record or successful context
is fabricated from absent data. Evidence-only fixtures, non-provider paths and
changed full parent observations fail before the exact read.

Neither `resolved` nor four matched retained declarations prove actual provider
compatibility, requested/returned model identity, registering-principal authority,
current installation authority, content availability or execution/release rights.
The existing profile has no model-identity declaration; this resolver does not
invent one. It does no content, key, credential or network I/O.

Graph acquisition, independent expected-closure derivation, cumulative job-wide
admission and guarded reinspection of these hashless mappings remain separate
work. This resolver exposes per-inspection whole-parent usage so that composition
can charge it without treating repeated work as free. Complete semantic/authority
closure and sealed snapshot/job publication remain open. No source kind, SQL
table, migration, grant, public route, worker or production composition is added.
An ended observation transaction cannot authorize later publication.
