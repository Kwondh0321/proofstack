# 인증된 선택 설치와 수명주기

[English](workflow-2-authenticated-selection-publication.md) |
[한국어](workflow-2-authenticated-selection-publication.ko.md)

상태: 체크포인트 4의 설치 서비스 작업입니다. Workflow 2의 승인 상태는 3/7입니다.

[ADR-0059](../architecture/0059-preserve-authenticated-selection-publications.md)는 실제 인증을
거친 설치와 기존 신뢰된 선언 저장소를 구별합니다. 기존 선택 정의와 0.1 정규 바이트는
보존합니다. 별도 최초 게시 기록이 원본 전체와 비밀정보가 없는 권한·세션 관측의 해시를
연결합니다. 이 기록은 최초 인증 근거이며 현재 결정 권한이나 게시 봉인이 아닙니다.

현재 마이그레이션을 적용하고 `releaseAuthority` 옵션으로 별도 비상속 로그인 역할을
명시적으로 준비합니다. 해당 역할의 `createPolicyPostgresPool`, 실제
`ReleaseMutationAuthenticator`와 `OidcSessionAuthenticator`로
`PostgresReleaseSelectionInstaller`를 구성합니다. 인증 저장소는 별도 권한의 연결을
사용합니다. 소유자·API·정책 작성자·평가 작업자 연결을 설치 연결로 재사용하지 않습니다.
옵션이 없으면 새 역할을 자동으로 부여하지 않습니다. 자격증명은 비밀 설정으로 관리합니다.
각 트랜잭션은 직접·PUBLIC 권한을 확인해 추가 테이블·시퀀스·스키마 권한이나 다른 게시
함수의 실행 권한을 거부합니다. 트리거의 이벤트·조건·열·인수·함수 스키마도 확인합니다.
원래 설정을 복원하면 기록이나 마이그레이션을 고치지 않고 정상 준비 상태로 돌아갑니다.

`publishSelection`은 서버의 범위·발행자·시각을 제외한 선택 의도를,
`publishLifecycle`은 정확한 선택 참조와 철회 또는 후속 버전 교체 의도를 받습니다.
실제 쿠키 소유·CSRF·범위·`release:selection:manage` 검사가 본문 해석보다 먼저입니다.
HTTP Origin 검사는 후속 API 미들웨어의 책임이며 이 내부 서비스 자체는 공개 HTTP 경로가
아닙니다. 호출자가 사용자·시각·완성된 인증 보고서를 제출해 권한을 얻을 수 없습니다.

하나의 제한된 READ COMMITTED 트랜잭션에서 마이그레이션·복구·메타데이터·선택·신원
보호를 유지하고 소유 저장소의 정규화된 전체 관측과 원래 이벤트 의도를 검사합니다.
기존 연결 대기·문장·트랜잭션·통신 한도와 서버 소유 10,000건/16 MiB 누적 한도를
사용합니다. 반복 관측, 전송 조각과 정규화 객체도 계산합니다. 실패하면 원래 계량기를
오염시키고 전체를 롤백하며 내부 자동 재시도나 새 의미 시각을 만들지 않습니다.

마이그레이션 0071의 별도 기록은 최초 원본과 비밀정보가 없는 관측을 보관합니다.
미완성 기록은 같은 백엔드/XID에서만 완성할 수 있고 필수 지연 제약이 미완성 커밋을
차단합니다. 원본·인증 근거·정규 이벤트는 함께 커밋하거나 함께 롤백합니다. 반환은
`created`, 원본 `record`, 간결한 `publication`, 사용량이며 내부 관측이나 비밀정보는
반환하지 않습니다. 같은 요청의 재시도도 현재 인증을 요구하지만 최초 사용자·요청·시각을
보존합니다. 뒤늦은 정책 철회로 과거 게시 기록을 다시 만들지 않습니다.

기존 선언과 철회 이력은 바꾸지 않으며 업그레이드로 인증 근거를 꾸며내지 않습니다.
근거가 없는 과거 버전·대상의 인증된 재사용은 거부하고 새로운 인증된 대상을 사용합니다.
자동 인수·재활성화·기록 삭제는 없습니다. 별도의 복원 검증은 두 원본 종류와 전체 관측·
정규 바이트를 복원하고 역할을 다시 준비한 뒤 실제 쿠키/CSRF 재시도로 최초 기록을 확인합니다.
저장된 최초 복구 세대는 이력이며 복원 후 살아 있는 작업 임대를 보장하지 않습니다.

검증 범위에는 독립 Python 벡터, 기존 선택 벡터, 원본·해시·신원 변조, 조각난 Unicode,
정확한 한도와 초과, 실패 전파, 실제 인증, 재시도, 철회, 동시 요청, 세 테넌트 충돌,
권한 변경과 보호 경합, 이벤트 훼손, 미완성 커밋, 함수·트리거·RLS 변경, 과거 보존과
역할 거부가 포함됩니다. 실제 DB·단위·정확한 SHA의 CI·복원 검증은 각각 구별합니다.

이 작업은 PostgreSQL 설치 서비스와 공유 최초 근거 검증 계약입니다. 메모리 설치 서비스,
공개 API/SDK, 실제 운영 신원 연동이나 체크포인트 4 완료를 뜻하지 않습니다. 후속 검토자
관리·계획·승인·책임 있는 결정·서비스 통합과 독립 종료 감사는
[진입 감사](workflow-2-decision-entry-audit.md)의 순서를 따릅니다.
