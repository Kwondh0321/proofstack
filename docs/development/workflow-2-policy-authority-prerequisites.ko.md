# 보존된 정책 권한의 전제조건

[English](workflow-2-policy-authority-prerequisites.md) | [한국어](workflow-2-policy-authority-prerequisites.ko.md)

상태: 요청에 연결된 정적 권한 전제조건 검사 구현. Workflow 2의 세 번째 체크포인트는 아직
미완료이며 승인된 체크포인트는 **2/7**입니다. 현재 권한 인증서·정책 판정·봉인된 스냅샷·실행
허가·출시 승인을 제공하는 기능이 아닙니다.

## 조립과 출처 보존

`capturePolicyArtifactEvidence`는 기존 그래프·트레이스·아티팩트 관측·픽스처 귀속 결과와 함께
`policyAuthority`를 반환합니다. 고정된 내부 검사기는 같은 호출에서 수집한 정확한 정책 루트,
설치 바인딩, 지지·반대 출처와 검토 기록, 검토자 자격 및 아티팩트 관측만 사용합니다. 저장소
추가 조회·검색·네트워크 수집·대체 출처·호출자가 선택한 판정을 추가하지 않습니다. 패키지 루트에는
결과 타입만 노출하며 임의 그래프를 받는 내부 검사기는 공개하지 않습니다.

정책의 원래 참조·전체 기록 해시·정확한 평가 시각, 의존 간선·아티팩트 관측 인덱스와 누적 검사
사용량을 보존합니다. 정책의 출처 목록과 같은 출처를 사용하는 규칙도 출현마다 검사·계측합니다.
중첩된 출처·검토·자격 증빙은 원래 부모 해시와 JSON 포인터에 연결됩니다. 소유 도메인의 검증기에
전달할 중복을 합치는 작업은 계측 이후에만 수행하며 원래 증거나 반복 사용량을 지우지 않습니다.

권한 증빙에는 설치 근거·출처 원문·발행자 신원 근거·검토 근거·검토자 자격 파일이 포함됩니다.
실제 보존 바이트가 검증돼야 이용 가능으로 취급합니다. 카탈로그 행·URL·파일 설명·선언 해시만으로
통과할 수 없습니다. 파일 부재와 인증된 콘텐츠 무결성 실패는 이용 불가이며 원래 관측에 세부
사유를 남깁니다. 기존 접근 주체·범위·분류 인가는 유지하고 게시·평가 권한을 새로 부여하지 않습니다.

## 게시 시각과 평가 시각의 구분

코어의 `validateReleasePolicyEvaluationAuthority`는 기존 설치·출처 요구사항을 재사용하되,
요청의 의미 시각 `evaluationTime`에서 정책의 `[effectiveAt, expiresAt)`를 검사합니다. 수집
시계가 미래라는 이유로 과거에 발효되지 않은 정책을 통과시키거나 만료를 연장하지 않습니다.
설치의 발행자·모드 인가는 아티팩트를 읽는 주체가 아니라 기록된 정책 발행자를 대상으로 합니다.

기존 `validateReleasePolicyAuthority`는 게시 전용입니다. 발효 전 게시를 계속 허용하며 게시
요청 시각은 UTC 밀리초 계약을 유지합니다. 평가 검증기는 기존 UTC 평가 시각 계약의 소수 초
최대 30자리까지 보존합니다. 두 함수 모두 보존된 출처 시각을 DB 마이크로초로 반올림하지 않고
비교합니다. 출처가 허용하는 시간대 오프셋과 원문 시각·해시도 바꾸지 않습니다.

정확한 범위·참조, 정책 전체 기간을 덮는 유효기간, 적용 범위, 라이선스, 독립적 신원 확인,
검토 결론·최신성·충돌 검토, 적격·독립 검토자와 보존 증빙 요구사항을 유지합니다. 선언된 신원,
사람의 전문성, 검토나 출처 주장이 현실에서 참이라는 보장은 아닙니다. 검색 결과로 연결된 출처를
몰래 대체할 수도 없습니다.

## 실패와 한도

`requirements.status`의 `valid`는 정적 요구사항에서 사유가 나오지 않았다는 뜻입니다.
미충족뿐 아니라 확인할 증거가 없어도 `invalid`이므로 최종 정책 판정으로 사용하거나 누락을
확정 위반으로 바꾸면 안 됩니다. 원래 기록·아티팩트 관측에 부재·기록 손상·참조 불일치·이용
불가를 구분해 남깁니다. 필수 출처·검토가 없으면 그에 의존하는 관계를 추측하지 않습니다.
따라서 사유 목록은 보지 못한 기록까지 가정한 모든 문제의 목록이 아닙니다.

루트 조회 실패는 기존 `roots_unavailable` 경로로 반환하며 권한 보고서를 만들지 않습니다.
예상 밖 저장소 예외는 전파합니다. 내부 부모 해시·의존 간선·출처 인덱스가 깨지거나 관측이
중복·충돌하고 아티팩트 범위·시각·참조가 바뀌면 정상 결과를 만들지 않고 수집을 실패시킵니다.

검사 계측 하나가 반대 증거, 규칙과 중첩 의존성의 반복 사용을 모두 포함합니다. 요청의 조회
기록 수·바이트 상한을 참조 출현 수와 canonical 참조 바이트에 적용하고 사용 전에 계측합니다.
실제 메타데이터·파일 I/O 계측과는 별개이며 CPU 타이머나 영속 재시도 계측이 아닙니다. 기존 파일
예산·분류·단조 시계·수집 종료 시점 보존 만료 검사는 그대로 적용합니다.

## 검증과 남은 경계

실제 메모리 게시 저장소·설치 소유 바인딩 해석기·암호화 카탈로그와 파일 저장소를 사용합니다.
정상 전제조건, 별도 아티팩트 조회 주체, 정밀 시각 경계, 게시 가능한 부정적 권한 기록, 따로
게시한 반대·충돌 증거, 기록 부재·손상·저장소 오류, 파일 부재·변조, 반복 출처, 정확한 누적
한도, 방어적 복사와 내부 일관성 실패를 검사합니다. 테스트의 다른 후보 의존성은 의도적으로
미해결이므로 정책의 정적 조건 통과가 후보 전체 그래프 완성을 뜻하지 않음을 확인합니다.
PostgreSQL 정책 워커나 출시 종단 간 검증을 수행했다고 주장하지 않습니다.

철회·대체 이력, 현재 권한과 아티팩트 변경 버전 방어, 원자적 스냅샷 게시, 정책 조건 계산,
영속 워커·재시도·API/SDK·복구·격리와 체크포인트 종단 간 검증은 남아 있습니다. 정적 `valid`
결과로 이 경계를 건너뛰거나 출시를 승인해서는 안 됩니다.
