# 수집한 데이터셋·픽스처의 연결 관계

[English](workflow-2-policy-dataset-relations.md) | [한국어](workflow-2-policy-dataset-relations.ko.md)

상태: 요청 기반 기록 수집에 데이터셋 구성원과 선행 버전의 직접 관계 검사를 연결했습니다.
전체 의미 관계의 완결성과 Workflow 2의 세 번째 체크포인트는 미완료입니다.

## 개별 기록 무결성만으로는 부족한 이유

정의 해시와 전체 기록 관측이 정상이더라도 두 기록의 연결이 올바른지는 별도로 확인해야 합니다.
기록형 상호작용 픽스처는 선행 증거 전용 픽스처의 스냅샷을 정확히 복사해야 합니다. 정의 해시에
포함하지 않는 `capturedAt` 접수 기록도 동일해야 합니다. 파일 바이트와 소유권이 일치한다고
이 관계의 오류가 해결되지는 않습니다.

다음 규칙은 기존 게시 경로와 [ADR-0017](../architecture/0017-own-interaction-content-per-fixture.md)을
따릅니다. 새 픽스처 형식을 만들거나 기존 버전을 재해석하지 않습니다.

- 데이터셋 구성원은 같은 테넌트·프로젝트·환경의 정확한 픽스처 ID·버전·정의 해시를 가리킵니다.
  증거 전용과 기록형 상호작용 픽스처를 모두 허용합니다.
- 데이터셋 선행 버전은 같은 논리 데이터셋과 범위에 속한 정확한 버전이어야 합니다.
- 두 픽스처 형식 모두 같은 논리 픽스처·범위의 증거 전용(`0.1`) 버전만 선행 버전으로 지정할 수
  있습니다. 기존 기록형 형식에는 선행 버전이 필수입니다.
- 기록형(`0.2`)으로 전환할 때 트레이스 ID, 순서 있는 이벤트 ID 목록, 개수, 완전성 표시와
  `capturedAt`을 포함한 전체 스냅샷을 그대로 복사합니다. 시각을 반올림하거나 다른 문자열 표현으로
  정규화해 같다고 처리하지 않습니다.
- 증거 전용 후속 버전에는 새로운 스냅샷을 담을 수 있습니다. 기록형 전환에만 필요한 정확한 복사
  제약을 이 경우까지 강제하지 않습니다.

## 고정된 도메인 검사기

`@proofstack/datasets`의 `inspectPolicyEvaluationDatasetRelations`는 범위·평가 시각,
중복 없는 데이터셋/픽스처 관측 목록과 참조 개수·바이트 한도를 받습니다. 검증된 기록 본문은
고정된 도메인 검사기로 한 번씩 다시 확인하고 정확한 참조·원래 전체 기록 해시에 연결한 뒤
의존 관계를 대조합니다. 범위와 접수 시각 검사는 유지합니다.

저장소·트레이스·객체·원문·네트워크를 읽지 않는 순수 검사입니다. 교체 가능한 검증기, 최신 버전
조회나 공개 HTTP 경로는 없습니다. 누락/사용 불가 관측의 본문은 null이어야 하며 원래 사유를
보존합니다. 이 관측은 신뢰된 수집 경로의 결과이지 호출자가 부재나 권한을 증명하는 수단이 아닙니다.

선언된 자식마다 정확한 관측이 목록에 있어야 합니다. 관측 자체의 누락, 중복 ID, 상충하는 전체
참조, 변경된 본문·해시, 잘못된 입력과 한도 초과는 실패하며 부분 성공 보고서를 반환하지 않습니다.
노드 수와 누적 관계 출현 수는 각각 `maxReferences`, 정규화된 기록 참조 바이트는
`maxReferenceBytes`로 제한합니다. 반복 관계도 계산합니다. 이 한도는 순수 검사의 제한이며
별도 수집 계측이나 전체 프로세스 메모리·네트워크 전송량 제한은 아닙니다.

## 결과와 신뢰된 연결 경로

`capturePolicyRecordGraph`가 직접 수집한 노드에서 검사 입력을 도출합니다. 호출자가 만든 그래프를
받지 않습니다. `datasetRelations`는 비교·트레이스·아티팩트 수집 결과에도 보존됩니다. 저장소를
추가 조회하지 않고 기존 수집 사용량을 초기화하거나 중복 부과하지 않습니다. 원래 그래프 간선,
기록 관측, 트레이스 읽기와 아티팩트 검사도 그대로 유지합니다.

출처 ID 순으로 정렬한 `parents`에는 정확한 출처와 전체 `recordSha256`이 있습니다. 순서 있는
`relations`는 `dataset_member`, `dataset_predecessor`, `fixture_predecessor` 종류와 부모 JSON
포인터, 전체 자식 참조, 원래 자식의 `recordObservation`을 보존합니다. 구성원 순서와 공유된 선행
버전의 반복 출현을 제거하지 않습니다.

| 관계 관측 | 의미 |
| --- | --- |
| `matched` | 검사한 직접 관계가 보존된 자식 기록과 일치 |
| `unavailable` | 검증된 자식 본문이 없음. 누락·잘못된 기록·참조·시각 사유는 `recordObservation`에 보존 |
| `mismatch / predecessor_format_mismatch` | 현재 게시 모델이 허용하지 않는 기록형 상호작용 픽스처를 선행 버전으로 지정 |
| `mismatch / trace_snapshot_mismatch` | 기록형 전환이 증거 전용 선행 버전의 정확한 전체 스냅샷을 복사하지 않음 |

`unavailableParents`에는 읽을 수 없는 부모를 따로 남깁니다. 알 수 없는 의존 목록을 선행 버전이
없는 정상 루트로 바꾸지 않습니다. 읽을 수 있는 증거 전용 픽스처의 관계 목록이 비어 있더라도
선언만 설명할 뿐, 논리 루트로 등록되었음을 증명하지 않습니다. 관계마다 먼저 해당하는 불일치만
보고하며 모든 결함을 열거하는 것은 아닙니다.

**직접 관계의 일치는 전체 계보의 적격성이 아닙니다.** 데이터셋의 구성원 참조가 일치해도 해당
픽스처의 선행 관계는 불일치하거나 확인 불가능할 수 있습니다. 두 관측을 모두 보존해야 합니다.
일부 관계의 전부 일치나 `artifacts_captured`만으로 정책 충족·릴리스 승인을 내리지 않습니다.

## 검증과 남은 범위

단위 테스트는 두 픽스처 형식, 데이터셋 선행 버전, 순서·공유 구성원, 원래 기록 해시, 누락·오류·
미래·참조 불일치 자식, 관측 누락·중복, 접수 기록·정의 대체, 시각 표현·정밀도, 이벤트 순서·구성원
변경, 결정적인 정렬, 분리된 반환값과 정확한 개수·바이트 한도를 다룹니다.

공개 수집 경로 테스트는 실제 메모리 게시, 그래프·증거 저장소와 인증 암호화한 합성 파일을 사용합니다.
간선·해시 출처와 ID별 한 번의 조회를 확인하며 두 픽스처 저장 형식은 별도 조회로 계산합니다.
통제된 잘못된 어댑터 응답을 통해 정의 해시·바이트·소유권이 정상이더라도 전환 시 복사한 접수
기록의 변경을 감지합니다. 저장소 장애는 사용 불가 관측으로 바꾸지 않고 그대로 전파합니다.
이 검사는 PostgreSQL 정책 워커나 실제 공급자 실행의 완료 검증이 아닙니다.

논리 루트 등록, 다른 재현·평가 관계, 변경 가능한 권한·철회, 동시 변경 방어, 권위 있는 전체
의존관계, 스냅샷 봉인, 결정론적 정책 판정, 영속 작업, API/SDK, 복구·격리와 종단간 완료 검증은
별도 작업으로 남아 있습니다. Workflow 2 완료 체크포인트는 **2/7**입니다.
