# PostgreSQL 인증된 검토자 권한 관리

[English](workflow-2-native-reviewer-administration.md) | [한국어](workflow-2-native-reviewer-administration.ko.md)

상태: 체크포인트 4 구성요소이며 정확한 소스의 전체 발행 검증이 필요합니다.
Workflow 2는 **3/7 체크포인트 승인**입니다.
[ADR-0062](../architecture/0062-publish-reviewer-administration-through-private-native-ports.md),
[인증된 참조 구현](workflow-2-authenticated-reviewer-reference.ko.md),
[결정 진입 감사](workflow-2-decision-entry-audit.ko.md)를 함께 읽으세요.

`PostgresReleaseReviewerAdministrator`는 참조 구현과 같은 고정 서비스 포트를 구현합니다.
실제 쿠키·CSRF·정확한 범위·`approval:authority:manage`를 본문 해석 전에 확인합니다.
서버가 발급자와 행위자를 도출하며 호출자 principal·시각·SQL·범용 권한 콜백을 받지 않습니다.

별도로 선택해서 구성하는 `reviewerAuthority` DB 역할은 전용 표시와 자격 증명을 사용합니다.
마이그레이션 원장 SELECT와 비공개 고정 실행 포트 7개만 얻습니다. 원본·세션 테이블 직접 접근,
선택 설치·승인·결정·작업자 권한은 얻지 않습니다. 실제 연결의 유효 권한과 부여 옵션,
함수 본문·강제 RLS·트리거 구성을 검증합니다.

마이그레이션 0073은 원본 선언·안전한 신원/권한/세션 원상·backend/XID/복구 epoch·발급 시각과
별도 reviewer-publication 0.1을 보존합니다. 쿠키·CSRF·비밀 검증값·아티팩트 내용·키는 보존하지
않습니다. 기존 검토자 선언·수명주기·상태·보증 표시·대상·정규 바이트는 유지합니다.

하나의 제한된 READ COMMITTED 연결이 메타데이터/복구·검토자·실제 OIDC 소스 가드를 끝까지
유지합니다. 고정 투영은 원래 정규화 검증기를 재사용하고 전체 대상 이력을 검사합니다.
페이지당 ID 16개, 프레임당 해독 바이트 64 KiB, 전체 10,000개 기록/16 MiB 한도를 적용하며
반복 관측도 해독 전에 계산합니다. 가드 아래에서 내용·키·외부 네트워크 I/O를 수행하지 않습니다.

원본·진행 중 증명·완성 프로필·정규 outbox 의도를 원자적으로 발행합니다. 불변/지연 트리거는
원본 변경과 미완성 커밋을 거부합니다. 최종 완성 직전에도 현재 세션·권한·복구 epoch를 재검사합니다.
손상·만료·한도·권한·스키마 실패는 전체를 롤백하며 자동 재시도하지 않습니다.

동일 요청에도 현재 인증이 필요하지만 최초 원본·행위자·요청·시각·프로필은 보존합니다.
새 버전은 원래 루트·부모 인증 근거와 전체 소유 이력을 재검사합니다. 과거 비인증 기록에 새 증명을
붙이지 않습니다. 원래 관리자의 이후 로그아웃은 모든 과거 선언의 철회가 아니며, 다른 적격 관리자가
새 행위를 발행할 수 있습니다. 미래 효력·미확인·거절 선언을 보존하고 활성 선택을 새 조건으로 만들지
않습니다. 관리 인증은 전문성·근거 내용의 진실성·대리 승인·현재 릴리스 권한이 아닙니다.

전진 마이그레이션 0072는 기존 0071과 함수 식별자·권한을 보존하면서 역할 시스템 카탈로그를 명시합니다.
실제 DB에서 테스트용 실행 권한을 일부러 부여한 잘못된 역할의 임시 카탈로그 위장을 재현했고 수정 후
차단합니다. 기본 API 역할에는 그 실행 권한이 없습니다. 스키마 검사도 실제 카탈로그를 명시하여 오래된
임시 복사본이 함수 변경을 숨기지 못하게 합니다.

참조·실제 DB가 같은 서비스 사례 16개를 실행하며 자기 발급·과다 권한·테넌트 충돌·후속/종료 기록·손상·
경합·자연 만료·미완성 커밋·충돌 롤백·연결 재사용을 추가 검증합니다. 실제 쿼리 관측을 이용한 단위 검사는
운영 신원 증명이 아닙니다. 기존 설치 원본 관측은 유지하고 새 스키마 관측만 명시적으로 합성합니다.

복구 연습은 실제 인증된 원본·후속·대체·철회 기록을 저장한 뒤 별도 DB로 복원하고 역할을 다시 구성하여
재요청에서 최초 영수증을 비교합니다. 단위 검사, 실제 서비스 통합, 정확한 커밋 전체 검증은 구별합니다.
운영 배포·가용성·전문성·RPO/RTO를 보장하지 않습니다.

다음은 실제 인증된 승인/철회, 결과 확인 전 입력 계획, 완전한 가드 기반 결정, 제한된 API/OpenAPI/SDK와
기여자 실행 검증, 별도 체크포인트 4 종료 감사입니다. 이후 체크포인트 5–7과 측정 기반 5단계도 남아 있습니다.
