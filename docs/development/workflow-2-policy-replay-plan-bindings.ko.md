# 수집한 재현 계획의 연결 검사

[English](workflow-2-policy-replay-plan-bindings.md) | [한국어](workflow-2-policy-replay-plan-bindings.ko.md)

상태: 기록 그래프 수집에서 선언된 재현 계획의 일관성을 제한된 범위로 검사합니다. 실제 재현 실행,
전체 의미 관계, 변경 가능한 권한과 Workflow 2의 세 번째 체크포인트 완료는 별도 검증입니다.

## 의미와 고정된 도메인 경계

스키마가 정상인 재현 계획도 내부 호출 정의 해시가 다르거나, 선언한 데이터셋 밖의 픽스처를
가리키거나, 실행 대상이 지원하지 않는 경계 종류·모드를 요구할 수 있습니다. 개별 기록 검증만으로
이 연결 관계를 증명할 수는 없습니다.

`@proofstack/replay`의 `inspectPolicyEvaluationReplayPlanBindings`가 수집한 계획·실행 대상·
데이터셋·픽스처·런타임 프로필·격리 프로필을 검사합니다. 정확한 입력을 요구하는
[ADR-0013](../architecture/0013-bounded-replay-execution.md), 기록형 픽스처 계약과 기존 워커의
사전 호환성 검사에 근거합니다. 런타임 검사는 보존된 프로필과 실행 대상의 아키텍처·플랫폼·버전
선언을 대조하는 것이며 검사기가 돌아가는 현재 컴퓨터를 측정하는 것은 아닙니다.

순수 검사기는 범위·시각·엄격한 관측 형식을 확인하고 고유한 검증 기록 본문마다 고정된 도메인
검사기로 한 번씩 재검증하여 원래 전체 해시에 연결합니다. 호출자 선택 검증기, 최신 별칭, 설치,
실행, 자격 증명 조회, 네트워크 검색이나 파일 읽기는 없습니다. 누락 관측은 null 본문과 원래
사유를 유지합니다. 이는 신뢰된 수집 결과이지 공개 호출자가 부재를 증명하는 수단이 아닙니다.

계획이 선언한 의존성마다 정확한 관측이 필요합니다. 관측 누락, 중복 ID, 참조 대체, 본문·접수 기록·
해시 변경, 잘못된 입력과 한도 초과는 부분 성공 없이 실패합니다. 고유 입력 노드와 누적 의존성
출현 수는 각각 `maxReferences`, 정규 참조 바이트는 `maxReferenceBytes`로 제한합니다. 반복 경계·
시뮬레이터 참조도 따로 계산합니다. 전체 메모리·전송량·영속 재시도 예산을 증명하는 제한은 아닙니다.

## 결과와 수집 경로

`capturePolicyRecordGraph`가 자체 노드에서 입력을 도출하며 `replayPlans`를 비교·트레이스·
아티팩트 수집에도 보존합니다. 저장소 추가 조회나 수집 한도 초기화는 없습니다. 각 `plans` 항목은
정확한 출처·원래 `recordSha256`·순서 있는 `dependencies`와 `checks`를 담습니다. 의존성마다
부모 JSON 포인터, 전체 대상 참조와 원래 `recordObservation`이 있어 기존 그래프 간선과 대응합니다.

의존성은 데이터셋, 런타임 프로필, 격리 프로필, 주 실행 대상, 이후 경계 순서의 기록형 픽스처·
시뮬레이터 대상 순입니다. 계획은 출처 ID 순으로 정렬합니다. 읽을 수 없는 계획은 성공한 빈 검사
목록이 아니라 `unavailablePlans`에 남기고, 읽을 수 없는 자식도 누락·오류·참조·시각 사유를 보존합니다.

각 검사는 `kind`, 부모 `path`와 `matched`, `mismatch`, `unavailable` 관측을 반환합니다.

| 검사 | 요구사항 |
| --- | --- |
| `runtime_family` | 계획의 런타임 계열과 보존된 주 실행 대상의 계열 일치 |
| `runtime_configuration` | 보존된 런타임 프로필과 주 실행 대상의 아키텍처·플랫폼·버전 일치 |
| `boundary_kind` | 주 실행 대상이 해당 경계 종류를 지원한다고 선언 |
| `boundary_mode` | 주 실행 대상이 해당 경계 모드를 지원한다고 선언 |
| `invocation_digest` | 기록형 경계 내부 호출 정의의 독립적인 해시 계산 결과가 선언된 해시와 일치 |
| `fixture_membership` | 기록형 호출의 정확한 픽스처 참조가 계획의 데이터셋에 포함 |
| `fixture_format` | 기록형 호출 대상이 증거 전용이 아닌 기록형 상호작용 픽스처(`0.2`) |

한 검사가 실패하더라도 다른 실패·확인 불가 조건을 생략하지 않습니다. 호출 정의 해시는 대상·
데이터셋·픽스처를 읽지 못해도 확인할 수 있습니다. 구성원 검사에는 데이터셋, 형식 검사에는
픽스처가 필요하며 서로의 결과로 추정하지 않습니다. 종류·경로와 보존된 계획·의존성으로 비교
대상을 식별하며 자유 형식 진단이나 정책 판정을 만들지 않습니다.

데이터셋 전체가 기록형일 필요는 없고 모든 구성원이 실행되었다고 주장하지 않습니다. 선언된
기록형 호출의 픽스처만 정확한 구성원이어야 합니다. 시뮬레이터 대상은 별도 정확한 참조로 확인하며
주 실행 대상의 런타임 조건을 임의로 강제하지 않습니다. 라이브 엔드포인트·자격 증명·자격 증거·
설치된 어댑터와 구현체는 별도 의존성입니다. 로컬 참조 워커의 컨테이너·프로토콜 버전·타임아웃
지원 한계를 보편적인 정책 사실로 적용하지 않으며 게시·실행 동작도 바꾸지 않습니다.

## 검증과 남은 한계

정규 벡터, 의미를 바꾼 뒤 독립적으로 해시를 다시 계산한 기록과 실제 메모리 재현 정의 게시를
평가 그래프에 연결한 테스트를 사용합니다. 개별 해시는 정상이지만 의미가 틀린 기록, 사용 불가
의존성, 정확한 간선·해시, 원래 누락 사유, 잘못된·중복·생략된 관측, 결정적 정렬, 분리된 반환값,
반복 시뮬레이터 참조, 세 경계 모드, 정확한 한도와 저장소 장애를 다룹니다. 실제 그래프 수집에서
계획·대상 ID마다 한 번 조회하며 외부 공급자나 대상 프로그램을 실행하지 않습니다.

직접 계획 일관성은 전체 픽스처 계보 적격성, 루트 등록, 파일 가용성, 출처·설치 권한, 런타임 설치,
과거 시도의 실행, 재현 결과 의미, 현재 철회 상태나 봉인을 증명하지 않습니다. 계획이 일치해도
픽스처 선행 관계 등은 잘못될 수 있으므로 모든 보고서를 보존해야 합니다. 다른 관계와 생명주기·
동시 변경 방어를 마친 뒤 스냅샷 봉인, 결정론적 정책 결과, 영속 작업, API/SDK, 복구와 종단간
검증으로 이어집니다. Workflow 2 완료 체크포인트는 **2/7**입니다.
