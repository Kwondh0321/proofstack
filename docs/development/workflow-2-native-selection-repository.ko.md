# 대상 소유 선택 목록의 PostgreSQL 저장소

[English](workflow-2-native-selection-repository.md) | [한국어](workflow-2-native-selection-repository.ko.md)

상태: 체크포인트 4의 PostgreSQL 선택 목록 저장 전제입니다. Workflow 2는 여전히 **7개 중
3개 체크포인트 승인** 상태입니다. 실제 설치 권한과 완전한 결정 발행은 남아 있습니다.
[ADR-0053](../architecture/0053-persist-complete-target-owned-policy-selections.md)과
[진입 감사](workflow-2-decision-entry-audit.md)를 함께 읽으세요.

## 원본 소유권과 원자적 저장

[마이그레이션 0065](../../packages/postgres/migrations/0065_release_policy_selection_storage.sql)는
최초 대상 소유 루트, 불변 버전, 순서가 있는 정책과 발행 주체, 종료 이력을 다섯 개의 비공개
추가 전용 테이블에 저장합니다. 강제 RLS는 테넌트·프로젝트·환경을 모두 확인합니다. 지연
제약은 정확한 루트·선행자·후속자, 완전한 정규화 투영, 정규 outbox 의도를 연결합니다.
불완전한 그래프나 충돌은 쓰기 전체를 롤백합니다.

[PostgreSQL 어댑터](../../packages/postgres/src/postgres-release-policy-selection-repository.ts)는
[메모리 참조](workflow-2-selection-repository.md)와 같은 신뢰된 내부 선언 포트를 구현합니다.
저장 전에 원본 정의와 정규 바이트를 검증하고, 커밋 전에 정규화 그래프와 outbox를 다시
읽습니다. 같은 의도의 재시도는 최초 행위자와 시간을 보존합니다. 테넌트 간 같은 물리 ID는
허용하지만 다른 프로젝트·환경의 선언이나 대상 소유권을 가져올 수 없습니다.

관리 연결이나 선언의 행위자 필드는 실제 설치 인증을 대신하지 않습니다. 새 런타임 역할,
기본 권한, 공개 POST, 작업 또는 워커는 추가하지 않습니다. 역할 재설정은 복원된 오래된
권한을 포함하여 PUBLIC과 기존 역할의 비공개 테이블·함수 접근을 회수합니다. 기존 정책
평가자의 정책 읽기 목록에서도 새 선택 테이블을 명시적으로 제외합니다.

## 완전한 읽기와 유지되는 guard

`readPostgresReleaseSelectionTargetOnClient`는 정확한 설치·게이트 대상에서 최초 소유권을
도출합니다. 별도 C4 도메인의 테넌트 공유 guard를 먼저 얻고 고정 16개 키셋 페이지로 모든
버전과 종료 이력을 읽습니다. 미래 버전·경쟁 버전·철회 이력을 유리하게 생략하지 않습니다.
대상 부재는 하나의 완전한 부재 관측이고, 손상된 인덱스나 투영은 무결성 실패입니다.

모든 선택 레코드 삽입에는 배타적 트랜잭션 guard가 강제됩니다. 부재 대상 생성과 종료
이력 추가는 읽는 트랜잭션이 끝날 때까지 기다립니다. 읽기 guard 경합은 부분 목록 없이
실패합니다. 비공개 VOLATILE 루트 함수는 guard 획득 뒤 READ COMMITTED 관측을 수행합니다.
테넌트 단위 잠금은 참조 구현의 정확성 선택이며 처리량 측정을 뜻하지 않습니다.

정확한 버전·종료 이력 읽기는 원본, 정규 투영, 관계, 정규 outbox 의도를 검증합니다. 대상
읽기는 원래 서버 소유 검증 예산에 원본 바이트·묶인 레코드 수·부재·반복 관계 읽기를 모두
계상합니다. 연결·트랜잭션·소스 실패를 잡아도 예산은 계속 실패 상태이며 새 조회에 재사용할
수 없습니다. 가짜 예산도 I/O 전에 거부합니다. UTC 원문은 소수점 이하 최대 30자리를
보존하고 정확한 순서 키는 문자열로 전송합니다. outbox의 DB 시간은 투영일 뿐입니다.

제공 연결 함수는 호출자의 명시적 정확 범위 READ COMMITTED 트랜잭션을 요구하며 커밋하거나
연결·guard를 해제하지 않습니다. 편의 저장소 읽기는 반환 전에 트랜잭션을 끝내므로
**반환된 목록만으로 나중에 결정을 발행할 수 없습니다.**

## 검증과 다음 경계

기존 공유 적합성 검사를 실제 PostgreSQL 구현에 적용합니다. 네이티브 검사는 다중 페이지,
동일 연결·XID·savepoint 유지, 부재·종료 이력 경합, 범위·격리 거부, 소유자에게도 강제되는
RLS, outbox 충돌 전체 롤백, 정규 투영 손상을 다룹니다. 역할 검사는 오래된 비공개 권한의
회수를 확인합니다. 단위 전송 fixture는 합성 데이터의 실제 PostgreSQL 16.15 응답이며
정규 정의·원본 시간·관계·outbox 변조, 예산, 롤백 정리를 검증합니다. 독립 SQL 오라클이나
실제 DB 검사를 대신하지 않습니다.

폐기 가능한 `proofstack_test`에서만 실행하고 기존 단언·커버리지·마이그레이션 체크섬·필수
CI 검사를 유지하세요. fixture 관리 권한은 테스트 전용입니다. 다음은 검토자·승인 저장소,
분리된 최소 권한 역할, 실제 현재 설치·검토자·발행 주체 권한, 모든 소스·부재 guard와 복구
epoch를 같은 연결에 유지하는 원자적 결정·outbox 발행입니다. 복구·API·SDK·실서비스 기여자
흐름과 독립 종료 감사를 거쳐야 체크포인트를 승인합니다. 이후 체크포인트 5–7과 측정 조건의
5단계도 계속 남아 있습니다.
