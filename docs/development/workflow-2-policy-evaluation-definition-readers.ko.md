# 정책 평가용 데이터셋·재현 정의 읽기

[English](workflow-2-policy-evaluation-definition-readers.md) |
[한국어](workflow-2-policy-evaluation-definition-readers.ko.md)

상태: 불변 기록 수집 기반 기능 구현. 재귀 수집, 보호된 스냅샷, 결정론적 규칙 평가 및
정책 평가 체크포인트는 아직 완료되지 않았습니다.

[평가 근거 읽기](workflow-2-policy-evaluation-evidence-reader.ko.md)가 다루는 평가·모델·사람 검토
기록 30종에 이어, 기존 데이터셋·재현 저장소에서 읽는 출처 종류 4개를 추가합니다.
새 DB 테이블, 쓰기 권한, 실행 권한, 엔드포인트, 웹사이트 또는 사용자용 포트는 추가하지 않습니다.

## 기존 도메인과 권한 경계 유지

`readPolicyEvaluationDataset`은 `packages/datasets`에,
`readPolicyEvaluationReplayDefinition`은 `packages/replay`에 있습니다.
두 함수는 `packages/core`의 공통 관찰 함수 `readPolicyEvaluationDefinitionRecord`에 의존하며,
core가 두 도메인을 역으로 가져오지 않습니다. 이후 수집 조합은 좁은 읽기 인터페이스로 연결해야
하며, core에 데이터셋·재현 발행 구현을 가져와 의존성 방향을 뒤집으면 안 됩니다.

공통 함수는 신뢰하는 고정 도메인 검증기를 위한 내부 기반 코드입니다. 공개 플러그인 등록이나
인가 API가 아닙니다. 각 어댑터는 기존 도메인 스키마와 정의 다이제스트 계산으로 기록을 다시
검증합니다. 외부 요청자가 제공한 콜백은 권위 있는 검증기가 될 수 없습니다.

| 출처 종류 | 정확한 읽기 | 검증 대상 |
| --- | --- | --- |
| `dataset_version` | `findDatasetVersion(scope, datasetVersionId)` | 회귀 데이터셋 버전 |
| `regression_fixture_version` | 같은 범위·버전 ID로 두 fixture 저장소 조회 | 증거 전용 v0.1 또는 기록된 상호작용 v0.2 |
| `replay_plan` | `findReplayPlan(scope, planVersionId)` | 재현 계획과 원래 발행 시각 |
| `target_release` | `findTargetRelease(scope, targetReleaseId)` | 재현 대상 릴리스와 원래 발행 시각 |

범위와 의미상 평가 시각은 이미 인가·검증된 요청·후보·정책 루트에서 가져와야 합니다.
이 함수들은 HTTP 사용자를 인증하지 않습니다. 의존성에는 읽기 메서드만 있으며, 원래 작성자
사칭, 정의 발행, 재현 실행, 콘텐츠 폐기 권한이 필요하지도 부여되지도 않습니다.

## 정확한 기록 관찰과 실행 성공은 다름

I/O 전에 알 수 없는 최상위 입력 필드, 잘못된 범위·시각·참조, 허용되지 않은 출처 종류를
거부합니다. 입력을 파싱한 사본과 저장소에 전달할 사본을 분리합니다. 최신 버전 선택, 다른
프로젝트 검색, 네트워크 검색, 수치가 같은 다른 기록으로의 대체는 하지 않습니다.

저장된 정의를 엄격하게 파싱하고 다이제스트를 재계산한 뒤 모든 참조 필드를 비교합니다.
논리 ID뿐 아니라 재현 대상의 중첩 어댑터·워커 프로토콜 정보까지 포함합니다. 중첩 값은 객체
주소나 키 삽입 순서가 아니라 정규화된 값으로 비교합니다. 테넌트·프로젝트·환경이 모두 같아야
하며, 원래 `createdAt`이 `evaluationTime`보다 늦으면 안 됩니다. 지원하는 소수초 정밀도를
버리지 않습니다.

| 결과 | 관찰 |
| --- | --- |
| 정확한 조회가 `null` 반환 | `missing` |
| 스키마·정의 다이제스트 오류 | `unavailable`, `record_invalid` |
| 유효한 기록이지만 범위·참조 불일치 | `unavailable`, `reference_mismatch` |
| 평가 시각 이후 발행 | `unavailable`, `not_yet_available` |
| 기록 수준 검사 통과 | `verified`, 발행 메타데이터를 포함한 전체 기록 SHA-256 |
| 저장소 오류 또는 예상하지 못한 검증 예외 | 원래 예외 전파, 관찰값을 만들어 내지 않음 |

검증된 기록만 방어적으로 파싱한 사본으로 반환합니다. 정의 해시가 같아도 발행 메타데이터만
바뀌면 전체 기록 해시가 달라집니다. 이는 정책 충족, 승인, 배포 허가, 출처 진실성의 증거가
아닙니다. 계획이 검증됐다고 재현이 완료된 것은 아니며, 대상 정의가 검증됐다고 실행 파일
바이트나 설치된 런타임 권한이 검증된 것도 아닙니다.

## 두 fixture 형식을 서로 대체하지 않기

기존 fixture 참조에는 스키마 형식 선택 필드가 없습니다. 따라서 독립적인 범위 사본으로 두
불변 저장소를 모두 조회합니다. **둘 다 정확히 `null`을 반환해야** 부재입니다. 두 저장소가
모두 값을 반환하거나 어느 한쪽의 비-null 값이 잘못되면, 해시가 맞는 다른 쪽을 임의로 고르지
않습니다. v0.1은 증거 저장소, v0.2는 상호작용 저장소에서만 받습니다. 저장소 장애를 다른
쪽의 성공으로 숨기지 않습니다.

상호작용 저장소가 함께 반환하는 소유권 메타데이터는 이 단계의 검증 대상이 아닙니다.
검증·해시 대상은 불변 `version`입니다. 별도의 아티팩트·소유권·폐기 상태 수집을 대신할 수
없습니다. 콘텐츠 폐기 후에도 과거 정의는 읽힐 수 있으며, 정의 읽기 성공만으로 재현 가능성이나
현재 바이트 가용성을 인정하면 안 됩니다.

데이터셋·계획·대상은 저장소 호출 1회, fixture는 동시 호출 2회의 성공 결과가 필요하며
어느 쪽이든 오류가 발생하면 대체 없이 전파합니다.
전역 원자적 스냅샷을 제공하는 것은 아닙니다. 상위 수집기는 누적 I/O·바이트·시간·재시도 제한과
발행·수명주기 경쟁에 대한 일관성·리비전 검사를 거쳐야 관찰 집합을 봉인할 수 있습니다.

## 검증과 남은 작업

기존 모든 관련 정의 벡터, 독립적으로 정렬한 JSON 해시 오라클, 의존 순서대로 발행한 실제
메모리 저장소를 사용합니다. 모든 참조 필드, 중첩 프로토콜 바꿔치기, 세 범위 차원, 잘못된
데이터와 부재의 구별, 형식 간 중복 ID·잘못된 저장 경로, 의미·해시 변경, 정밀 시간 경계,
발행 해시, 방어적 복사, 콜백의 입력 변경, 저장소 오류와 예상 밖 검증 예외를 검사합니다.

새 PostgreSQL 통합, 아티팩트 콘텐츠 검증, 정책 워커가 완성됐다는 의미는 아닙니다.
정의 의존성 확장, 정확한 재현 결과·작업·시도 검증, 비교·루트·프로파일·설치 출처 수집,
해시 없는 선택자 해소, 부모·자식 관계 재계산, 전역 충돌 검사, 보관 바이트 내부 참조 확장,
수명주기·리비전 검사와 보호된 스냅샷이 남아 있습니다. 워커, DB 역할·복구, API·SDK, 기여자
실행 흐름 및 [체크포인트 진입 검토](workflow-2-policy-evaluation-entry-audit.ko.md)의 모든
종료 조건도 계속 필수입니다.
