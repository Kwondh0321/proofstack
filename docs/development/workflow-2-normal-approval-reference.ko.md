# Workflow 2 인증된 정상 승인 참조 구현

`MemoryReleaseSelectionInstallerReference`에
`ReleaseNormalApprovalRecorder.recordNormalApproval(credentials, intent)`를 연결했습니다.
정책 선택·검토자 관리·원래 검토자의 철회와 하나의 비공개 상태를 공유하는 합성 참조 구현입니다.
Workflow 2 체크포인트 4는 아직 완료되지 않았습니다.

실제 OIDC 쿠키·CSRF·범위와 현재 `approval:decide`를 본문보다 먼저 검사합니다. 요청은 검토자,
인증 영수증, 자격, 시계나 읽기 함수를 지정할 수 없습니다. `normal_approval`만 허용하고,
원래 요청 인덱스가 가리키는 완료 작업·전체 봉인 페이지·결과를 읽어 재계산합니다. 실제 원래
`approval_required` 규칙에서 검토 요건과 작성자 제외 조건을 도출합니다.

대상의 전체 정책 선택·검토자 자격 목록을 원래 인증된 발행 출처와 대조합니다. 정확한 후보 대상과
선택된 정책, 정책 유효기간 및 종료 이력이 일치해야 합니다. 현재 검토자 자격은 역할·독립 그룹에
부합하고, 검증 상태이며, 자격 충돌이 없고, `synthetic_reference`임을 명시해야 합니다.
정책 작성자는 제외하고 후보 작성자 제외 여부는 원래 규칙을 따릅니다.

선택 근거와 모든 검토자 근거는 실제 사용자의 `artifact:read`로 기존 AES-GCM 읽기를 수행합니다.
`approval:decide`가 내용 읽기 권한을 대신하지 않습니다. 누락·손상·만료·잘못된 범위·변경된 내용은
발행을 막습니다. 같은 내용의 반복 사용도 각각 읽고, 암호화 형식 오버헤드를 포함한 합산 16 MiB
한도를 읽기 전에 예약합니다. 공통 레코드·바이트·승인 예산은 전체 카탈로그와 반복 검사도 셉니다.
키·경로·평문·브라우저 비밀은 응답에 포함하지 않습니다. 무결성이 실제 전문성이나 문장의 진실을
보증하지는 않습니다.

내용과 키를 읽은 뒤 같은 임시 소유 상태에서 현재 출처·카탈로그·소유권·보존기한을 재검사합니다.
승인·원래 안전한 인증 출처·두 정규 이벤트 의도를 한 번의 상태 비교·교체로 반영합니다. 그 사이
다른 정상 쓰기가 발생하면 전체 작업을 거부하며, 더 최신 상태로 몰래 옮겨 발행하지 않습니다.
요청한 유효기간은 선택·정책·검토자·근거의 알려진 만료 경계를 넘을 수 없습니다.

네 가지 의견과 선언한 충돌·조건·정확한 대체·철회 이력을 보존합니다. 같은 요청의 재시도도 현재
인증·권한을 요구하지만 첫 검토자·세션·요청·시각·자격·기록을 그대로 반환합니다. 이는 만료된
과거 영수증일 수 있으며 새 권한을 만들지 않습니다. 원래 평가는 계속 `approval_not_evaluated`인
`indeterminate`입니다. 이후 별도 권한과 보호를 갖춘 결정만 해당 전제조건을 해소할 수 있습니다.

합성 자료 준비는 실제 완료 저장소의 독립 복사본과 암호화된 시험 근거를 사용하는 소유자 기능입니다.
공개 업로드나 C3 발행 검증을 대신하지 않습니다. 상태와 로컬 암호화 키는 프로세스 종료 시 사라지며,
바이트 예약은 지속 작업 예산이나 실제 네트워크 전송 측정이 아닙니다. 실제 전문성, 현재 정책의
상위 출처 적격성, 정족수·결정·운영 승인 권한을 완료했다고 주장하지 않습니다.

예외의 전체 원래 평가자 출처·보완 통제, PostgreSQL 보호 발행·철회·복구, 결과를 보기 전 결정 입력
예약, 결정·API·SDK·기여자 흐름과 독립 종료 감사가 남아 있습니다.
