# 정책 메타데이터 수집 예산 확보

Workflow 2 체크포인트 3은 아직 열려 있습니다. 이 변경은 내부 메타데이터 예산
확보·정산을 정의하며, 실제 수집·봉인 진입점과의 연결은 남아 있습니다.
공개 API, worker 실행 파일, 사람의 승인 또는 운영 배포를 제공하지 않습니다.

`reserveAcquisition`은 I/O 전에 원래 요청의 남은 읽기·레코드·참조 수와 공유
레코드/참조 바이트 예산을 커밋합니다. 확보량은 사용량이 아니며 정확한 작업·시도·
작업자·리스·fence·복구 epoch에 묶입니다. 기한이나 요청 한도를 바꿀 수 없습니다.
열린 확보의 중복 응답은 원래 기록을 보존하며 새로운 수집을 허가하지 않습니다.
닫힌 확보 ID도 재사용할 수 없습니다.

시작한 작업이 모두 끝난 뒤 서버가 관측한 다섯 메타데이터 카운터를 정산합니다.
비용을 확정할 수 없는 `usage: null`은 확보량 전체를 차감하고 작업을
`budget_exhausted`로 닫습니다. 취소·중단·리스 회수·이력 한도·복구도 미확정 확보량을
먼저 차감합니다. 취소와 기한 만료의 결과 우선순위는 보존합니다. 응답 손실·롤백·
크래시로 비용을 환불하지 않으며, 모호한 응답은 권위 있는 조회로 확인해야 합니다.
변경을 자동 재시도하거나 같은 확보로 두 번째 수집을 시작하면 안 됩니다.

아티팩트 바이트와 규칙 실행 비용은 별도로 유지합니다. 확보 중 외부 메타데이터
사용량 변경을 거부하며, 새 선택 필드가 없는 과거 그래프의 정규 바이트·해시는
유지합니다. 마지막 이력 슬롯은 운영상 예산 소진 기록에 사용합니다.

마이그레이션 0061은 강제 RLS를 적용한 비공개 원장과 evaluator 전용 변경 함수를
추가합니다. 원래 확보·닫힌 정산 기록을 보호하고, 최종 커밋 시 실제 DB 시간과
복구 epoch를 확인합니다. 복구와 취소는 만료 후에도 미확정 비용을 보존하며 이전
작업자의 실행 권한을 되살리지 않습니다. 기존 마이그레이션과 검사 기준은 유지합니다.

메모리/PostgreSQL 공통 검사, 커밋 직전 만료 검사, 열린 확보를 포함한 실제
PostgreSQL/S3 복원 검증을 제공합니다. 실제 수집의 남은 한도 강제, 동일한 보호
트랜잭션에서 정산 후 봉인, 실패 비용 보존을 연결한 뒤 worker·API·SDK·기여자
검증과 독립 종료 감사를 완료해야 합니다.

세부 경계는 [영문 가이드](workflow-2-policy-acquisition-allowances.md)와
[체크포인트 진입 감사](workflow-2-policy-evaluation-entry-audit.md)를 참조하세요.
