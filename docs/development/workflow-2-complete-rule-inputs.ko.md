# 원래 순서를 보존한 전체 정책 규칙 입력

[English](workflow-2-complete-rule-inputs.md) |
[한국어](workflow-2-complete-rule-inputs.ko.md)

상태: 전체 규칙의 원래 입력 목록을 구현했습니다. Workflow 2는 승인된 체크포인트
2/7이며 체크포인트 3은 미완료입니다. 규칙 판정이나 봉인 스냅샷은 생성하지 않습니다.

`capturePolicyArtifactEvidence`는 기존 아티팩트·비교·평가 입력 보고와 함께
`ruleInputs`를 반환합니다. 고정된 내부
[`inspectCapturedRuleInputs`](../../packages/policy-evaluation/src/capture-rule-inputs.ts)가
수집 복사본을 소유하고 세 소유 검사기를 각각 한 번 실행합니다. 외부 보고 배열이나
검사기 콜백을 받지 않습니다. 요청·루트·본문·수신·해시·전체 참조·간선과 기존 후보
목록·계보를 동일 수집에서 재검증하며 모든 입력 보고의 후보·정책 루트가 같아야 합니다.

## 원래 규칙을 빠짐없이 원래 순서로 보존

정확한 요청 참조·범위·의미 평가 시각과 후보·정책 참조·전체 루트 해시를 연결합니다.
각 정책 규칙을 원래 순서대로 한 번씩 남기고 조건·ID·심각도·nonWaivable·근거·
출처 선언을 모두 보존합니다. 각 입력 보고의 규칙 위치·ID·조건이 원래 규칙과 같아야
하며 누락·중복·잘못된 입력 종류·불필요한 추가 항목을 허용하지 않습니다.

아티팩트 요구는 아티팩트 입력, 비교 임계값·안전 이벤트 상한·비교 표본 개수/비율은
비교 입력, 평가 표본 개수·불확실성·평가/모델 적격성은 각각의 평가 입력에 연결합니다.
인덱스는 같은 호출의 입력 보고에만 사용할 수 있습니다. 허용되는 반복 숫자 조건은
각각 별도 위치와 원래 출처·면제 설정을 유지합니다. 사용 불가 입력도 소유 보고에
명시적으로 남습니다.

승인 조건은 정족수·검토자 역할·독립/인간 그룹·충돌 규칙·작성자 제외 설정을 그대로
보존합니다. 기존 계약의 승인 요구 최대 한 개와 고위험 독립 검토 요건을 유지합니다.
연결 상태는 `not_evaluated`, 사유는 `approval_not_evaluated`입니다. 승인·검토자 기록·
면제·릴리스 처분을 만들지 않습니다. 이후 평가는 봉인된 입력과 ADR-0022 의미를
사용해야 하며 이 목록 자체에는 판정 결과가 없습니다.

## 예산과 권한 경계

각 소유 입력 검사의 기존 비용을 한 번 계산합니다. canonical UTF-8 문맥 하나와
원래 전체 규칙 프레임의 개수·바이트 비용도 동일 요청의 불변 예산에 포함합니다.
정확한 합산 한도는 통과하고 하나 모자라면 실패하며 중첩 반환값은 독립 복사본입니다.
세 순수 입력 검사는 콘텐츠 관측 뒤, 최종 후보·정책·기준 권한 관측 전에 함께 실행합니다.
시계·저장소·객체·키·네트워크 I/O, 역할·권한·의존성·마이그레이션·경로·worker·
발행 포트를 추가하지 않으며 공개 표면에는 목록 타입만 추가합니다.

`authorityBoundary`는 `retained_inputs_only`입니다. 끝난 읽기 전용 원본 재검사는
이후 발행을 승인하지 않습니다. 전체 의미·현재 권한·부재·선택자 관계, 유한 투영을
사용하는 엄격한 봉인 스냅샷·결과 계약, 같은 열린 트랜잭션의 스냅샷·작업·fence 발행,
일곱 순수 조건·내구성 실행·역할·불변 결과·outbox·API·SDK·복구·기여자 수락과 독립
체크포인트 완료 감사가 필요합니다.
