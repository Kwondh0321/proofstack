# 요청 기반 권한 확인 아티팩트 수집

[English](workflow-2-policy-artifact-capture.md) | [한국어](workflow-2-policy-artifact-capture.ko.md)

상태: 그래프·트레이스에 연결된 아티팩트 수집 구현. 소유권 적격성, 전체 의미 관계, 변경 가능한
권한, 경쟁 방어가 있는 스냅샷 봉인과 Workflow 2의 세 번째 체크포인트는 미완료입니다.

## 하나의 요청에서 직접 수집

`@proofstack/policy-evaluation`의 `capturePolicyArtifactEvidence`는 기존 기록 그래프, 비교
결과 검증, 정확한 트레이스 수집과
[아티팩트 소유 도메인의 검증](workflow-2-policy-artifact-observation.ko.md)을 연결합니다.
호출자가 조립한 그래프·아티팩트 목록·판정이나 임의 검증기를 받지 않습니다. 패키지 의존성의
확장은 [ADR-0025](../architecture/0025-compose-authorized-policy-artifact-observations.md)에
기록했습니다.

저장소 I/O 전에 불변 요청과 인증된 아티팩트 접근 주체를 검증·복사합니다. `artifact:read`,
테넌트 일치와 프로젝트·환경 접근을 요구합니다. 메타데이터·트레이스 포트의 별도 인가는 신뢰된
조립 계층의 책임이며 아티팩트 접근 권한으로 모든 도메인의 조회를 허용하지 않습니다. 주체는
HTTP 본문에서 그대로 신뢰할 자격 증명이 아닙니다. `policy:evaluate`만으로 원문을 읽을 수 없습니다.

전체 호출에서 단조롭게 증가하는 서버 시계를 사용합니다. 평가 시각과 요청 접수 시각 모두
시작 시각 이하여야 합니다. 잘못되거나 뒤로 움직이는 시계는 실패합니다. 그래프·트레이스 수집
뒤에는 알려진 모든 제한 콘텐츠 참조를 사전 검사하고 나서 아티팩트를 조회합니다. 소유 도메인
검증기는 실제 저장된 분류도 확인하므로 제출 분류를 낮춰도 권한을 우회할 수 없습니다.

## 출현 위치와 관측 보존

보존된 순서의 그래프 아티팩트 참조를 먼저 읽고 트레이스의 각 참조를 이어 읽습니다.

| 출처 | 연결되는 근거 |
| --- | --- |
| `record`와 `edgeIndex` | 정확한 부모 식별자·부모 기록 해시·참조 JSON 포인터 |
| `trace`와 `artifactReferenceIndex` | 정확한 트레이스 선택자·이벤트 식별자·기록 해시·콘텐츠 참조 포인터 |

중첩된 `traceCapture`가 실제 부모 관측을 보존합니다. 인덱스 자체는 별도 권한이나 외부 URL이
아닙니다. 중복 출현을 버리거나 호출자가 유리한 관측을 선택하지 못합니다. 각 출현마다 고정된
소유 도메인 검증기를 호출하고 원래 참조·부재·이용 불가를 구분합니다. 관리형 계약 밖의
트레이스 참조는 원래 형태를 보존하며 관리형 저장소를 조회하지 않습니다.

`roots_unavailable`은 근거와 함께 남고 성공적인 빈 목록으로 바뀌지 않습니다.
`artifacts_captured`는 관측 수집을 뜻할 뿐 모든 원문 검증이나 전체 의존 관계의 완성을 뜻하지
않습니다. 읽을 수 없는 부모는 미해결 상태이며 알 수 없는 자식 참조를 만들거나 없다고 단정하지 않습니다.

같은 아티팩트 식별자가 반복되면 전체 카탈로그 관측과 콘텐츠 결과를 비교합니다. 개별 시각과
사용량은 달라도 되지만 카탈로그 해시·소유권·상태·부재 여부·내용 관측이 다르면
`observation_conflict`로 실패합니다. 한 번의 읽기 중 기록이 바뀌면 소유 도메인의
`source_revision_changed`가 전파됩니다. 저장소·키 제공자·예상 밖 오류를 일반적인
indeterminate 증거로 바꾸거나 부분 성공 결과를 반환하지 않습니다.

전체 수집의 마지막 시각에는 앞서 검증한 원문이 그 사이 만료됐는지도 확인합니다. DB 행이
아직 갱신되지 않았더라도 이용 가능성이 바뀌었으므로 `source_revision_changed`로 실패합니다.
이전 관측을 유리하게 고치거나 자동 재시도·스냅샷 게시 권한을 부여하지 않습니다.

## 공유 자원 한도

그래프 조회·트레이스 행·아티팩트 전후 카탈로그 조회와 전체 raw JSON은 하나의 메타데이터
예산을 사용합니다. 앞단 검사는 getter, 숨겨진 값, JSON이 아닌 값과 순환을 도메인 검사 전에
거절합니다. 기존 그래프·트레이스 참조는 출현마다 한 번 계산되며 결과의 출처 인덱스 때문에
새 참조가 생기거나 한도가 초기화되지 않습니다.

실제 오브젝트 요청 전 예상 암호문 크기(원문 길이 + 기존 envelope 20바이트)를 요청의
`maxArtifactReadBytes`에서 예약합니다. 반복 읽기는 다시 예약하며 부재·짧은 응답·잘못된 응답·
실패여도 예약을 환불하지 않습니다. 예상보다 큰 버퍼는 복사·해시·복호화 전에 초과분을
계산합니다. 한도 소진은 `artifact_byte_limit` 오류이며 유리한 판정을 위해 증거를 생략하지 않습니다.

| `usage.artifacts` 필드 | 의미 |
| --- | --- |
| `reads` | 허용하여 시작한 오브젝트 호출 수 |
| `reservedBytes` | 호출 전에 예약한 예상 암호문 크기의 합 |
| `receivedBytes` | 완성된 `Uint8Array` 응답으로 실제 받은 크기. 실패 트래픽을 추측하지 않음 |
| `chargedBytes` | 호출마다 예약량과 완성된 응답량 중 큰 값의 합 |

예산 0은 콘텐츠 검증 면제가 아닙니다. 이용 가능한 원문을 읽어야 하면 사전 거절하지만,
카탈로그 부재나 명시적인 이용 불가는 오브젝트 I/O 없이 관측할 수 있습니다. 이 값들은 호출
하나의 계측입니다. 실패하면 성공 envelope를 반환하지 않고 이미 시작한 읽기를 정리하는 동안
예약을 초기화하지 않습니다. 후속 영속 워커는 실패·재시도 사이의 누적 계측과 부분 전송·전송
계층 재시도까지 기록해야 합니다. 현재 전체 버퍼 포트는 원격 메모리 할당을 제한하거나 실패한
전송 내부의 바이트를 볼 수 없습니다. 이 제한이 요청 계약의 영속 계측 의무를 면제하지는 않습니다.

## 검증 범위와 남은 작업

실제 그래프·데이터셋·증거 메모리 저장소와 인증 암호화로 출처 연결, 반복 관측, 루트 부재,
지원 밖 참조, 권한, 공유 조회·UTF-8·오브젝트 한도, JSON 승인, 입력 변경, 시계·만료,
카탈로그·콘텐츠 변경과 실제 키 제공자 실패를 검사합니다. 기존 그래프·트레이스 진입점의
동작은 유지하며 공유 계측 내부 함수는 패키지 루트에 노출하지 않습니다.

반환값에 원문·감싼 키·내부 저장 위치·정책 판정·봉인 표시를 추가하지 않습니다. PostgreSQL
정책 워커나 출시 종단 간 검증도 아닙니다. 관측 일치는 소유권 적격성, 현재 정책·출처 권한,
원자적 봉인, 배포 허가나 운영 준비를 뜻하지 않습니다. 이후 해당 경계와 결정론적 조건,
영속 작업·API/SDK·복구·격리·종단 간 검증을 완료해야 합니다. Workflow 2 완료 수는 **2/7**입니다.
