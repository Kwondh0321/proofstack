# 정책 계산 호출별 영속 비용 예약

Workflow 2 체크포인트 3은 아직 미완료입니다.
`publishPolicyEvaluationWithReservedRules`는 native 결과 게시자를 호출하기 전에
원래 순서 있는 규칙 전체의 작업량을 새 예약으로 커밋합니다. 원래 저장 스냅샷과 페이지는
서버 구성에서 가져옵니다. 공개 결과 POST, 새 역할·마이그레이션, worker 실행 파일이나
자동 변경 재시도를 추가하지 않습니다.

입력 파싱이나 저장소 호출보다 먼저 위임할 수 없는 service-token 실행 권한을 확인합니다.
fence는 인증된 worker를 가리켜야 합니다. 정확한 허용 범위에서 실제 작업을 읽고 원래 실행
시도와 스냅샷을 확인한 뒤, 전체 원래 페이지에서 규칙 수를 도출합니다. 일부 규칙만 고르거나
더 새로운 source cut을 선택하지 않습니다.

기존 `reserveWork`는 계산·게시와 별개로 먼저 커밋됩니다. 서버가 생성한 새 예약 ID에 대해
`created: true`와 불변 이력을 받아야 합니다. 범위·작업·fence·예약 ID·전체 작업량과
전후 그래프 해시를 확인하고 전이를 독립적으로 재생합니다. 중복·불명확한 응답은 계산을
시작하지 않습니다. 다른 작업이 준비한 그래프를 바꾸면 비용은 보존하고 응답을 보수적으로
거부합니다. worker는 heartbeat와 작업을 조정하고 제한된 재시도 전에 현재 상태를 읽어야 합니다.

DB 기록 시간으로 lease·시도·작업의 남은 시간을 계산합니다. 예약 호출 전에 시작한 단조
타이머가 응답 대기와 검증 시간을 포함하므로, 만료된 응답은 계산을 시작하지 못합니다.
native 게시자는 게시와 최종 커밋에서 실행 권한을 별도로 재검증합니다.

게시 실패·롤백·취소·응답 손실은 커밋된 비용을 환급하지 않습니다. 실제 다음 호출에는 새 ID와
전체 추가 작업량이 필요하며, 중복 응답은 두 번째 계산을 허용하지 않습니다. 완료는 모든
기존 비용과 원래 종료 시도의 fence·스냅샷·시간을 보존해야 합니다. 반환 근거도 다시 검증합니다.
과거 무결성 검증은 제한된 검증이며 새 source cut이나 새 권한 있는 계산 시도가 아닙니다.
이미 완료된 작업은 원래 결과의 정확한 조회·재시도를 사용합니다. 이 새 계산 구성은 거부합니다.
불변 outbox 충돌은 그대로 보존하며 재시도를 위해 레코드나 보호 장치를 제거하지 않습니다.

실제 PostgreSQL 검사는 게시 전 별도 비용 커밋, 게시 전체 롤백 후 비용 보존, 중복 예약
재사용 거부, 실패한 다음 호출의 추가 비용과 예약 후 취소를 다룹니다. 오류 주입 모델은
권한 우선 확인, 전체 입력 바인딩, 예산 초과, 지연·불명확 응답, 바뀐 응답과 환급 거부를
별도로 검사합니다. 이 모델은 실제 DB 트랜잭션 검증을 대신하지 않습니다.

전체 metadata·읽기·참조·입력 전송 비용, 메모리·공통 저장소, worker 실행 파일, 모든 상태의
복구, API·SDK, contributor 검사와 독립 exit audit가 남아 있습니다. 체크포인트 완료,
release 권한, 사람 승인, 제공자 측정의 진실성이나 운영 준비를 뜻하지 않습니다.
