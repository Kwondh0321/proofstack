# 수집된 정책 철회·대체 이력

[English](workflow-2-policy-lifecycle-capture.md) | [한국어](workflow-2-policy-lifecycle-capture.ko.md)

상태: 요청 기반 종결 이력 관측과 수집 중 변경 감지 구현. Workflow 2의 세 번째 체크포인트는
미완료이고 완료된 체크포인트는 **2/7**입니다. 원자적인 권한 시점 확정·입력 봉인·정책 판정·
출시 허가를 제공하는 기능은 아닙니다.

## 원래 정책과 소유 저장소 이력

코어의 `readPolicyEvaluationLifecycle`이 정책 검증·이력 의미·해시 계산을 소유합니다. 상위
조립 패키지는 원래 그래프 루트에 연결하고 두 관측을 비교하며 외부 의존성이나 대체 검증기를
추가하지 않습니다.

`capturePolicyArtifactEvidence`는 `policyLifecycle.beforeArtifacts`와 `afterArtifacts`를
반환합니다. 원래 정책 루트의 소유 스키마·범위·정확한 참조·전체 기록 해시를 재검증하고
`listReleasePolicyLifecycleEvents`로 전체 이력을 조회합니다. 대체 정책을 선택하지 않습니다.
루트 부재는 이력 조회 없이 기존 `roots_unavailable`로 남습니다.

기존 저장소 계약은 버전마다 종결 이벤트 0~1개를 허용합니다. 배열이 아닌 응답, 잘못된 이벤트,
중복을 포함한 여러 이벤트, 다른 범위·참조, 정책 게시 전 이벤트는 계약 오류입니다. 유리한
이벤트를 고르거나 중복을 제거하지 않습니다. 저장소 예외를 빈 이력으로 바꾸지도 않습니다.

대체 이벤트의 정확한 후속 정책을 조회하여 소유 스키마·정의 해시·범위·이벤트 참조·원래 정책을
가리키는 선행 참조를 검사합니다. 게시가 이벤트보다 늦을 수 없습니다. 전체 이벤트·후속 정책과
canonical SHA-256을 보존하며 정의 해시 밖의 게시 기록도 반영합니다. 후속 정책은 계보 근거일
뿐 평가할 정책을 교체하거나 불변 그래프에 새 루트를 추가하지 않습니다. 그 자체의 권한 조건이
유효하다는 보장도 아닙니다.

메타데이터 조회 인가는 조립 계층의 별도 책임입니다. 아티팩트 조회는 정책 게시·평가 권한이
아닙니다. 패키지 루트는 결과와 수집 저장소 타입만 노출하며 임의 그래프를 받는 내부 관측기는
공개하지 않습니다. 기존 기록·트레이스 수집의 좁은 저장소 요구사항을 유지합니다.

## 평가 시각과 관측 시각

평가 시각은 소수 초 최대 30자리를, 이벤트는 소유 계약의 UTC 밀리초 시각을 유지합니다.
이벤트가 `evaluationTime` 이전 또는 같으면 `withdrawn_at_evaluation` 또는
`superseded_at_evaluation`입니다. 나머지는 `no_terminal_event_at_evaluation`이며
활성·유효·승인되었다는 뜻이 아닙니다.

평가 시각보다 늦은 이력도 보존합니다. 그 후속 정책은 평가 시각 이후 게시될 수 있지만 늦은
이력의 근거일 뿐 과거 규칙을 통과시키는 미래 증거는 아닙니다. 이벤트는 관측 완료보다 미래일
수 없고 같은 시각은 허용합니다. 상위 수집기가 유효하고 뒤로 움직이지 않는 서버 시계를 관리합니다.

정적 `policyAuthority.requirements.status`와 이력 상태는 별개입니다. 설치·출처·검토자
조건을 충족해도 철회된 정책일 수 있습니다. 향후 판정기는 두 관측과 다른 전제조건을 함께
사용해야 하며 정적 `valid`만으로 출시를 허가할 수 없습니다.

## 변경 감지와 자원 한도

첫 관측은 오브젝트 읽기 전, 두 번째는 파일·정적 권한 검사 후이며 최종 보존 만료 검사 전입니다.
범위·정확한 정책·원래 루트 해시·평가 시각·전체 이력·시작과 완료 시각을 보존합니다.
`proofstack.policy-lifecycle-observation.v1`로 구분한 해시는 기록을 포함하되 관측 시계는
제외하므로 정상적인 시간 경과가 충돌을 만들지 않습니다.

이력·후속 정책 내용이 바뀌면 `source_revision_changed`로 실패합니다. 새 이벤트가 평가
시각보다 늦어서 의미 상태가 같아도 변경을 무시하지 않습니다. 잘못된 두 번째 응답은 계약
오류이고 저장소 예외는 그대로 전달합니다. 부분 성공이나 자동 재시도는 제공하지 않습니다.

이력·후속 정책 조회는 공통 누적 예산을 사용합니다. 조회마다 읽기·기록 예약을 사용하고 반환
이력 항목마다 기록 수를 추가합니다. 빈 배열과 전후 반복 기록을 포함한 원래 JSON 바이트도
사용 전에 계측합니다. 대체는 두 관측 각각에서 후속 정책 조회·본문을 계측합니다. 기존 참조·
파일 바이트·분류 인가·JSON 검사·시계·최종 만료 방어를 유지합니다. 응답 승인 한도이며 전송
메모리 상한이나 영속 재시도 계측은 아닙니다.

관측 해시는 **DB 변경 버전 토큰이 아닙니다**. 전후 읽기가 같아도 마지막 조회 후 변경이나
저장소 전체의 원자적 시점을 보장하지 않으며 계약을 위반해 중간에 변경 후 복원한 상황도
감지하지 못합니다. ADR-0022의 이력·아티팩트 변경 버전 검증을 포함한 원자적 스냅샷 게시가
별도로 필요합니다. 두 번의 읽기가 향후 트랜잭션을 대신하지 않습니다.

## 검증과 남은 작업

단위 테스트는 정밀 시각·늦은 대체 계보·스키마·전체 이력 손상·선행 참조·미래 기록·전체 해시·
복사·정확한 기록 수와 바이트 한도를 검사합니다. 조립 테스트는 실제 메모리 게시 저장소·요청
기반 그래프·암호화 파일로 조회 중 종결 게시, 같은 시각의 행위자·사유 변경, 저장소 실패,
정적 유효성과 종결 상태 공존, 시간 경과와 재조회 중 만료를 재현합니다.

PostgreSQL 봉인 경쟁·영속 워커·전체 의미 관계·출시 검증은 완료하지 않았습니다. 경쟁 방어
봉인, 결정론적 규칙 계산, 영속 작업, API/SDK, 복구·격리와 종단 간 검증은 남아 있습니다.
