# 요청 소유 잠금 아래 정책 출처 재검사

[English](workflow-2-policy-source-recheck.md) | [한국어](workflow-2-policy-source-recheck.ko.md)

상태: 인가된 파일 수집에 선택적인 신뢰된 읽기 전용 재검사를 연결했습니다. Workflow 2 완료
수는 **2/7**입니다. 스냅샷 발행기·워커·lease/fence·정책 결과·출시 승인이나 트랜잭션 종료 후의
최신성 토큰이 아닙니다.

## 소유권과 연결

`capturePolicyArtifactEvidence`에 서버가 소유한 선택적 `sourceTransactions` 의존성을 전달합니다.
생략하면 기존 관측·잠금 계획만 반환하고 `sourceRecheck`는 없습니다. 루트가 이용 불가이면
출처 트랜잭션을 시작하거나 성공한 빈 재검사를 보고하지 않습니다. 요청은 트랜잭션·잠금 부분
목록·그래프·SQL·출처 URL·발행 콜백을 제출할 수 없습니다. 메타데이터·트레이스 포트의 별도
인가와 인증된 파일 읽기 주체는 여전히 필요합니다. HTTP·SDK 옵션·DB 역할·런타임 권한을
추가하지 않습니다.

고정된 내부 조합은 파일·키 I/O 뒤에 [요청 소유 계획 전체](workflow-2-policy-source-guard-plan.ko.md)를
도출합니다. 모든 알려진 파일·정책 잠금을 순서대로 즉시 시도한 뒤에만 권위 기록을 읽습니다.
정확히 boolean `true`만 성공이며 false·잘못된 결과·오류·한도 소진은 전체 트랜잭션을
실패시킵니다. savepoint·부분 결과·잠금 없는 우회·자동 재시도는 없습니다.

`PostgresPolicySourceTransactions`는 조합 계층이 소유한 읽기 전용 포트를 구현합니다.
연결 전에 테넌트·프로젝트·환경을 복사하고 스코프 SELECT 전에 명시적으로 READ COMMITTED를
시작합니다. 트랜잭션 로컬 스코프와 기존 0050 비공개 잠금 함수를 사용하며, 같은 연결의
[정규화 읽기](workflow-2-policy-transaction-reads.ko.md)가 기존 어댑터 검증을 공유합니다.
풀·역할의 기본 격리 수준 때문에 잠금 전의 오래된 repeatable-read 스냅샷을 쓰지 않습니다.
종료 시 스코프는 지우되 세션 기본값은 바꾸지 않습니다.

포트는 `tryMetadataGuard`, `tryGuard`, `findCriterion`, `listCriterionSetStatuses`,
`findArtifact`, `findPolicy`, `listPolicyHistory`, `observationTime`뿐입니다.
DB 클라이언트·임의 SQL·DML·파일/키 I/O·발행은 노출하지 않습니다. 정리 전에 수명이 끝나며,
이미 시작한 읽기는 commit/rollback·연결 반환 전에 정리합니다. 호출자가 잡아 숨기거나 await하지
않은 포트 실패도 전체 작업을 오염시켜 후속 쿼리와 commit을 막습니다. 롤백까지 실패하면
원래 오류를 보존하고 연결을 폐기합니다. 멈춘 조회를 기다리는 것은 타임아웃·취소 기능이 아닙니다.

의존 방향은 `postgres -> policy-evaluation -> artifacts/core/contracts/datasets/replay`이며
순환을 만들지 않습니다. 검증기를 PostgreSQL로 옮기거나 조합 계층이 DB를 import하지 않습니다.
[ADR-0026](../architecture/0026-recheck-policy-sources-through-scoped-transaction-ports.md)에
결정을 기록합니다. 기존 API 자격증명은 잠금 함수 실행이 거절됩니다. 어댑터 생성 자체는
워커·스냅샷 권한을 부여하지 않습니다.

그래프에 기준 권한 관측이 있으면 자원 잠금보다 먼저 비공개
[0052 메타데이터 잠금](workflow-2-policy-metadata-barrier.ko.md)을 얻습니다. migration·recovery
잠금과 조율하며, 연결 전에 migration 파일을 읽고 잠금 아래 같은 연결에서 현재 원장 전체를
검증합니다. 이 두 단계가 성공하기 전에는 새 기준·전체 이력 포트가 SQL을 실행하지 않습니다.
false·잘못된 응답·원장 오류는 전체 트랜잭션을 오염시키고 롤백합니다. 기준 출처가 없는
그래프는 기존 파일·정책 절차를 유지합니다. `not_required`는 이용 불가 부모에 기준이 없다는
증명이 아닙니다.

## 현재 잠금 영역 전체를 얻은 뒤 비교하는 내용

- 부재 버전과 보존된 후속 정책도 포함해 고유 정책 버전마다 한 번 읽고, 요청의 정확한 의미
  시점에서 그래프 정책 노드의 전체 관측을 기존 검사기로 비교합니다.
- 지원하는 고유 파일 카탈로그마다 한 번 읽고, 기존 인가된 검사기로 전체 카탈로그 해시·공개
  메타데이터·소유권·시간별 관측을 비교합니다. 잘못된 `undefined`를 부재 `null`로 바꾸지 않습니다.
- 지원 밖 descriptor도 알려진 잠금 좌표는 유지하되 관리형 카탈로그를 조회하지 않습니다.
  원래 반복·부재·이용 불가 기록을 제거하지 않습니다.
- 루트의 전체 종결 이력을 먼저 비교한 뒤 캐시된 정책으로 기존 생명주기 검증을 수행합니다.
  새 후속 정책은 그 잠금이 없는 상태에서 조회하지 않습니다. 전체 이벤트·후속 정책 해시를
  비교하며 최신 정책으로 요청 루트를 교체하지 않습니다.
- 기준 상태 이력의 모든 행을 먼저 비교하고, 이미 관측한 기준·후속 버전만 같은 연결에서
  고유하게 읽습니다. 그래프 관측과 영수증을 포함한 전체 제어 관측을 비교하며 원래 기준과
  선택된 상태를 보존합니다. 더 새로운 승인을 원래 선택 대신 사용하지 않습니다.
- 메타데이터 조회 뒤 모든 잠금 아래 DB 시각을 얻고, 잘못되거나 수집 단계 완료보다 앞선
  시점을 거절합니다. 파일 영수증·정확한 만료에는 DB 네이티브 정밀도를 유지합니다. 기존 정책·
  이벤트·fixture 소유권의 영수증 계약은 밀리초이며, 마이크로초 소유권 기록을 허용하지 않습니다.

내부 기준 해석기는 Date를 거치지 않고 정확한 UTC DB 시점을 사용합니다.
`criterionAuthority.underGuards`는 콘텐츠 전후 관측과 별도로 전체 이력·제어 조회와 평가·수집
시점의 해석을 보존합니다. 저장된 내용이 같아도 두 시점 사이의 발효·만료는 새 해석에
반영됩니다. `completedAt`과 `atCapture.at`는 잠금을 유지한 DB 시점이며 이후의 권한을 보장하지
않습니다. `sourceRecheck`의 추가 필드는 `metadataGuard`, `criterionReads`,
`criterionHistoryReads`, `criterionHistoryRows`입니다. 기준 출처가 없으면 flag는 false,
카운터는 0입니다. 실제 읽기와 모든 이력 행, 반복 해석 참조를 공유 한도로 계산하고 캐시 해석
때 실제 읽기를 중복 계산하지 않습니다.

이미 바이트를 검증했거나 오브젝트 부재·콘텐츠 무결성 실패를 관측한 파일은 같은 전체
카탈로그의 `content_pending`으로 재검사되어야 합니다. 이는 보존된 콘텐츠 시도를 위한 카탈로그
가용성이지 **새 콘텐츠 검증이 아닙니다**. DB 잠금 아래 파일 조회·키 조회·복호화를 하지 않습니다.
나머지 부재·이용 불가는 동일한 관측이어야 합니다. 상태·영수증·암호화 정보·소유권·만료·정책·
종결 이력이 달라지면 `source_revision_changed`로 실패합니다.

카탈로그 전용 검사기의 신뢰된 관측 시점은 기존 전체 정밀도 UTC 평가 시각 형식을 받습니다.
초기 콘텐츠 수집의 Date 시계는 기존 밀리초 계약을 유지합니다. 전체 완료 시각은 단조로운
호스트 시계와 정확한 DB 시점 중 나중 값이므로 내부 관측보다 앞설 수 없습니다. 최종 콘텐츠
만료 검사도 이 단계 뒤에 수행합니다. 나중 변경이 이 보고서를 봉인된 버전으로 바꾸지는 않습니다.

## 공유 한도와 출력

그래프·트레이스·콘텐츠 수집과 같은 호출 단위 한도로 잠금 포트 호출, 정규화 조회, 전체 이력의
행/JSON과 DB 시각 응답을 계산합니다. 한도를 초기화하지 않습니다. 잠금 배열 canonical
바이트는 계획 도출 때 이미 계산하며 새 증거 발생이나 오브젝트 비용을 만들지 않습니다.
정확한 남은 한도는 통과하고 한 행·바이트 부족이면 잠금이나 조회를 생략하지 않고 실패합니다.

이는 논리 포트 호출과 원래 응답의 계측입니다. 정규화 읽기 내부의 모든 SQL, 드라이버 할당,
숨겨진 재시도나 DB 실행 시간을 계측한 값이 아닙니다. 실패한 호출은 성공 사용량 envelope를
반환하지 않으며, 영속 실패·재시도 원장은 후속 워커의 의무입니다. 조회·JSON 한도는 기한을
대체하지 않습니다.

성공 시 선택적 `sourceRecheck`는 `observations_rechecked`, 정확한 `observedAt`, 잠금 수,
고유 파일·정책 조회 수와 앞서 설명한 기준·메타데이터 계측을 반환합니다. 원문·키·내부 위치·봉인·스냅샷 digest·판정·capability는
없습니다. 조합 오류 코드는 `policy_evaluation_source_recheck_failed`이며 사유는
`guard_unavailable`, `guard_invalid`, `source_revision_changed`, `clock_invalid`입니다.
기존 무결성·저장소·한도 오류는 유지합니다. 보고서는 **읽기 전용 트랜잭션이 끝난 뒤** 반환됩니다.

## 검증과 남은 발행 조건

[공개 조합 검사](../../packages/policy-evaluation/src/capture-artifact-evidence.test.ts)는 실제 메모리
저장소·인증 암호화와 전체 잠금 우선 순서, 전체 실패, 카탈로그·정책·이력 변경, 잘못된 부재,
후속 정책, 지원 밖 좌표, 실패 콘텐츠 유지, 정확한 시점, 루트 실패와 공유 한도 경계를 검사합니다.
[어댑터 단위 검사](../../packages/postgres/src/postgres-policy-source-transactions.test.ts)는 같은
연결·정확한 스코프·격리·엄격한 응답·실패 전파·수명·지연 읽기 정리·migration 원장 실패·
메타데이터 잠금 선행·롤백 실패를 검사합니다.
[PostgreSQL 조합 검사](../../packages/postgres/src/postgres-policy-source-transactions.integration.test.ts)는
실제 카탈로그·정책·기준·전체 상태 이력·잠금·경쟁 쓰기를 사용합니다. 기준 시나리오는 격리된
관리자 fixture로 제어·실행 기록을 준비하며 API의 실행 기록 발행 금지는 유지합니다.
`pg_blocking_pids`로 대기를 확인하고,
커밋된 중간 변경·부재 생성 거절, 이전 잠금의 롤백 해제, 풀 재사용과 기존 역할 실행 거절을
검사합니다. 관리자 관측 풀은 일회성 테스트용이며 운영 워커 권한이 아닙니다. 후보·나머지 상위
기록과 암호화 메모리 오브젝트는 명시적인 fixture입니다. 완전한 봉인 종단 간 승인이나 새 S3
통합 검사가 아닙니다.

선택적 메타데이터 잠금은 설치된 테넌트 출처 쓰기 범위를 보호하지만 현재 조합은 파일·정책과
수집된 기준·상태 이력만 다시 읽습니다. 모든 상위 기록의 부재·selector·논리 root·변경 가능한
출처 권한·전체 의미 계보는 아직 닫지 않았습니다. 후속 발행기는 필요한
모든 잠금을 **같은 열린 트랜잭션에서 계속 유지**하며 나머지 관계와 실행 lease/fence를 검증하고
스냅샷·작업 상태를 원자적으로 저장해야 합니다. 종료 후 이 보고서를 최신 권한으로 받아들이거나
재검사와 발행 사이에 잠금을 풀 수 없습니다. 현재 설치/마이그레이션 확인, 전용 권한, 스냅샷
계약, 순수 조건 평가, 영속 재시도·기한·취소 계측, 복구·API/SDK·독립 종단 간 승인은
[진입 감사](workflow-2-policy-evaluation-entry-audit.ko.md)의 미완료 조건입니다.
