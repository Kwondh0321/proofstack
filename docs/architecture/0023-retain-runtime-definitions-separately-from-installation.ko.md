# ADR-0023: 런타임 정의와 설치 권한을 분리해 보존

[English](0023-retain-runtime-definitions-separately-from-installation.md)

상태: Accepted

날짜: 2026-09-26

담당: ProofStack maintainers

## 배경

정책 매니페스트에는 런타임 프로파일·격리 프로파일·런타임 어댑터가 있지만 기존 참조의
ID·버전·해시만으로 실제 정의 본문이 존재하거나 올바른지 확인할 수 없다.
[후보 런타임 권한](../../apps/api/src/release-candidate-authorities.ts)은 운영자 허용 목록과의
정확한 일치를 확인한다. 이 Boolean은 후보 발행 경계의 증거이지 정의 본문·등록 시각이 아니다.
[대상 실행 경계](../../services/replay-worker/src/target-launch.ts)의 사전 설치 실행 파일 검증도
프로파일 정의나 운영체제 격리 증명과 다르다.

요청된 참조 자체를 해시하거나, 등록 시각을 만들거나, 최신 버전을 고르거나, 후보가 제출한
데이터로 권한 있는 레지스트리를 만들어 매니페스트를 완성해서는 안 된다.

## 결정

contracts에 엄격한 버전별 정의 기록 세 종류를 추가하고 core에 검증과 읽기 전용 카탈로그를
둔다. core가 API나 재현 워커에 의존하지 않도록 한다.

- 런타임 프로파일: 기존 ID·버전·계열, 정확한 엔진 버전·플랫폼·아키텍처, 구현·설정
  아티팩트 참조와 명시적인 한계.
- 격리 프로파일: 기존 ID·버전·종류, 구현·설정 아티팩트 참조와 한계. `container` 정의의
  존재가 컨테이너 실행 구현을 뜻하지 않고, `local_child_process`가 OS 네트워크·파일 격리를
  보장하지 않는다.
- 런타임 어댑터: 논리·버전 식별자, 프로토콜 이름·버전, 경계 종류, 구현·설정·인터페이스
  계약 아티팩트 참조와 한계. 모양이 같다고 대상·수집 어댑터나 워커 프로토콜과 같아지지 않는다.

설정과 인터페이스 본문은 정확한 보관 의존성이다. 정책 평가기에 전달하는 실행 코드가 아니며
읽기 단계에서 설정을 해석하거나 실행하지 않는다. 실제 바이트 수집·해시·분류·소유권과 필요한
프로파일별 의미 해석은 별도 수집·설치 의무다. 메타데이터만으로 제어 기능이나 호환성이
검증됐다고 할 수 없다.

Canonical UTF-8 인코딩은 의미 필드 전체·종류·스키마/인코딩 버전·테넌트/프로젝트/환경을
결속한다. 등록 시각·운영자 주체는 별도 receipt이며 전체 캡처 해시는 이들까지 포함한다.
실제 receipt의 보존과 출처는 신뢰된 설치 운영자의 책임이다. 해시로 등록자를 인증하거나
시각을 만들어내지 않는다. 공개 등록 API나 요청자가 본문을 제출하는 경로도 추가하지 않는다.

`StaticRuntimeDefinitionCatalogue`는 최대 256개 기록을 엄격하게 검증해 시작 시 불변 복사한다.
범위·종류·정확한 ID/버전으로 읽고 어댑터는 정확한 버전 ID로 읽는다. 같은 저장 식별자는
내용이 같아도 중복 등록을 거부한다. 반환 값도 복사한다. 읽기 단계에서 참조의 모든 필드,
의미 해시, 등록 시점과 전체 기록 해시를 검사하며 부재·무효·불일치·미래·운영 실패를 구분한다.
대체 버전·네트워크·실행 파일 접근은 하지 않는다.

기존 후보 허용 목록이나 실행기를 이 카탈로그로 바꾸지 않는다. 정책 워커의 읽기 포트는
신뢰된 서버 조립에서 주입해야 하며 평가 요청에서 받지 않는다. 올바른 정의는 현재 설치,
인가·안전성·폐기 상태·바이트 가용성·재현 완료·릴리스 승인이 아니다.

## 결과와 한계

실제 본문과 원래 receipt를 검사할 수 있고 구현·설정 의존성이 드러난다. 기존 참조와 실행
계약은 바뀌지 않는다. 반면 운영자는 이전 허용 목록 외에 정의 본문과 receipt도 보존해야 한다.
정적 카탈로그는 영속 수명주기 DB나 원격 탐색 서비스가 아니며 설정 보존·진위는 신뢰 경계다.
과거 임의 해시를 새 기록의 날짜를 소급해 유효하게 만들지 않는다. 부재한 정의는 부재로 남기고
과거 재현·후보 기록을 고쳐 쓰지 않는다. 범용 설정 언어·OS 격리·공급자 신원 증명이나
자동 자격증명/설치 관리도 제공하지 않는다.

## 후속 작업

영속 정책 워커에 신뢰된 카탈로그 조립을 연결하고 정확한 캡처 기록을 봉인 스냅샷에 보존해야
한다. 재귀 수집·실제 바이트·권한/리비전·복구·전체 체크포인트 검증은 별도 필수 조건이다.
가변 설치·집행 관찰과 불변 정의를 구분하며 출처 종류 지원만으로 단계를 완료하지 않는다.

## 검토한 대안

- 허용 목록이나 참조 해시를 본문으로 취급: 독립 본문과 원래 receipt가 없고 요청자가 스스로
  검증 근거를 만들기 때문에 거부한다.
- 실행기를 호출해 정의 탐색: 읽기 전용 수집에 실행·공급자 권한이 생기므로 거부한다.
- 범용 배포·등록 발행·원격 증명 서비스 신설: 추가 권한·수명주기 설계가 필요하므로 후속
  범위로 둔다. 설치 및 영속 수집 검증을 대체할 수 없다.

## 재검토 조건

카탈로그 한도 초과, 영속 수명주기 관리, 설정 해석이 필요한 새 정책 술어, 실제 컨테이너나
원격 워커의 집행 증거가 승인된 실행 프로파일에 포함되는 경우.
